<objective>
Close a pre-existing cross-tenant write hole: `ContactsController.AddNote` passes the raw caller-supplied `contactId` straight through to `ContactRepository.AddNoteAsync`, which does an unconditional `Add()` + `SaveChangesAsync`. EF Core's `HasQueryFilter` constrains SELECTs only, never INSERTs, so an authenticated user on Board A can durably insert a note against a Board B contact by guessing an id from the single global identity sequence.

Purpose: `EditNote` and `DeleteNote` are already safe because they re-resolve through a filtered query before mutating. `AddNote` is the one note path that skips the resolve step. This makes it fail closed at both the controller and the repository, so neither layer alone is the only thing standing between a guessed id and a committed row.

Output: Board-scoped resolve in the controller, defence-in-depth guard in the repository, and two regression tests (route-level and repository-level) that fail against the current code and pass after the fix.
</objective>
