## Spacing Scale

Inherited unchanged from the foundation spec § "Spacing Scale" (xs 4, sm 8, md 16, lg 24, xl 32, 2xl 48, 3xl 64) and its touch-target and width exceptions. Content spacing outside the compact month uses those tokens only.

**Calendar-fit geometry (FIXED; component-local, not spacing).** The compact month is a measured fit, so its row sizes are declared once as local variables on the Calendar/Index page wrapper (`.calendar-page`, names `--cal-*`), the same way the foundation declares `--card-width` and the poster seals are declared per modifier class. They are component dimensions, not gaps between things. Every value other than the two marked off-scale is a multiple of 4. The two off-scale values are an **operator-accepted exception**: they are drawn in the Gate 1 calendar mockup (item 11) and stand only if the operator accepts them there.

| Variable | Value | Where | Why |
|----------|-------|-------|-----|
| `--cal-row` | 20px | compact entry and "+N more" row height | D-03; the density the operator asked for |
| `--cal-mark` | 16px | status marker box (24px inside the day panel row) | one glyph per row, inside the 20px row |
| `--cal-top-h` | 20px | day-number row | |
| `--cal-row-gap` | 2px (**off-scale**) | gap between stacked rows and between the number row and the first entry | measured: 3 slots need 90px; a 4px gap would cost 8px per cell and drop 1280x720 to 2 slots |
| `--cal-cell-pad-y` | 2px (**off-scale**) | top and bottom padding of a day cell | same budget |
| `--cal-cell-pad-x` | `--qb-space-xs` | side padding of a day cell | |
| weekday header cell | 24px tall (`--qb-space-xs` block padding around a 16px line) | `.calendar-header` | the mockup used 22px; 24px is on the grid and costs 2px once for the whole grid |
| calendar header padding | block `--qb-space-xs`, inline `--qb-space-md` | `.calendar-page .modern-card-header` | overrides the foundation's 16px/24px title-band padding so the header row is 45px (36px buttons, 8px padding, 1px border), at most 48px |
| page block padding above and below the month card | `--qb-space-sm` | `.calendar-page` | the mockup used a smaller value; this one is on the grid |
| card width | 352px; panel width 420px (`max-width: calc(100vw - 16px)`) | floating card and day panel | measured in the mockup; multiples of 4 |
| panel row | at least 48px | day panel rows | the passing-size equivalent of the 20px entry (D-03) |

The cell budget for 3 slots is `20 (number row) + 2 (gap) + 3 x 20 + 2 x 2 (row gaps) + 2 x 2 (padding) = 90px`; for 4 slots 112px; for 5 slots 134px. Grid rows are `minmax(<that minimum>, 1fr)` (DISCRETION; the mockup used `minmax(0, 1fr)`): rows share the leftover height, and where the leftover is smaller than the minimum (windows below the fit target, or the manager alert state) the grid grows and the page scrolls instead of clipping an entry.

Phone calendar, Events and Agenda: `--qb-hit-min` (44px) for every control from the shell rule; card padding `--qb-space-md`; gap between agenda day sections `--qb-space-md`; gap between rows inside a day `--qb-space-xs`.

Exceptions: exactly two, `--cal-row-gap` and `--cal-cell-pad-y` at 2px each (fit geometry, restated here as an operator-accepted exception shown at Gate 1, item 11). Every other pixel value in this phase's geometry (4, 8, 16, 20, 24, 36, 44, 48, 352, 420) is a multiple of 4. Border widths and glyph sizes are not spacing. The floating-card gap (8px, `--qb-space-sm`), the panel offset (8px), the hover bridge (8px) and the panel row marker (24px) all sit on the scale.

## Typography

Inherited from the foundation spec § Typography: four sizes (14, 16, 20, 28px), two weights (400, 600), body line height 1.5, heading line height 1.2, Cinzel for display only, **nothing below 14px**. No size or weight is added. `fw-bold`, `fw-semibold`, `fs-*`, `small` and `.lead` are not used in new markup (use the tokens through a class).

**DISCRETION that changes the mockup (GATE 1 item 2).** The calendar-fit mockup set entry, legend, weekday and card text at 13px (`0.8125rem`). That is below the foundation's 14px floor and no exception for it is recorded anywhere, so this contract pins **14px (`--qb-text-sm`)** for every text element in the month. The row height (20px, line height 18px) holds a 14px line. Cost: text is about 8% wider, so the average visible title shrinks by about one character (research measured 12.6 characters at 1280 and 15.7 at 1440 at 13px; expect about 11.6 and 14.5 at 14px, re-measured on the Audit Board fixtures at Gate 1). The 10px status glyph inside a 16px marker is an icon, not text. If the operator prefers the mockup's 13px, it is recorded as an exception to the 14px floor, never silently kept.

| Element | Step | Weight | Notes |
|---------|------|--------|-------|
| Page title (`h1`), Calendar, Events, Agenda, Series, Create, Edit, Details | Display 28px desktop, 20px phone, Cinzel | 600 | one `h1` per page in the card header. Calendar/Index and Calendar/Index.Mobile both get a visible `h1` `Quest Calendar` (Q-41). **Colour (see "Page and card title colour" under Color):** gold desktop `h1` by the foundation rule on Events/Index, Agenda, Events/Details, Series/Details, Events/Create and Events/Edit; **parchment on Calendar/Index desktop**; parchment on the phone layout |
| Month name | Heading 20px, body face | 600 | a `p` or `span` (not a heading); `Cinzel` is dropped from the phone month name (a date is not display text) |
| Section headings in cards (`Your Availability`, `Description`, `Who's Coming`, `Actions`, `Recurrence Rule`, `Occurrences`, `Legend`) | Heading 20px, **body face** (not Cinzel), no letter-spacing | 600 | `h2`, never `h4` or `h6`; `h3` for sub-sections; heading levels step down one at a time. Every card that carries one of these titles and is not the page-title card takes `.modern-card--aside` (listed under "Card roles"); without it the foundation would set a card-header `h2` in the 28px display face. **No local title-size, family or letter-spacing override** in any area sheet |
| Day number | Label 14px | 600 | inside the 20px number row |
| Weekday header | Label 14px | 600 | `--qb-fg` on `--qb-wood` |
| Compact entry time and title, "+N more" | Label 14px | time 400, title 600, "+N more" 600 | one line, title ellipsised, `font-variant-numeric: tabular-nums` on the time |
| Legend items, panel and card body, facts | Label 14px | 400; fact values 600 | |
| Card title, panel row title, phone row title | Body 16px | 600 | wraps, never truncated on the card, the panel (clamped at 3 lines with the full text in the same row's name) or the phone |
| Panel title (the date) | Heading 20px | 600 | |
| Phone day label | Label 14px | 600 | `text-uppercase` and letter spacing in CSS; the server text is mixed case (see "Dates") |
| Form controls | Body 16px | 400 | prevents iOS focus zoom |

## 1. Calendar/Index, desktop: the month that fits

### 1.1 Page structure and the fit (D-03, D-04, D-05; FIXED)

- **Wrapper.** `Calendar/Index.cshtml` wraps its output in `.calendar-page`. Every compact rule (fit, entries, "+N more", card, panel) is scoped under it. Nothing in the month rules is reachable from Quest Details (the shared partial branches on `isDetailsPage`).
- **Full width.** The legend sidebar column (`col-lg-2`) is gone; the month card takes the full container width. The legend moves into the header (1.2).
- **Slot count.** `--cal-slots` is a custom property on `.calendar-page`, set by media queries and read by the module. At `min-width: 992px`: 2 slots by default, **3 at `min-height: 712px`, 4 at `min-height: 850px`, 5 at `min-height: 980px`**. Below 992px it is `0` (no fit rule). One slot is one entry or the "+N more" row. A day with no more entries than slots shows them all; a day with more shows `slots - 1` entries and "+N more", so **"+1 more" never appears**.

| Viewport height (at 992px wide and up) | Slots | A day that overflows shows |
|----------------------------------------|-------|-----------------------------|
| under 712px | 2 | 1 entry and "+N more" |
| 712 to 849px (**1280x720**) | 3 | 2 entries and "+N more" |
| 850 to 979px (**1440x900**) | 4 | 3 entries and "+N more" |
| 980px and up | 5 | 4 entries and "+N more" |

- **Weeks.** The server renders `calendar-grid--weeks-4|5|6` from `GetCalendarDays().Count / 7`; the grid has that many equal rows. The worst case is a six-week month at 1280x720.
- **Height rule.** The month card fills the viewport below the navbar: the grid's height is `100dvh` minus the navbar (`--qb-nav-h`), the page block padding, the header and the weekday row. Rows are `minmax(<cell minimum>, 1fr)` (see "Spacing Scale"). **D-04: the site footer sits below the fold on this page**; the footer is reached by scrolling and no rule shortens the grid for it.
- **Fit target (measured by the sweep, evidence stored).** No page scroll caused by the month at 1280x720, 1366x768, 1440x900, 1536x864, 1920x1080, 1280x1024 and 1280x700, in a five-week month and a six-week month, with the wrapped-legend header (1.2) and the empty-month note (1.8). At 991x720 and below the rule is off by design.
- **The header budget (re-stated against the v6.0.2 title band).** The foundation's `.modern-card-header` is a scrim band with `--qb-space-md` block and `--qb-space-lg` inline padding and a 1px bottom border; left alone it would make the header about 69px (16 + 36 + 16 + 1) and cost about 24px of grid, about 4px per row of a six-week month, which the 1.2px slack at 1280x720 cannot absorb. So `.calendar-page .modern-card-header` sets **`padding-block: var(--qb-space-xs)` and `padding-inline: var(--qb-space-md)`** in `@layer pages` (on the scale; the band fill and the border are kept). Header row 1 is then `4 + 36 + 4 + 1 = 45px`, **at most 48px including the border** (the mockup's 48px used 6px padding, so the budget gains 3px). Two rows: row 1 as above plus a legend row of at most 28px. The card body keeps `p-0` as today (the foundation's 24px body padding would cost 48px). A plan fact asserts the measured header height is at most 48px at 1280x720 in the one-row state. Anything else above the grid at 992px and up is a defect, with the one named exception below. The month card is one of the page's few large panels, so it takes the 12px blur; the grid inside it is not a nested card, so it carries none of its own.
- **Manager runway alert (GATE 1 item 6).** The low-runway series alert (`CanManage` and a series below the runway) is an existing element and can add 40 to 60px. **Default: it stays above the month as today, and in that state the grid keeps its minimum cell height so the page scrolls by up to the alert's height; nothing clips.** Recorded as an accepted exception to the fit target for that one state. The alternative shown at Gate 1 is one fewer slot while the alert is present. The alert is shown at Gate 1 as its own frame.
- **No-JS fallback (FIXED).** Without the module every entry is visible; the cell's item list scrolls (`overflow-y: auto`) inside its fixed row, as today's `.day-cell-items` does. The module hides entries with the `hidden` attribute, never with inline style.

### Planner assumptions (surfaced, not silently dropped)

1. **Server-render and enhance.** The mockup renders the month in the browser; production renders every entry and its detail block in Razor and the module only hides, clones and positions. The `CanOpen` decision stays server-side.
2. **Hook classes survive.** Roughly 100 rendered-markup assertions key on `calendar-day`, `linked-entry*`, `linked-day-count`, `legend-*`, `agenda-*`, `avail-*`; they stay on the elements that still exist. `DayCell` is rewritten once. The two `window.location.href` assertions in `LinkedBoardMobileCalendarTests` are rewritten to "one link to that URL, no handler"; static-row intent is kept.
3. **Status and key are separate markers** (the finalized check no longer hides behind the warning).
4. **Culture.** `Html.WallClock` formats with the invariant culture; today's `.ToString` uses the host's. Identical on an English or invariant host; the production host `LANG` was not inspected. Confirm before release.
5. **`title` handling.** Compact entries keep `title` in the HTML and the module removes it at enhancement time (see 1.4).
6. **Call-site conversion** for `DateOnly` and `TimeOnly` (no helper overload) and **server-only date styles** (no `site.js` change); both keep Definition-of-converted item 9 literally true. Research open questions 1 to 3.
7. **One `calendar.css`** (month page and Quest Details block, scoped under `.calendar-page` and `.details-page`) rather than two sheets; the weekday header is the one shared rule.
8. **Phase 96 shares the checkout.** Append to, never replace, the `UiFoundationLayerGuardTests` arrays; re-read `components.css`, `shell.mobile.css`, `AccessDenied.cshtml` and the layouts' link list before each affected slice; execution starts after Phase 96 finishes (ports 8000 and 8001 free).
9. **Title icons** inherit the title colour on every page in this phase (the `text-info` and `text-purple` title icons go; event purple stays on event identity markers): gold beside a gold desktop `h1`, parchment beside the Calendar and phone titles.
10. **`.modern-card--aside` on secondary cards.** The foundation defines the class for sidebar cards; this phase also applies it to every titled non-page-title card (Events/Details right column, Series sections), because the alternative is a 28px Cinzel `h2` in a card header or a local override. If the operator would rather have section titles in card bodies, that is a markup change, not a style one.
11. **Blur and `position: fixed`.** The blurred month card contains the header's legend popover (absolute, unaffected) but not the card or the panel, which are mounted on `body`.
12. **Planning IDs.** No D-xx, Q-xx, A-events-xxx, DoC-x, phase or plan number is written into any source, CSS or test-string comment; the planning-reference scans stay green.
