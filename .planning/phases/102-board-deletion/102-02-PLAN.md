<objective>
Make the stale active-board recovery cover super admins, the case research found broken: `GroupSessionMiddleware`
skips revalidation for `SuperAdmin`, so a super admin whose selected board was deleted keeps a session pointing at a
missing `Groups` row, and a subsequent write that stamps the active board (quest create) would hit a foreign-key violation
and a 500. Add one shared helper that clears the three active-board keys, use it in the middleware, and add a
board-exists check for super admins when revalidation is due.

Discretion resolved here (CONTEXT: "confirm the existing stale-board recovery falls back cleanly, and fix it only if it
does not"): ordinary ex-members already recover (unchanged); super admins do not, so this plan fixes it. The deleting
admin's own session is cleared immediately by the controller in plan 102-09, using the helper created here.

Purpose: no session can outlive its board and turn a subsequent request into a 500 (D-11's friendly-failure rule).
Output: `ActiveBoardSessionExtensions`, the middleware arm, updated unit tests, the one rewritten integration test.
</objective>
