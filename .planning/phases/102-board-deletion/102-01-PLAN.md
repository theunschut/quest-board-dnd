goes from controller to service (name check) to repository (member recheck, scoped reads, tracked removals, one

Domain contracts (QuestBoard.Domain, no EF reference):
1. Create `Enums/BoardDeleteStatus.cs`: public enum `BoardDeleteStatus` with members `Deleted`, `NotFound`,
   `HasMembers`, `NameMismatch`, each with a one-line plain-language XML summary.
2. Create `Models/BoardDeletion/BoardDeletionResult.cs` (namespace `QuestBoard.Domain.Models.BoardDeletion`): public
   sealed class with init-only `Status` (`BoardDeleteStatus`) and `BoardName` (string, default empty), and a static
   factory `Refused(BoardDeleteStatus status, string boardName = "")`. Plan 102-04 adds the per-kind removed counts
   to this class as an additive property.
3. `IGroupRepository`: add `Task<BoardDeletionResult> DeleteBoardAsync(int groupId, CancellationToken token = default);`
   with an XML summary: deletes the board named by the id and everything scoped to it in one save, unlinking rows on
   other boards that point into it; returns HasMembers and changes nothing while the board has members; NotFound when
   no such board exists; a failed save clears the change tracker and rethrows.
4. `IGroupService`: add `Task<BoardDeletionResult> DeleteBoardAsync(int groupId, string? confirmName, CancellationToken token = default);`
   with the same summary plus: refused with NameMismatch, nothing changed, unless the typed name with surrounding
   whitespace trimmed equals the stored board name exactly (ordinal, case-sensitive), per D-08.
5. `GroupService.DeleteBoardAsync`: `await repository.GetByIdAsync(groupId, token)`; null returns
   `BoardDeletionResult.Refused(BoardDeleteStatus.NotFound)`; when
   `string.Equals(confirmName?.Trim(), group.Name, StringComparison.Ordinal)` is false return
   `Refused(BoardDeleteStatus.NameMismatch, group.Name)` without calling the repository delete; otherwise return
   `await repository.DeleteBoardAsync(groupId, token)`. Trim only the typed side. Do not copy the ambient clock read
   that `AddAsync` uses.

Repository (`GroupRepository.cs` only; it is on the closed IgnoreQueryFilters allowlist, so do not create a new
repository file and do not make it partial):
6. Add private scoped query helpers, each `DbContext.<set>.IgnoreQueryFilters().Where(<explicit groupId predicate>)`
   returning `IQueryable<TEntity>`: `BoardQuests(int groupId)` (`q.GroupId == groupId`), `BoardProposedDates`
   (`pd.Quest.GroupId == groupId`), `BoardDateVotes` (`v.ProposedDate.Quest.GroupId == groupId`),
   `BoardPlayerSignups` (`ps.Quest.GroupId == groupId`), `BoardReminderLogs` (`r.Quest.GroupId == groupId`). Put one
   comment above the helper block in the style of the existing comment on
   `GetFutureEventIdsForGroupIgnoringActiveBoardAsync`: the ambient filter answers for the caller's selected board,
   this operation targets the board named by an explicit id, each helper re-imposes scope from that id, and the
   helpers are the single definition of what belongs to a board, shared by the delete and its preview.
7. `DeleteBoardAsync(int groupId, CancellationToken token = default)`: load the group with
   `DbContext.Groups.FirstOrDefaultAsync(g => g.Id == groupId, token)` (null gives `Refused(NotFound)`); recheck
   membership first with `DbContext.UserGroups.AnyAsync(ug => ug.GroupId == groupId, token)` and return
   `Refused(HasMembers, group.Name)` before anything is staged (D-09); for each helper `await ToListAsync(token)` and
   pass the list to `RemoveRange` on its set (date votes, player signups, proposed dates, reminder logs, quests);
   `DbContext.Groups.Remove(group)`; exactly one `await DbContext.SaveChangesAsync(token)` inside `try`, with a bare
   `catch` that calls `DbContext.ChangeTracker.Clear()` and rethrows (comment: no half-applied tracked graph may be
   saved by a subsequent save in the same request), the shape `QuestMoveRepository` uses; return a result with
   `Status = Deleted` and the board name. EF orders the DELETE commands by the model's foreign keys inside that one
   save, which is one database transaction, so the staging order is for readability only. Tracked removals only: no
   bulk delete, no raw SQL, no attaching, no hand-set entity state (D-11; `FeedRevisionWriteSeamTests` scans for those
   shapes). Inject no clock and read no ambient time: this file is on the ambient-clock guard list.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| super admin browser to Platform `GroupController` | route id and typed `confirmName` are untrusted form/route input on a destructive POST |
| repository to other boards' rows | every query here bypasses the tenant filter, so a missing scope predicate crosses into other boards |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-102-01 | Tampering | `GroupRepository` scoped helpers (cross-board deletion through an unscoped `IgnoreQueryFilters`) | high | mitigate | Every bypass is immediately followed by a `Where` on the explicit `groupId`; plan 102-04's `Delete_LeavesAnotherBoardUnchanged` compares the other board's full graph with active board = other and = null |
| T-102-02 | Tampering | `DeleteConfirmed` POST (CSRF) | high | mitigate | `[ValidateAntiForgeryToken]` kept on the action; `AntiForgeryTokenCoverageTests` already pins POST coverage |
| T-102-03 | Tampering | delete of the wrong board | medium | mitigate | Server-side ordinal compare of the trimmed typed name against the stored name in `GroupService` (D-08); authoritative member recheck in the repository before staging (D-09) |
| T-102-04 | Denial of Service | partial delete leaving rows that block or corrupt the board list | medium | mitigate | One `SaveChangesAsync` (one database transaction); `ChangeTracker.Clear()` then rethrow on failure |
| T-102-05 | Information Disclosure | exception text on a failed delete | low | mitigate | Controller logs the exception server-side and shows only the fixed friendly sentence; never rethrows to the error page |
| T-102-06 | Elevation of Privilege | non-super-admin reaching Delete | high | mitigate | Class-level `[Authorize(Policy = "SuperAdminOnly")]` unchanged on `GroupController`; no new route |
| T-102-07 | Repudiation | one-way delete with no record | low | accept | The audit log line arrives in plan 102-09; this plan's toast and error log are the interim record |
</threat_model>
