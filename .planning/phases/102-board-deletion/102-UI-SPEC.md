# Phase 102 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Surfaces in scope: the Platform board Delete confirmation page (desktop `Areas/Platform/Views/Group/Delete.cshtml`, phone `Delete.Mobile.cshtml`), the success and failure toasts that surround it, and the board-count column on `/platform/Users` (desktop `Index.cshtml`, phone `Index.Mobile.cshtml`).

Sources: user decisions D-01 to D-13 in `102-CONTEXT.md` are binding and are not re-asked. Technical shape comes from `102-RESEARCH.md`. Visual rules come from `.claude/ui-guidelines.md` and the foundation tokens in `wwwroot/css/tokens.css`. The Phase 92 Move page (`Views/Move/Index.cshtml`) is the visual precedent: card header with icon title, rows with an icon and a status stripe, `<hr>` then a split action row, `data-disable-on-submit` on the form. Where this spec says "precedent", copy the structure but not the Move sheet's literals (hex, `rgb()`, `!important`): new markup meets Phase 100's "definition of converted" now so nothing is redone there.

Decisions made in this run (the user is remote, nothing was asked) are marked **[Decision]** and are grounded in the foundation, not taste.

## Layout Contract

**Focal point.** The primary focal point of the Delete page, on both twins, is the typed-name input and the Delete board button at the bottom of the card: the red-filled Delete button is the only danger-filled control on the page, and the `alert-danger` panel at the top frames the page without competing with it. The type rows above are scannable reference and never take a filled or accented treatment.

### Delete page, desktop (`Delete.cshtml`)

One card, centred: `<div class="row justify-content-center"><div class="col-lg-8 col-xl-7">`. **[Decision]** One card, not the Move page's two columns: the board's identity goes in the intro and the confirmation help, which keeps the typed-name step on the same eye line as the name and avoids a column-order problem on narrow desktop windows (a narrow desktop window never becomes the phone layout, and must not overflow at 320px).

Structure (top to bottom), identical in content on both twins; share it in one partial `Group/_BoardDeleteBody.cshtml` rendered by both twins so the twins cannot drift (the title chrome differs per twin; everything below the header is the partial). The new static guard fact for the Delete views must read the partial too.

1. `card modern-card` > `card-header modern-card-header`
   - Desktop: `<h2 class="mb-0"><i class="fas fa-trash text-danger me-2" aria-hidden="true"></i>Delete board</h2>`
   - `<span class="header-subtitle">This permanently removes the board and everything on it.</span>`
2. `card-body modern-card-body`
   1. Intro paragraph: `You are about to delete <strong>"{Name}"</strong>.` followed by a facts line: board type (the same `badge` as `Group/Index`: Campaign `bg-info text-dark` with `fa-book-open`, One-Shot `bg-primary` with `fa-dice-d20`), `Created {Html.LocalTime(CreatedAt, "date")}`, and `No members`. The facts line exists so two boards with similar names cannot be confused. `Html.LocalTime` is used because `CreatedAt` is a real instant; never `.ToString` on the date.
   2. One `alert alert-danger` (`role="alert"` is not set: it is present on load, not injected) with `fa-triangle-exclamation me-2`: `This cannot be undone. Nothing on this list can be recovered once you confirm.`
   3. `h3` "What will be deleted", then the type list (see below), or the empty-board line.
   4. If any unlink row has a count above zero: `h3` "Kept, but unlinked", one-sentence lead, then the unlink rows.
   5. Always: `h3` "Not affected" and one neutral row.
   6. The form (see Interaction Contract): `<hr>`, the confirmation form group, `<hr>`, the action row.

### Type rows (shared by "deleted" and "unlinked" sections)

A `<ul class="board-delete-rows list-unstyled">` of `<li class="board-delete-row board-delete-row--{deleted|unlinked|kept}">`. Each row:

- Left: a 24px-wide `fa-fw` icon cell (decorative, `aria-hidden="true"`).
- Body: a `<p class="mb-0">` with `<strong>{count} {label}</strong>` (count and label together, label pluralised: "1 quest", "12 quests"), then an optional `<p class="board-delete-hint mb-0">` (14px) when the type has a hint, then, only when the type has names, a `<details>`.
- Status stripe: `border-left: var(--qb-space-xs) solid` in the row's token (`--qb-danger-text` deleted, `--qb-info-text` unlinked, `--qb-neutral-text` kept). The stripe is reinforced by the icon and the words, never colour alone.
- Body cell: `min-width: 0; overflow-wrap: anywhere;` so a long board, quest or contact name wraps and never forces horizontal scroll at 320px (desktop) or 390px (phone).

Names list: `<details class="board-delete-names"><summary>{summary text}</summary><ul class="board-delete-name-list">` with one `<li>` per name, in the order given below. **[Decision]** The list is complete, not truncated, and has no inner scroll box: the confirmation exists to show everything that goes (CONTEXT specifics), and an inner scroll region would add a keyboard trap and clip the focus ring. The page scrolls. Each `<li>` is plain text (Razor-encoded; never `Html.Raw`; names are user-authored). A blank or whitespace name renders `(untitled)`. Duplicate names are all shown, not merged. Lists are collapsed by default (D-07); native `<details>` marker and toggle, no custom JS.

`summary` text is specific per type so each is distinguishable to a screen-reader user (D-07 types):

| Type | Row icon | Singular / plural label | Hint (14px, optional) | Names? | Summary text | Name order |
|------|----------|-------------------------|-----------------------|--------|--------------|------------|
| Quests | `fa-scroll` | quest / quests | none | yes | Show quest titles | title A to Z |
| Proposed dates | `fa-calendar-day` | proposed date / proposed dates | none | no | n/a | n/a |
| Date votes | `fa-check-to-slot` | date vote / date votes | none | no | n/a | n/a |
| Player signups | `fa-user-check` | player signup / player signups | none | no | n/a | n/a |
| Reminder records | `fa-envelope` | reminder record / reminder records | `Logs of reminder emails already sent for these quests.` | no | n/a | n/a |
| Events | `fa-calendar-days` | event / events | none | yes | Show event titles | title A to Z |
| Event signups | `fa-user-check` | event signup / event signups | none | no | n/a | n/a |
| Event series | `fa-repeat` | event series / event series | none | yes | Show event series names | name A to Z |
| Characters | `fa-user-shield` | character / characters | `Deleted together with their classes and images.` | yes | Show character names | name A to Z |
| Contacts | `fa-address-book` | contact / contacts | `Deleted together with their images.` | yes | Show contact names | name A to Z |
| Contact notes | `fa-note-sticky` | contact note / contact notes | none | no | n/a | n/a |
| Contact categories | `fa-folder` | contact category / contact categories | none | yes | Show category names | name A to Z |

| Shop items | `fa-store` | shop item / shop items | none | yes | Show shop item names | name A to Z |
| Purchases and returns | `fa-receipt` | purchase or return / purchases and returns | `The only record of what members paid on this board.` | no | n/a | n/a |

Rows appear in this order. A type with a count of zero is not rendered at all (D-07), including its hint and its details. Sorting is case-insensitive ordinal; no dates are rendered in the lists, so no `Html.LocalTime`/`Html.WallClock` call is needed there.

### "Kept, but unlinked" section (D-05, D-06)

`h3` "Kept, but unlinked", lead sentence `These rows live on other boards. They stay, and only their link to "{Name}" is removed.`, then rows in `board-delete-row--unlinked` style with `fa-link-slash`. Each row is hidden at count zero; the whole section (heading, lead, rows) is hidden when every row is zero.

| Row | Label | Hint | Names | Summary text |
|-----|-------|------|-------|--------------|
| Follow-up quests on other boards | `{n} follow-up quest on another board` / `{n} follow-up quests on other boards` | `Each loses its link to the original quest on this board.` | yes, `{title} (on {board name})` | Show follow-up quests |
| Signups using a character from this board | `{n} signup on another board uses a character from this board` / `{n} signups on other boards use a character from this board` | `Each stays signed up and loses only the character.` | no | n/a |
| Events detached from a series (defensive, expected to stay hidden) | `{n} event on another board belongs to a series on this board` / `{n} events on other boards belong to a series on this board` | `Each stays and is detached from the series.` | no | n/a |

### "Not affected" row (always shown)

One `board-delete-row--kept` row, `fa-shield-halved`: `User accounts, Dungeon Master profiles, trade items and calendar subscriptions are not touched. If this board is in a linked board set, it leaves the set and the set stays.` **[Decision]** This is a fixed sentence, not data-driven: the domain `Group` model carries no linked-set field and the spec adds no query for it.

### Empty board

When every deleted-type count is zero, the "What will be deleted" section renders one paragraph (not the `.empty-state` block, which is for a list that has nothing to show and would be oversized inside a confirm card): `<p><i class="fas fa-circle-info me-2" aria-hidden="true"></i>Nothing is stored on this board. Only the board itself will be deleted.</p>`. The typed-name step still applies.

### Delete page, phone (`Delete.Mobile.cshtml`)

`<div class="container-fluid px-2 mt-2"><div class="card modern-card">` (the converted phone card pattern, as `QuestLog/Index.Mobile.cshtml`), header with `<h1 class="mb-0">` and the same icon and title text (20px Cinzel, the phone display step), subtitle identical. Body is the same partial. Phone-only rules in `platform-group-delete.mobile.css`:

- every `summary` is `min-height: var(--qb-hit-min)` with `display: flex; align-items: center` (the foundation's `:where()` 44px rule does not cover `summary`), and the whole `summary` row is the tap target;
- the typed-name input and both buttons are at least 44px tall and wide (the foundation rule already covers `.btn` and `input`; do not size them smaller);
- the action row is `d-flex justify-content-between gap-2` and must not overflow at 390px: "Keep board" and "Delete board" are short enough to share a row; do not wrap or stack the buttons;
- no `@media` anywhere in the sheet.

The phone twin is content-equivalent to the desktop page by decision D-10: nothing is omitted on either side.

## Interaction Contract

### Typed-name confirmation (D-08)

Inside `<form method="post" asp-action="Delete" asp-route-id="@Model.Id" data-disable-on-submit>` (antiforgery tag helper renders the token; `data-disable-on-submit` is the existing `site.js` hook the Move page uses):

```
<hr>
<div class="mb-3">
  <label for="confirmName" class="form-label">Type the board name to confirm</label>
  <input id="confirmName" name="confirmName" class="form-control" type="text"
         autocomplete="off" autocapitalize="none" autocorrect="off" spellcheck="false"
         aria-describedby="board-delete-help board-delete-status" data-board-delete-name="{Name, HTML-encoded}" />
  <div id="board-delete-help" class="form-text">Type "{Name}" exactly, including capitals and spaces. The delete button unlocks when it matches.</div>
  <div id="board-delete-status" role="status" class="board-delete-status"></div>
</div>
<hr>
<div class="d-flex justify-content-between">
  <a asp-action="Index" asp-area="Platform" class="btn btn-secondary"><i class="fas fa-arrow-left me-2" aria-hidden="true"></i>Keep board</a>
  <button type="submit" class="btn btn-danger" data-board-delete-submit disabled><i class="fas fa-trash me-2" aria-hidden="true"></i>Delete board</button>
</div>
```

Behaviour of `platform-board-delete.js` (ES module):

| State | Input | Button | Status region |
|-------|-------|--------|---------------|
| Initial / empty | empty, not focused (no autofocus: the admin must read the lists first) | `disabled` (rendered server-side) | empty |
| Partial or wrong text | typing | disabled | empty |
| Exact match | `input.value.trim() === data-board-delete-name`, ordinal, case-sensitive, trim the typed side only | enabled | `<i class="fas fa-circle-check me-2" aria-hidden="true"></i>Name matches. You can delete the board now.` (success-text colour; announced politely once, only when the state changes to a match; cleared when it stops matching) |
| Was matching, then edited | typing | disabled again | cleared |
| Submitting | locked | disabled by `data-disable-on-submit` | n/a |
| Restored from the back-forward cache | value kept by the browser | re-synced from the value (the script listens to `pageshow` and runs the same sync; `site.js` re-enables submit buttons on `pageshow`, so the gate must run after it and win) | re-synced |

Rules:
- Paste is allowed in the input (guidelines: forms allow paste). No `onpaste` block.
- The script never enables the button after the form has been submitted.
- **[Decision]** JavaScript is required to unlock the button. Server render is `disabled`, and a no-JS browser can never delete; this is accepted for a super-admin-only tool and the server remains the authority (it re-checks the name with an ordinal compare against the stored name on POST).
- Pressing Enter in the input submits only when the default button is enabled; with the button disabled the browser does not submit.
- No inline `onkeyup`, `oninput` or `<script>`; the board name goes into the data attribute HTML-encoded and nowhere else in script.

### Refusal and error states

| State | Where it shows | Behaviour |
|-------|----------------|-----------|
| Typed name does not match on POST (D-08, server re-check) | Re-render of the Delete page (not a toast, so the admin stays on the page with the preview) | Preview is rebuilt so counts are current. A `refusal-line` (`role="alert"`) appears above the input: icon `fa-circle-exclamation`, text `The name you typed does not match "{Name}". Check it and try again.` The input is empty (never echo the wrong text back), carries `is-invalid` and `aria-invalid="true"` (the shared invalid-field treatment: 2px danger border plus the message), `aria-describedby` also names the refusal line's id, and takes `autofocus` so focus lands in the field. The button is disabled again until the gate matches. |
| Members were added since the preview (D-09) | Error toast on the board list | `TempData["Error"]`, redirect to Platform `Group/Index`. Persists until dismissed (`role="alert"`). Nothing deleted. Same outcome when a GET opens Delete for a board that has members. |
| Board no longer exists (deleted by another admin, bad id) | Info toast on the board list | `TempData["Info"]`, redirect to Platform `Group/Index`. |
| Save failed, rolled back (D-11) | Error toast on the Delete page | `TempData["Error"]`, redirect back to the Delete page (the board still exists). Never a 500. |
| Success | Success toast on the board list | `TempData["Success"]`, redirect to Platform `Group/Index`; polite `role="status"`, auto-hides after 5s. |

**[Decision]** There is no "things changed while you were reviewing" banner, unlike Move: D-09 states the preview need not match exactly and content added after the preview is simply deleted too.

Toasts use only the shared `_Toasts` partial through `TempData` keys; no toast markup is written for this phase. Each message is one sentence.

### Navigation

- "Keep board" (the secondary action, left of the primary, as the guidelines place a cancel action) and the success path both go to `Platform/Group/Index` (the board list titled "Group Management"). **[Decision]** The label is "Keep board", replacing the old "Back to Groups"; it names the outcome of leaving without deleting.
- The Delete link on `Group/Index` is unchanged (still shown only when `MemberCount == 0`).
- No `confirm()` dialog on this page.

## Users column (D-12, D-13)

Display only: no sort control, no filter, no link, and `<th>` is not clickable.

### Desktop (`Users/Index.cshtml`)

New column **Boards**, placed between Email and Confirmed: `<th scope="col">Boards</th>`.

- Cell: `<td title="Alpha, Beta, Gamma">3<span class="visually-hidden"> boards: Alpha, Beta, Gamma</span></td>`. The visible content is the bare number in the table's body face. The `title` gives hover for mouse users (D-12); the visually-hidden text gives screen-reader and keyboard users the same names, since a `title` on a cell is not keyboard reachable. Singular for one: `1` with ` board: Alpha`.
- A user on zero boards shows `0`, no `title` and no hidden text.
- Names are sorted A to Z, case-insensitive, joined with `, `.
- The cell is plain text on the paper table surface (dark ink); no colour, icon or badge is added, so there is no status to convey by colour.
- Nothing is added to the Actions cell. The existing `onclick="return confirm(...)"` and the legacy markup are left for Phase 100.

### Phone (`Users/Index.Mobile.cshtml`)

Inside each `.user-card-mobile`, after the email block and before the action buttons, one new block:

- `1` or more boards: `<details class="user-boards"><summary><i class="fas fa-layer-group me-2" aria-hidden="true"></i>3 boards</summary><ul class="user-boards-list list-unstyled">` one `<li>` per board name, A to Z. Singular summary: `1 board`. The summary is the whole tap target, at least `--qb-hit-min` tall, with the shared focus ring.
- Zero boards: plain `<div><i class="fas fa-layer-group me-2" aria-hidden="true"></i>0 boards</div>`, no `details`.
- Names wrap (`overflow-wrap: anywhere`); the list indents by `var(--qb-space-lg)`; rows are separated by `var(--qb-space-xs)`.
- The legacy `platform-users.mobile.css` is not edited; the new rules live in `platform-users-boards.mobile.css` under `@layer pages` with no `@media` and no `!important`.
- Phone text colour is inherited from the glass card; set none.

The phone twin deliberately shows the count as words ("3 boards") while desktop shows the bare number under a "Boards" header: the header does the naming on desktop, and the phone card has no header row.

## Accessibility (per `.claude/ui-guidelines.md` checklist)

- Contrast: all text on glass is `--qb-fg` or a `--qb-*-text` variant that already holds 4.5:1; row stripes (non-text) use the `-text` variants and are at least 3:1 on the scrim; no new colour token is added, so `UiFoundationLayerGuardTests` token pairs are unchanged.
- Focus: native `summary`, input, buttons and the Keep board link take the foundation's two-tone ring (`base.css` covers `summary`); no ancestor sets `overflow: hidden`.
- Landmarks and names: the one `h2` (desktop) or `h1` (phone) is the page title; section headings are `h3`; the input is labelled by its `<label for>`; every decorative icon is `aria-hidden="true"`; the `title` on the Users cell is backed by visually-hidden text.
- Live regions: the match status is `role="status"`; the mismatch refusal is `role="alert"`; the toasts keep their existing roles (error persists, success hides after 5s).
- Targets: at least 44 by 44px on the phone (summaries, input, both buttons), at least 24 by 24px on desktop.
- No inline `style`, `<script>` or handler in any new markup; no `@media` in a phone sheet; no `!important`; no hex or `rgb()`.
- Motion: nothing animates; `<details>` uses the native toggle.
