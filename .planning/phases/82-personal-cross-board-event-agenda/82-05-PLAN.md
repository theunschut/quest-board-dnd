<objective>
Make the agenda reachable and make the round trip out of it complete.

The user-menu entry is the unconditional path in and is what keeps the page reachable when no
board type has resolved (D-08/D-10). The two cross-links from the availability overview and the
calendar are convenience only — both of those surfaces already sit behind the resolved-board-type
gate, so neither can be the way in. And a viewer who followed a row into an event's details needs
a signposted route back to the list they were working through (D-13); the active board is
deliberately not switched back, because switching twice per answer is state that is easy to get
wrong and hard to notice when it is.

Purpose: close the navigation loop around the page built in `82-03`/`82-04`.
Output: two nav entries, four cross-links, one conditional back-link, and the nav tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| navigation markup → route | A nav entry is a hint, never an authorisation; the target must gate itself |
| query string → `EventsController.Details` | The origin marker is attacker-supplied and must grant nothing |
| anonymous request → authenticated navigation | An entry leaking into the public navigation would disclose that a feature exists and invite probing |
