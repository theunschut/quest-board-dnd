<objective>
Put the cross-board read behind a page: view models, a controller that reads the viewer's
memberships fresh on every request and intersects the session-remembered board filter against
them, the desktop view with rosters inline and a shared switch-confirm modal, and the
integration suite that proves the happy path, the three empty states, and reachability with no
active board.

Two things in here are load-bearing and easy to get wrong:

1. **The intersection.** The stored filter selection is only ever a hint about which of the
   viewer's *current* memberships to show. It is intersected against the freshly read
   membership set before it can reach any predicate (D-04, D-15, D-17 case 4).
2. **The middleware exemption.** `GroupSessionMiddleware` redirects every authenticated GET
   with no active board to the board picker. The agenda is specifically the surface that needs
   no active board, so without an exemption it is unreachable in exactly the situation it
   exists for. This was found by reading the live middleware during planning; it is not in
   CONTEXT.md, RESEARCH.md or the UI spec.

Purpose: the phase's first working surface.
Output: controller, view models, desktop view, stylesheet, integration suite.
</objective>

  <action>
Implements D-04 (the filter narrows before the window is taken), D-05 (session memory), D-09 (no
SuperAdmin widening branch), D-15 (membership read fresh every request) and D-17 case 4 (the
filter cannot widen the set). It deliberately does not touch the landing path — per D-07 the
agenda supplements rather than replacing where anyone lands, so the board picker's own redirect
is left exactly as it is.

Create `QuestBoard.Service/Controllers/AgendaController.cs` in namespace
`QuestBoard.Service.Controllers` (beside `GroupPickerController`, not under `Controllers/Events`).

`[Authorize]`, primary-constructor injection in the style of `EventsController`:
`IEventService eventService`, `IGroupService groupService`, `IUserService userService`,
`IActiveGroupContext activeGroupContext`, `IMapper mapper`, `IOptions<AgendaOptions> agendaOptions`.

One action:
`[HttpGet] public async Task<IActionResult> Index(int? take = null, string? boards = null, CancellationToken token = default)`

Body, in this order:

1. Clamp the window: `var options = agendaOptions.Value;` then
   `var effectiveTake = Math.Clamp(take ?? options.DefaultTake, 1, Math.Max(1, options.MaxTake));`
   Copy the comment from `EventsController.Index` explaining that the ceiling stops a
   client-supplied size becoming an unbounded query and the floor is a second defensive layer.

2. `var currentUser = await userService.GetUserAsync(User);`

3. Read memberships fresh: `var memberships = await groupService.GetGroupsForUserAsync(currentUser.Id, token);`
   then `var memberGroupIds = memberships.Select(m => m.Id).ToList();`
   Comment plainly that this is read on every request and never taken from session or claims,
   because membership is the authorisation for this page: a board the viewer has left has to
   disappear on the very next page load, not whenever a cache happens to expire.

   State plainly in a comment that there is deliberately **no** SuperAdmin branch here. The board
   picker hands a SuperAdmin every group; mirroring that on this page would turn it into an
   unbounded read over every event in the application. One rule for everyone: this page is
   scoped by the viewer's own membership rows.

4. Resolve the requested selection into `List<int> requestedIds`, using the `boards` parameter's
   three-state contract:
   - `boards` is null (absent) → read `HttpContext.Session.GetString(SessionKeys.AgendaBoardFilter)`.
     A null session value (key never set) means "all of my boards": use `memberGroupIds`. The
     literal `none` means the viewer deselected everything: use an empty list. Anything else is
     parsed as comma-separated ints, skipping empty and unparseable tokens.
   - `boards` equals `all`, case-insensitively → remove the session key and use `memberGroupIds`.
     This is the reset control on the all-filtered-out empty state.
   - otherwise → parse `boards` the same way as a stored value. Note the desktop filter form
     carries a leading empty hidden field with the same name, so unticking every box still
     submits the parameter; that is how "no boards selected" is expressible at all.

5. **Intersect before use:** `var effectiveGroupIds = requestedIds.Intersect(memberGroupIds).Distinct().ToList();`
   Comment that the stored or supplied selection is only ever a hint about which of the viewer's
   *current* memberships to show — it narrows, it can never widen, and a stale id left over from
   a board the viewer has since left is silently dropped rather than rejected with an error.
   This is the line that makes "the filter cannot widen the set" true by construction rather
   than by convention. Do not move it after the query, and do not skip it on any branch.

6. Persist the selection whenever `boards` was supplied and was not the reset sentinel:
   `HttpContext.Session.SetString(SessionKeys.AgendaBoardFilter, effectiveGroupIds.Count == 0 ? "none" : string.Join(',', effectiveGroupIds));`
   Store the intersected set, never the raw request, so a foreign id can never be parked in
   session.

7. `var agenda = await eventService.GetCrossBoardAgendaAsync(effectiveGroupIds, currentUser.Id, effectiveTake, token);`
   Call it unconditionally, including when `effectiveGroupIds` is empty.

8. Build a `Dictionary<int, GroupWithMemberCount>` keyed by id from `memberships`, map the rows
   with `mapper.Map<IList<AgendaRowViewModel>>(agenda.Rows)`, then for each mapped row set
   `BoardName` and `BoardType` from that dictionary and
   `IsActiveBoard = activeGroupContext.ActiveGroupId == row.BoardId`. This is the post-map
   assignment the profile explicitly ignores those members for. Every row's board id is
   guaranteed present in the dictionary because the service already dropped anything outside the
   membership set; if a lookup ever misses, drop the row rather than rendering a blank board
   name, and say why in a comment.

9. Build `AvailableBoards` from `memberships`, ordered by name, with
   `IsSelected = effectiveGroupIds.Contains(m.Id)`. Set `TotalCount = memberships.Count`,
   `SelectedCount = effectiveGroupIds.Count`,
   `SelectedBoardIds = string.Join(',', effectiveGroupIds)`.

10. `ActiveBoardName`: the name of the active board from the membership dictionary when
    `activeGroupContext.ActiveGroupId` is non-null and present in it, otherwise null. The view
    renders a different sentence when it is null.

11. `EmptyState`: `NoBoards` when `memberGroupIds` is empty; otherwise `AllBoardsFiltered` when
    `effectiveGroupIds` is empty; otherwise `NoUpcomingEvents` when there are no rows; otherwise
    `None`. Comment that the filtered-out case is kept distinct because it is the only one with a
    one-click fix, and that it is keyed on the effective set being empty rather than on a second
    probe query, so rendering an empty page never costs an extra unbounded read.

12. Set `HasMore`, `Take = effectiveTake`,
    `NextTake = Math.Min(effectiveTake + options.PageIncrement, options.MaxTake)`,
    `CurrentUserId = currentUser.Id`, and `return View(viewModel);`

In `QuestBoard.Service/Middleware/GroupSessionMiddleware.cs`, add
`$"/{ControllerNameOf<AgendaController>()}"` to `ExemptPathPrefixes`, using the same
`nameof`-derived form as the two entries already there rather than a raw literal. Add a comment

Change nothing else in the middleware: the null-active-board redirect, the 409 on
