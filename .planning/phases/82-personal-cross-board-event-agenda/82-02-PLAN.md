<objective>
Build the cross-board read: one repository query that returns the next N upcoming events
across an explicitly supplied set of board ids with every signup and signer name eagerly
included, and one service method that turns those rows into an agenda carrying the viewer's
own cell and the full roster on each row.

This is the application's first user-facing read that deliberately steps outside the ambient
tenant filter. It is safe only because the caller's own membership set is pinned into the same
predicate that lifts the filter, making the query strictly narrower than the ambient filter
would be for any single board, never broader (D-14). A second, deliberately weaker in-memory
re-check runs after materialization (D-16).

Purpose: get the read correct and provably bounded before any UI exists.
Output: four domain types, one repository method, one service method, one unit test class.
</objective>
