`width: 100%`; `display: flex; align-items: center; gap: var(--qb-space-md)`; `min-height: var(--qb-hit-min)`; `padding: var(--qb-space-sm) var(--qb-space-md)`; `border: 0`; `border-radius: var(--qb-radius-md)`; `background-color: transparent`; `color: inherit`; `font: inherit`; `text-align: start`. ### Keyboard and assistive-technology contract (FIXED; closes the S1 barrier)

1. Tab order is: skip link, bar (Logout), Go to Platform when present, then each board row in list order, then the page ends. No `tabindex` anywhere on the rows.

3. Each row's accessible name is its text: board name then the member count. The icons are `aria-hidden`.
4. A screen reader announces a list of N items.

### Copy button states (FIXED; closes the phone icon-only regression)

Rest: the original markup and class list, captured once when the script wires the button (icon-only on the phone, icon and `Copy` on desktop), `btn-secondary`. Success: `btn-success` with `fa-check`; **desktop** label `Copied!`; **phone** stays icon-only (check icon, same 44px width, `aria-label` unchanged so nothing shifts). Fallback (clipboard unavailable or denied): label `Press Ctrl+C` on desktop, the address field revealed. After 2 seconds the button returns to exactly its captured rest markup and classes. A visually hidden `role="status"` element on the page receives `Copied!` or `Press Ctrl+C to copy` so the state change is announced (default, confirm at Gate 2).

When the fallback reveals the address field it takes its own full-width line inside the actions area (`flex: 1 1 100%; min-width: 0`), is selectable, takes the row's text colour at 4.5:1 or better, never widens the page, and stays revealed. ## 5. `Shared/AccessDenied` and the phone overflow fix

**View (twin-less, both layouts).** One `h1` `Access Denied` (`fa-shield-alt`) in the card header; body centred: a `fa-ban` icon, `h2.section-heading` `You Don't Have Permission` (16px on the phone, 20px on desktop, per Typography), the sentence `You don't have permission to view this page.` at body colour (the `text-muted` class is dropped; default, confirm at Gate 2), then **one** alert: signed in `alert-info` with `fa-info-circle`, signed out `alert-warning` with `fa-sign-in-alt` and the underlined `log in` link to `Account/Login`; then `Back to Quest Board` as `btn-secondary` with `fa-home` (navigation, not caution), full width on a phone and auto width from the `md` step (`d-grid gap-2 d-md-block`, as today). Wrapper `row justify-content-center` > `col-md-6`. The apostrophe in `Don't` is a literal character in static markup.

**Overflow fix: observable contract (X-4; Phase 97 reuses it on `Events/Details`).**

1. At a phone User-Agent with touch at 390px and at 412px, `document.documentElement.scrollWidth` equals the viewport width (today 394 at 390 and 416 at 412).
2. At a desktop User-Agent at 320px, no horizontal scroll, for both the signed-in and the signed-out variants.
3. With the text-spacing stress (line height 1.5, letter spacing 0.12em, word spacing 0.16em) there is still no horizontal scroll.
4. The merged credential views, `Events/Details` and every other page whose root is a `.row` inside the phone main show no horizontal scroll and move by no more than the 4px that the overflow removed.

**Placement (default, confirm at Gate 1).** Root cause: the phone main pads its content by 8px (`container-fluid px-2`) while a Bootstrap `.row` pulls out by 12px. Recommended: a single rule in the phone shell sheet, `shell.mobile.css`, inside its existing layer, scoped so only a root-level row is affected:

```
.mobile-layout main > .row { --bs-gutter-x: var(--qb-space-md); }
```

(`.row` declares `--bs-gutter-x` on itself, so the override must target `.row`, not `main`.) Row margin becomes -8px and column padding 8px; the card inset stays 8px. This is a one-rule edit to a foundation sheet, so it needs the operator's yes at Gate 1; it also serves `Events/Details` in Phase 97, which has a real two-column grid that the fallback cannot help. **Fallback:** drop `.row` and `.col-md-6` from `AccessDenied` and centre the card with a `max-width` and `margin-inline: auto` class in `account.css` (`pages` layer); Phase 97 then fixes `Events/Details` on its own. Either way the contract above is verified with the overflow probe before the fix is called done.
