with `Url.Action(nameof(SetPassword), "Account", ...)` and enqueues `ForgotPasswordEmailJob`; `SetPassword` GET renders
the view for any `userId` and `token`, and the POST validates the token, showing the persistent error
`Password reset failed. The link may be expired or invalid. Please request a new one.` on failure and redirecting to

`EmailSettings:SuppressSending: true` and says to set `EmailSettings__SuppressSending=false` to test against a real inbox;
run-app's `--env` passes that to the one app process. A successful reset changes the account's security stamp, so the
same link is refused afterwards. The link is a credential: the verify script never prints it, uses only its path and
query against http://localhost:8096 (whatever host the mail shows), and its report records carry `token=REDACTED`.
</context>
