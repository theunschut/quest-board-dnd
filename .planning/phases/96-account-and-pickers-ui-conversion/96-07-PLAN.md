Script facts (verified in research): the ~90 inline lines are identical on both twins; the repository has no module
precedent yet (`contact-tags.js` is a classic script), and the guideline asks for `<script type="module" src=...>`; a
module is deferred, so no DOMContentLoaded wrapper is needed, and the `bootstrap` global from the layout's classic
bundle is available. Bootstrap 5.3.8's modal data-attribute click handler calls `preventDefault()` only when the trigger
is a link (`A` or `AREA`, checked in the vendored bundle), so a `type="submit"` button carrying that attribute would
open the dialog while its own form still submitted unless the module cancelled it: with the module failing to load and
Bootstrap running, the revoke would go out behind an open confirmation. So the row's Delete carries no Bootstrap modal
attribute, and the module opens the dialog itself inside the row form's `submit` listener: when `#deleteSubscriptionModal`
exists and `window.bootstrap.Modal` is defined it calls `event.preventDefault()` and then
`bootstrap.Modal.getOrCreateInstance(dialog).show(opener)`, `opener` being `event.submitter` or the form's submit button.
`Modal.show(relatedTarget)` hands the opener to `show.bs.modal` as `event.relatedTarget` (read in the vendored bundle),
so the fill code is the same as for a data-attribute trigger. Bootstrap returns focus to the trigger only for
data-attribute opens, so the module does it: it keeps the opener and focuses it on the dialog's `hidden.bs.modal` while
it is still connected. Outcomes: both scripts run, the dialog opens and nothing is sent; the module missing with
Bootstrap present, no dialog and today's plain post; Bootstrap missing, the module does not cancel, today's plain post;
JavaScript off, today's plain post. Never a dialog and a post together. This departs from the RESEARCH "Alternatives
Considered" row and the PATTERNS Delete-modal note, which open through the data attribute for Bootstrap's built-in
focus return: that route cannot keep the no-script post without the dialog-plus-post failure, so the focus return is
written by hand here. The UI-SPEC "2. Profile" Delete row (`type="button"` with the modal attributes), its Delete
dialog "Opening" row and its "Without script" row are superseded the same way (the UI-SPEC carries a supersession note
under its Delete dialog table saying so). Today's sentence, which the dialog must carry verbatim: `Delete "` + name + `"? Any device using this
address will silently stop receiving updates the next time it checks — this cannot be undone. You can always create a
new subscription afterward.` Pinned: the 20 copy-contract strings (two of them, `Copied!` and `Press Ctrl+C`, live in
the script after this plan); the empty-state sentence in `ProfileCalendarSubscriptionTests` and in
`CalendarSubscriptionStaticGuardTests`; the per-row marker counts (the dialog is outside the rows and must contain
neither counted stem); `RevokeSubscription_*` and `Mutations_AreRejectedWithoutAnAntiforgeryToken` post directly and
