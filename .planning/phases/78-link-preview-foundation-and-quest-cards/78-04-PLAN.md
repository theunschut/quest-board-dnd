<objective>
Widen `IActiveGroupContext` with `SetGroupId(int? groupId)` and implement it on every existing implementation, so that a caller with only the interface can scope a read to a group it proved rights to by other means.

This is the seam the signed preview route needs. The concrete service already has this method, but resolving the concrete type works in production and silently does nothing under test: the integration-test host substitutes its own singleton double for the interface, and that double — not the concrete service — is what the database query filter reads. Widening the interface is the only shape that behaves identically in both places; the alternative fails in the worst possible way, with green tests over a dead code path.

Purpose: make group scoping settable through the abstraction so the preview path is testable and honest.
Output: one new interface member and thirteen implementations, with the whole suite still green.

Decisions implemented (see 78-CONTEXT.md): D-12
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → group scoping | Whatever sets the active group decides which board's rows the database query filter will return; this is the tenant-isolation boundary |
| request scope → session | An override that leaked into Session would outlive the request and become a lasting grant |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-78-01 | Information Disclosure | `IActiveGroupContext` implementations | critical | mitigate | Every implementation sets an in-memory override only, scoped to the execution context; the fail-closed query filter continues to be the single enforcement point and is never bypassed |
| T-78-03 | Elevation of Privilege | any implementation that persisted the override | high | mitigate | The interface doc-comment states the prohibition where an implementer reads it, and no implementation added here touches Session |
| T-78-14 | Tampering | test doubles diverging from the production implementation | high | mitigate | The integration-test double's method assigns the same state its getter reads, so a call through the interface is observable by the query filter in tests exactly as in production — this is the specific failure this plan exists to prevent |
</threat_model>
