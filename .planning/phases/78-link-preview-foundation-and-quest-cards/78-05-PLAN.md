<objective>
Build the three small, stateless domain services the rest of this phase and all of the next phase consume: the one that signs and verifies a share token, the one that turns a Markdown description into a card-sized plain-text snippet, and the one that turns a relative path into the application's public absolute URL.

All three are deliberately shaped to extend by adding a caller rather than by being edited: the signer takes an entity type, the description builder takes its fallback text as a parameter, and the URL builder takes any relative path.

Purpose: put every piece of new logic that can be tested without a web request behind a unit test, before any of it is wired into a route.
Output: three interfaces, three implementations, one constants class, their registrations, and three unit-test classes.

Decisions implemented (see 78-CONTEXT.md): D-01, D-04, D-07, D-14
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| link recipient → token verification | An arbitrary string arriving from anywhere on the internet is handed to the verifier; everything downstream trusts its output |
| quest author → card description | Author-controlled Markdown becomes text published to third-party crawlers |
| configuration → absolute URL | The public base URL determines where every card and copied link points |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-78-04 | Tampering | `LinkSigningService.TryUnprotect` | high | mitigate | Verification is the framework's authenticated data-protection primitive; a modified, malformed, empty, over-long, cross-purpose, or wrong-type token returns false with both out parameters at zero. Rejection is total — there is no degraded or partial success path |
| T-78-02 | Spoofing / Elevation of Privilege | signed payload shape | high | mitigate | Entity type, entity id and group id are signed as one payload, so a signature for a quest on one board does not verify as the same id on another; the different-group test pins this |
| T-78-06 | Information Disclosure | `LinkCardDescriptionService.BuildDescription` | medium | mitigate | Truncation operates on the rendered, sanitized plain text and never on the Markdown source, so a cut can never strip a closing fence and reveal text the author hid inside it |
| T-78-15 | Denial of Service | anonymous token verification | low | mitigate | Tokens over 512 characters are rejected before any cryptographic work is attempted |
| T-78-16 | Spoofing | `PublicUrlBuilder` base resolution | medium | mitigate | The configured public base URL wins over any request-derived value, so a forged host header cannot redirect card metadata at an attacker-controlled origin even if proxy trust were misconfigured |
</threat_model>
