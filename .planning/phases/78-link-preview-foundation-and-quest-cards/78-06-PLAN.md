<objective>
Produce the single branded 1200x630 card image every quest card will use, and prove it is reachable by an anonymous caller with no redirect.

This is an asset-production deliverable, not a code reference. The quest entity has no image of its own and per-quest generated images are out of scope, so this one file is the visual identity of every card this phase and the next one emit. It is produced programmatically from board art already in the repository, and then a human looks at it — a script can guarantee the dimensions and the file size but not that the result looks like this project.

Purpose: give every card a large-format image so the embed renders as a large card rather than a small side thumbnail, and prove the crawler-facing serving contract.
Output: the PNG, the generator that made it, and an integration test asserting the serving contract.

Decisions implemented (see 78-CONTEXT.md): D-13
</objective>

  <action>
    Write a Python generator at tools/link-preview-card/generate.py using Pillow, which is already installed on this machine. Commit it alongside the image so the asset can be regenerated for a rebrand or reused by the next phase. This is a deliberate choice over a throwaway script: an uncommitted one-off would leave the only branded asset in the product unreproducible.

    Background. Open Ruined Poster 5.png, falling back to Ruined Poster 6.png if the first is unusable. The source is portrait, so take a landscape band from its central texture area rather than squashing the whole poster: crop a region whose aspect ratio is 1200 to 630, as wide as the source allows, centred vertically at about 45 percent of the source height, then resize that crop to exactly 1200 by 630 with a high-quality resampling filter.

    Vignette. Composite a radial darkening over the background — black, fully transparent at the centre, reaching about 22 percent opacity at the corners — so text stays legible without a flat panel hiding the parchment texture.

    Headline. Draw the text "D&D Quest Board", horizontally centred, with the text block sitting in the upper-to-middle third of the canvas and a rendered block height of roughly 110 to 130 pixels. Resolve the font in this order: a Cinzel face already installed under the Windows font directory; then the OFL-licensed Cinzel variable font fetched into the scratchpad from the Google Fonts repository, with its weight axis set to 700 — the application already loads this exact family from Google Fonts at runtime, so a local copy for a one-time render introduces no new dependency; then, if the weight axis cannot be set on that variable font, the same face rendered with a stroke width of 2 to approximate bold; then, only if Cinzel cannot be obtained at all, an installed serif bold face. Record which branch was taken and raise it explicitly at the checkpoint in task 2 if the last fallback was used, so the operator decides whether the substitution is acceptable rather than discovering it later.

    Headline contrast. Before drawing, measure the mean luminance of the background pixels inside the headline bounding box. If it exceeds 120, deepen the vignette within that band until the measured mean is at or below 110. Then draw the headline twice: first in black, offset 3 pixels right and down at about 80 percent opacity, then in gold #FFD700 on top. The measurement decides whether contrast is adequate, not an assumption. Print the measured value and record it in the SUMMARY.

    Emblem. Open Crown Seal.png, scale it to about 140 by 140 preserving its alpha, and composite it in the lower-left region. It must never sit centred behind the headline; it reads as a signature mark, not as a competing focal point.

    Safe area. Every drawn element — headline and seal — must lie entirely inside the rectangle inset 40 pixels from each edge. The generator asserts this and exits with a failure rather than writing a clipped card.

    Omit the optional subhead and the optional dice glyph. The subhead adds density for no functional gain, and the dice glyph would need an icon font this repository does not vendor; leaving both out keeps the render deterministic. If the operator wants them, they can be added at the checkpoint.

    Export. Save as an optimised PNG to QuestBoard.Service/wwwroot/images/link-preview-card.png. If the result exceeds 200KB, re-save through an adaptive 256-colour palette; if still over, try 128 colours, then 64. Never switch to a different image format while keeping the .png extension — this file is served unauthenticated and its content type comes from its extension, so the bytes and the extension must agree. If 64 colours still exceeds the budget, stop and raise it at the checkpoint rather than shipping an oversized asset.

    Write tools/link-preview-card/README.md recording what the file is for, the exact source images consumed, the canvas and safe-area numbers, the font resolution order, the size budget, and the single command that regenerates the asset. Plain language, no phase, plan, or requirement identifiers anywhere in either file.
  </action>

| T-78-18 | Denial of Service | repeated anonymous fetches of the image | low | accept | A single sub-200KB static file served by the framework's static-file middleware, cached by the very crawlers that fetch it; no per-request work is done on this path |
