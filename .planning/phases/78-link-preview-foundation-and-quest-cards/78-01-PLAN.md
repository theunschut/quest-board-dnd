<objective>
Make the Data Protection key ring durable and make the app's forwarded-header trust cover scheme and host, not just client IP. Nothing else in Phase 78 is meaningful until both are true: a signed link that outlives one deploy needs a persisted key ring (D-03), and an absolute `og:url`/`og:image` needs correct scheme and host (D-05).

Purpose: remove the two silent, infrastructure-level failure modes that would make every later plan in this phase appear to work locally and produce no card in production.
Output: a `DataProtectionKeys` table created by an EF migration, key persistence registered inside the Repository layer, extended `ForwardedHeadersOptions`, and an automated test pinning the forwarded-header flags.

Decisions implemented (see 78-CONTEXT.md): D-03, D-05, D-06
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reverse proxy → Kestrel | Forwarded scheme/host/client-IP headers cross here; a caller reaching Kestrel directly can attempt to inject them |
| application → database | The Data Protection key ring — the secret material every signed link in this phase depends on — is written and read across this boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-78-05 | Spoofing | `ForwardedHeadersOptions` in Program.cs | medium | mitigate | Forwarded headers honoured only from addresses listed in the `ReverseProxy:KnownProxies` configuration section; the runtime drops all forwarded headers when that list is empty, so the failure mode is a wrong-looking URL, never a trusted spoofed host |
| T-78-09 | Information Disclosure | `DataProtectionKeys` table | medium | mitigate | Keys are stored in the application database, which is already the app's highest-trust store and is not exposed by any endpoint; the table carries no tenant column and is never returned through a query filter or repository |
| T-78-07 | Repudiation | signed link lifetime | low | accept | Links carry no expiry and cannot be revoked per the locked decisions; deleting the quest is the only retraction, and it works because the serve path does a live read. Accepted deliberately over a link that silently stops working |
| T-78-SC | Tampering | NuGet install of `Microsoft.AspNetCore.DataProtection.EntityFrameworkCore` | high | mitigate | Package legitimacy audit in 78-RESEARCH.md returns verdict OK / Approved — first-party Microsoft package from the dotnet/aspnetcore repository, version index cross-checked on nuget.org. No `[ASSUMED]` or `[SUS]` entries, so no human legitimacy checkpoint is required; the pinned version must be 10.0.9 to match the existing EF-family pins |
</threat_model>
