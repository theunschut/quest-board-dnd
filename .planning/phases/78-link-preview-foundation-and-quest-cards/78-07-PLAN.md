<objective>
Build the anonymous-allowed route that turns a signed token into a rich card: verify the signature, scope the read to the signature's own group, load the quest, and render a standalone minimal document carrying the Open Graph and Twitter Card tags plus a meta-refresh to the real quest page.

The route is deliberately separate from the quest controller. Nothing that later changes the quest page can widen what an anonymous signed caller sees, the endpoint is small enough to audit in one sitting, and the next phase adds sibling routes alongside it rather than a second branch inside another controller.

Purpose: make a shared quest link unfurl as a card, with the signature — and only the signature — deciding whether it does.
Output: a preview controller, its view model, its standalone view, one middleware exemption, and an integration-test class covering the tag contract, tamper rejection, cross-board replay, and the token's strict metadata-only scope.

Decisions implemented (see 78-CONTEXT.md): D-04, D-08, D-10, D-11, D-12, D-14
</objective>

    Create `QuestPreviewController` in `QuestBoard.Service.Controllers.LinkPreview`, deriving from `Controller`, with primary-constructor injection of `ILinkSigningService`, `IActiveGroupContext`, `IQuestService`, `ILinkCardDescriptionService` and `IPublicUrlBuilder`.

    Do not put a class-level authorization attribute on it, and do not add an anonymous-allow attribute either: this application registers no fallback authorization policy, so an unattributed action is already anonymous, and adding a redundant attribute would suggest one is being overridden.     Add a single action `Quest` attributed `[HttpGet("/s/quest/{token}")]` taking `string token` and a `CancellationToken`. Its body, in this exact order:

    1. Call the signing service's try-unprotect with the token and the quest entity-type constant. On false, return `NotFound()` immediately — rejected, never degraded to a generic card.
    2. Call `SetGroupId` on the injected `IActiveGroupContext` with the group id the signature yielded. Call it through the injected abstraction; never resolve a concrete context type from the container. This sets an in-memory override for this request only. It must not be persisted anywhere that outlives the request — doing so would convert a metadata token into board access for the rest of that visitor's session.
    3. Read the quest with the quest service's single-record read by id. Do not weaken, disable, or work around the global query filter in any way; the whole point of step 2 is that the filter can do its job unchanged. This application has shipped two real cross-board leaks and the filter is the remedy.
    4. If the quest is null, return `NotFound()`. Null covers both "deleted" and "belongs to a different board than the signature claims".
    5. Build the view model. Resolve the request origin once as the current scheme and host joined by "://" and pass it to the URL builder as the fallback argument. `CanonicalUrl` is the absolute URL of the real quest page at the conventional `/Quest/Details/{id}` path — not the signed URL, because the signed URL is a bearer link and the quest page is the canonical resource. `ImageUrl` is the absolute URL of the shared branded card image under the static images path. `Title` is the quest title. `Description` is the description builder's output over the quest description, with a private const fallback string of exactly: No description yet — open the link to see the full quest. `SiteName` is the private const D&D Quest Board.
    6. Return `View("QuestCard", model)`.

    Nothing in this action reads any request header other than the host, and nothing branches on device or client type. Every caller gets the same result for the same token.

    In `GroupSessionMiddleware`, add the literal "/s" to `ExemptPathPrefixes` and extend the comment above the array to name it alongside the other literal entries. Explain in plain language why: this route establishes its own group scope from a verified token, and it must return an identical response to every caller — an authenticated visitor whose session happens to hold no active group would otherwise be bounced to the group picker instead of receiving the card. Note that the prefix match is segment-aware, so it matches the preview route and nothing else that begins with the same letter.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous internet caller → preview route | An arbitrary token from anywhere reaches an endpoint that requires no login |
| verified signature → group scoping | The signature's group id becomes the scope for a database read; this is the tenant-isolation boundary |
| preview interstitial → quest page | A human forwarded onward crosses from an anonymous surface to an authenticated one |
