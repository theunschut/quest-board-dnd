Rename the board-scoped availability surface to **Board Availability** on both layouts, give it the
subtitle that answers "which board, and events or quests", gate its cross-link button to Dungeon
Masters, and add the one shared CSS rule both this page and My Agenda need for that subtitle.

nor which board. The subtitle carries the secondary events-versus-quests fix for free (D-03).

`.header-subtitle` rule, and a controller comment that stops a future reader from bolting an
authorization policy onto an intentionally open page.
</objective>

  <action>
Insert one new CSS rule immediately after the `.modern-card-header h1, h2, ...` block that ends on line 40 of `QuestBoard.Service/wwwroot/css/modern-card.css`.

Selector: `.header-subtitle` — written unscoped, starting at column 1.

**Deviation from the UI-SPEC's drafted selector, and why it is required.** The UI-SPEC Color section drafts the selector as a descendant of the card header. That works on desktop, where both subtitles sit inside a `card-header modern-card-header` element. It does NOT work on mobile: `Views/Events/Index.Mobile.cshtml` and `Views/Agenda/Index.Mobile.cshtml` render their headings inside a plain `container-fluid px-2 mt-2` wrapper with no card-header ancestor anywhere on the page, so a descendant-scoped selector would leave both mobile subtitles completely unstyled while the desktop pair looked correct — a silent half-shipped rule of exactly the desktop/mobile-drift kind this phase is guarding against. Writing the selector unscoped satisfies the UI-SPEC's own stated intent ("a shared, generic rule — not scoped to Events or Agenda specifically") and still inherits the card header's `color: #1a1a1a` and text-shadow when it does sit inside one, because the rule declares no `color` of its own.

Declarations — exactly these five, exactly these values, no others: `display: block;`, `margin-top: 0.25rem;`, `font-size: 0.8125rem;`, `font-weight: 400;`, `opacity: 0.75;`.

Do NOT add a `color` declaration and do NOT reach for Bootstrap's muted-text utility class — per D-03's UI-SPEC rationale, that grey was never tuned against this app's glass-surface header and this codebase has already had to fix one contrast defect from that exact assumption. Dimming the inherited colour via `opacity` is the decision.

Precede the rule with a one-line plain-language CSS comment explaining that it is shared by every page-header secondary line and is deliberately unscoped so it also applies where the header is not a card header. Per `CLAUDE.md`, that comment must not name a phase number, a plan number or a decision ID.
  </action>
