<objective>
Move the board-scoped grid's navigation entry out of the Calendar surface and into the Dungeon
Master menu on **both** layouts, collapse the now-single-item desktop Calendar dropdown back to a
plain link, and replace the four role-blind presence cases in `LayoutNavigationTests` with the
role-flip set that actually proves the move happened.

Purpose: this is the phase's highest-risk change. This codebase has shipped a nav entry on desktop
but not mobile before, and has gated an entry to the wrong board type and made a surface
unreachable; `LayoutNavigationTests` asserts on strings rather than markup structure, so a move can
pass the existing suite while leaving the entry unreachable in practice. The answer is the flip —
the entry's old site was role-blind, so present-for-DM plus absent-for-player can only mean it is
inside the DM block.
Output: one atomic navigation move across both layouts, and twelve executed test cases that fail
loudly if it half-lands.
</objective>
