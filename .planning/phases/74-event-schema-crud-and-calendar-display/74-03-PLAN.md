## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| controller → domain service | Everything the controller can reach must already be group-scoped; a repository method that bypasses the query filter would move the boundary without anyone noticing. |
| domain model → entity (AutoMapper) | A model-onto-entity map can overwrite fields the caller never intended to change, including `GroupId`. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-74-03 | Information Disclosure | `EventRepository` reads | high | mitigate | Every read goes through `DbContext.Events` / `DbContext.EventSeries` with the fail-closed query filter applied and no manual group condition and no `IgnoreQueryFilters()`. Both are asserted by grep in the acceptance criteria. |
| T-74-01 | Tampering / Elevation of Privilege | `GetSeriesGroupIdAsync` | high | mitigate | Provides the controller with the owning board of a repeating-schedule row so a write can be rejected before save. | T-74-14 | Tampering | `CreateMap<Event, EventEntity>` | medium | mitigate | `BaseRepository.UpdateAsync` maps the model onto a tracked entity. `Group` and `Series` are ignored so a loaded navigation is never nulled; `GroupId` is re-stamped from the active group by the controller (plan 74-04) rather than trusted from the posted model. |
