<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored Markdown → rendered HTML | An event description is author-supplied text rendered into every viewer's page. |
| view-rendered control → server action | A visible button implies a permission; a view that renders a control the server would reject is a usability bug, and a view whose visibility check is mistaken for the security check is a vulnerability. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-74-04 | Tampering | event description rendering in `Views/Events/Details.cshtml` | medium | mitigate | Rendering goes through `Html.Markdown`, the single sanitized render path already trusted for quest descriptions. The view never touches the markdown service or `Html.Raw` directly, and the acceptance criteria assert exactly one `Html.Markdown` call and no second rendering route. |
| T-74-02 | Elevation of Privilege | Actions card on the details view | high | mitigate | `Model.CanManage` only decides whether the buttons are drawn. The server-side policy attribute on Edit and Delete is the real boundary, and a Player POSTing directly is rejected — proven by the Player-blocked facts in plan 74-01. |
| T-74-05 | Tampering | Delete form on the details view | medium | mitigate | The form posts through the standard tag helper, which emits the request verification token that the controller's antiforgery attribute validates. |
| T-74-17 | Tampering | write controls inside the shared calendar partial | high | mitigate | Edit and Delete live only on the details view. `Views/Shared/_Calendar.cshtml` is not modified by this plan at all, so the five out-of-scope quest detail call sites cannot inherit a Dungeon Master control. Asserted by a clean `git status` on that file. |
| T-74-SC | Tampering | package installs | low | accept | Zero new NuGet packages this phase; `74-RESEARCH.md` § Package Legitimacy Audit records this explicitly. The Markdown editor assets are loaded from the existing shared scripts partial, which already pins subresource integrity hashes. |
</threat_model>
