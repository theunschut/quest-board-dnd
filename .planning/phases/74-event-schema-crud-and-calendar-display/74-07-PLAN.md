<objective>
Make events visible on the mobile calendar page, which today lists only days that have quests.

Purpose: `Views/Calendar/Index.Mobile.cshtml` never calls the shared partial — it hand-rolls its own agenda loop filtered on quests. Events stay completely invisible there until that filter changes, which makes this the seventh touch point the roadmap calls out separately from the six partial call sites. Widening the filter and rewriting the empty state are both required; doing only the first produces a worse state than today.
Output: the mobile agenda view and its stylesheet.
</objective>

| T-74-04 | Tampering | event title inside the agenda entry | medium | mitigate | Razor HTML-encodes the title in the entry body. The navigation target is `Url.Action` over an integer identifier, so no author-supplied text is interpolated into the inline handler. |
| T-74-19 | Information Disclosure | empty-state wording | low | accept | The neutral empty state no longer reveals whether a month is empty of quests specifically. That is a wording change with no security consequence and is accepted as-is. |
| T-74-17 | Elevation of Privilege | write controls in the agenda | high | mitigate | The agenda entry navigates to the details view and contains no form, button or write action; edit and delete stay confined to the details view. |
