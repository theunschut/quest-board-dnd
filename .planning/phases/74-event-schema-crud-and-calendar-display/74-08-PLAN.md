<objective>
Close the remaining validation gaps: the two-group tenant isolation suite the roadmap makes a hard success criterion, the write-side scoping proofs, and the render assertions for desktop, mobile and navbar.

Purpose: the standard integration harness shares a single mutable group context defaulting to group 1, so an ordinary test is structurally blind to the multi-group bug class. This app has shipped two real cross-tenant leaks. A dedicated two-group test is not optional, and neither is its positive counterpart — an absence assertion against a page that failed to render passes for the wrong reason.
Output: one new test file and three extended ones.
</objective>
