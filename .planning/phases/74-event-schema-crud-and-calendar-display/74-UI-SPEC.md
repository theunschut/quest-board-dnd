# Phase 74 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — server-rendered ASP.NET Core MVC / Razor, not a component-registry stack. shadcn gate does not apply (not React/Next.js/Vite). |
| Preset | not applicable |
| Component library | Bootstrap 5.3.0 + Popper (already loaded on both `_Layout.cshtml` and `_Layout.Mobile.cshtml`) |
| Icon library | Font Awesome (`fas fa-*`, `me-2`/`me-1` spacing per CLAUDE.md) |
| Font | Headings: `'Cinzel', serif` (fantasy display face, used via `.cinzel-heading` and `.modern-card` heading rules). Body/UI: Bootstrap's default system stack (no custom body font declared in `site.css`). |

**Existing visual system this phase must match (not invent):** a "glassmorphism fantasy notice-board" theme —
- Page background: fixed parchment/notice-board image (`body::before`), the same on every page.
- `.modern-card` / `.modern-card-header` / `.modern-card-body`: translucent white glass (`rgba(255,255,255,0.15)`, `backdrop-filter: blur(15px)`), 12px border-radius, 1px `rgba(255,255,255,0.3)` border.
- Card header/heading/label text renders in parchment `#F4E4BC` with a heavy dark text-shadow stack (`2px 2px 4px rgba(0,0,0,0.9), -1px -1px 2px rgba(0,0,0,0.9), 1px 1px 6px rgba(0,0,0,0.8)`) so it reads over the glass. Card body copy renders dark (`#1a1a1a`) on the near-transparent body background.
- This phase's Create/Edit/Details views (Events CRUD) MUST use `.modern-card`/`.modern-card-header`/`.modern-card-body` verbatim per CLAUDE.md — do not invent a new card shell.
- The calendar day-cell chip system (`.quest-event`, `.calendar-quest-title`, `.legend-item`) is a **separate, deliberately dense micro-typography system** (8–14px) distinct from the card system above — the event chip extends this system, not the card system (see Typography below).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside chips/badges, `.legend-item` internal spacing |
| sm | 8px | `.calendar-day` cell padding, gap between stacked event/quest chips, `mb-2` |
| md | 16px | `.modern-card-body` padding, `mb-3` form-field spacing, default form row gap |
| lg | 24px | `mb-4`, section separation inside a CRUD card |
| xl | 32px | Not natively a Bootstrap spacer class — use inline `style` or a utility only where a section genuinely needs more room than `mb-4`/`gap-4` (48px) gives; do not invent a new class for this phase |
| 2xl | 48px | `mb-5` — page-level card-to-card spacing (matches Contact/Quest CRUD pages) |
| 3xl | 64px | Not used anywhere in this phase's scope |

Exceptions:
- The calendar day-cell system does **not** follow the 8-point scale — it uses sub-8px values (`padding: 2px 4px`, `gap: 1px`) by deliberate design, because a `.quest-event` chip must fit inside a ~112px-tall day cell alongside up to 3 other chips. The new `.event-block`/event chip class must match this existing scale exactly (2px 4px padding, 1px inter-chip gap) rather than the 8-point scale, so events and quests read as one visual system. Do not apply 8px/16px spacing inside the day cell — it will not fit and will reintroduce Pitfall 1 (clipping).
- 44px touch target minimum applies to the mobile month-nav chevrons (`.calendar-nav-btn { min-width: 44px; width: 44px; }`) — already established, reuse as-is for any new icon-only mobile control this phase adds.

## Typography

Two typography systems apply in this phase — declare both.

### System A — CRUD views (Events Create/Edit/Details), inside `.modern-card`

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (Bootstrap default `1rem`) | 500 (`.modern-card p/li/span/small` rule) | 1.5 |
| Label | 16px (`.modern-card .form-label`, Bootstrap default) | 600 | 1.5 |
| Heading (card title, e.g. "Create Event") | 1.5rem / 24px (Bootstrap `h4`, matches `Contacts/Create.cshtml`'s `<h4>`) | 600 | 1.2 |
| Display (page-level `<h2>`, matches `Calendar/Index.cshtml`) | 2rem / 32px (Bootstrap `h2`) | 600 | 1.2 |

### System B — Calendar chip micro-typography (desktop day cell + legend), inside `.calendar-day` / `.legend-card`

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Chip title (`.calendar-event-title`, mirrors `.calendar-quest-title`) | 10px | 600 | 1.2 |
| Chip secondary (time / "All day" label, mirrors `.quest-time`) | 8px | 400 (italic where it mirrors `.calendar-quest-dm`) | 1.2 |
| Day number (`.day-number`, unchanged, for reference) | 14px | 600 | 1.2 |
| Legend label (`<small>` next to `.legend-item`) | Bootstrap `<small>` default (0.875rem / 14px) | 400 | 1.5 |

### System C — Mobile agenda entries (`Index.Mobile.cshtml`)

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Agenda entry title (`.agenda-event-title`, mirrors `.agenda-quest-title`) | 16px (`1rem`) | 700 (bold, matches `fw-bold` on `.agenda-quest-title`) | 1.4 |
| Agenda entry time / "All day" | Bootstrap `<small>` default (14px) | 400 | 1.4 |
| Day section label (`.agenda-day-label`) | `small` + `fw-bold` (14px) | 700 | 1.4, `text-uppercase`, `letter-spacing: 0.08em` |
| Month title (`.calendar-month-title`) | 1.25rem / 20px, `'Cinzel', serif` | 700 | 1.2 |

**Rule for this phase:** do not introduce a third size scale. The event chip/agenda entry must reuse System B/C's exact px values (10px/8px desktop, 16px/14px mobile) — these are already unusually small because of the fixed cell/card constraints, and mixing in 8-point-scale sizes (e.g. a 12px or 13px chip label) will look like a rendering bug next to the quest chips it sits beside.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Fixed notice-board background image + `.modern-card-body`'s near-transparent surface (`#1a1a1a` text on transparent) | Page background, card body text color |
| Secondary (30%) | `rgba(255,255,255,0.15)` glass (`.modern-card`), `rgba(255,255,255,0.05)` glass (`.modern-card-header`) | Card surfaces, header bars, legend card |
| Accent (10%) | `#ffc107` (Bootstrap `warning` gold) | **Reserved for:** primary CTA buttons only (`btn-warning` — "Create Event", "Save Event", matches `Contacts/Create.cshtml`'s "Create Contact" button and the quest-proposed calendar color); the event chip's identifying border-left color (see below); focus-ring accents already defined globally (`.form-control:focus`) |
| Destructive | `#dc3545` (Bootstrap `danger`, default `btn-danger`) | Delete Event button only, on the event details view (D-11) |

**Event vs. Quest color contract (EVENT-03's "distinguishable at a glance"):**
- Quest chips already use `border-left-color: #ffc107` (proposed, amber/gold) or `#28a745` (finalized, green) — both colors are claimed.
- The event chip MUST use a **third, unclaimed color** for its `border-left`, and MUST also be visually separated by **position** (D-08: its own block above `.quest-events`, not interleaved) so the distinction is never colour-only (accessibility: colour-blind DMs/players must still tell them apart by position and by the block having its own icon).
- **Assign `#6f42c1` (Bootstrap `purple`/`indigo` — not used anywhere else in `calendar.css`) as the event chip's `border-left-color` and the `.legend-item.event` swatch color.** This keeps every existing quest color meaning untouched and gives events a color no other calendar element currently owns.
- Event chip background matches the existing quest chip convention: `rgba(255, 255, 255, 0.9)` (desktop), `#343a40` dark surface with the purple `border-left` (mobile agenda, matching `.agenda-quest-entry`'s shape).
- Prefix every event chip and every agenda entry with a Font Awesome icon (`fas fa-star` or `fas fa-calendar-day` — planner's discretion, but it must be a different glyph from quests, which use none today) so the distinction survives at a glance even before color registers.

Accent reserved for: primary CTA buttons (`btn-warning`) on Create/Edit Event forms and the navbar "Create Event" link hover state (inherited from existing `.dropdown-item` styling, no new rule needed) — never used as a generic "interactive element" color elsewhere in this phase.

## Component Contract

This section is the load-bearing part of this phase's UI-SPEC — it turns CONTEXT.md's D-08 through D-20 into concrete, checkable markup/CSS decisions.

### Desktop calendar day-cell (D-08, D-09, D-10)

- **New CSS classes:** `.calendar-events` (container, mirrors `.quest-events`), `.calendar-event` (chip, mirrors `.quest-event`), `.calendar-event-title`, `.calendar-event-time`.
- **Structure inside `.calendar-day`:** `.calendar-events` block renders **first**, immediately after `.day-number`, **above** `.quest-events`. Both blocks are siblings inside the same flex-column `.calendar-day`.
- **Row-height fix (Pitfall 1 — mandatory, not optional):** change `.calendar-body { grid-auto-rows: 120px }` to `.calendar-body { grid-auto-rows: minmax(120px, auto) }`. Do not leave `overflow: hidden` on `.calendar-day` untouched without verifying a day with 1 event + 3 quests renders uncropped — this is an explicit acceptance check, not a nice-to-have.
- **Per-day cap:** events get their own `Take(3)` cap (planner's discretion per CONTEXT, but 3 is the recommended default to match quests' existing cap and keep cell height predictable now that it can grow via `minmax`).
- **Clickability:** the whole `.calendar-event` chip is a link/clickable target to the event details view (`EventsController.Details`), exactly matching `.quest-event`'s `.quest-link` wrapper pattern — not just the title text.
- **No inline DM controls** (no pencil/trash icon) inside the chip — D-11 confines Edit/Delete to the details view only.

### Legend card (D-12)

- Add a fourth `<div class="d-flex align-items-center mb-2">` row between "Finalized" and "No building key", using a `.legend-item.event` swatch (purple `border-left-color: #6f42c1`, same 20x12px shape as the existing two swatches).
- Update the hint text at the bottom from **"Click quests for details"** to **"Click quests or events for details"** — this is the specific existing string in `Views/Calendar/Index.cshtml:62` that becomes false the moment event chips are clickable.

### Event details view (D-10, D-11)

- One shared view, readable by every board member (no role gate on the GET). Follows `Contacts/Details.cshtml`'s structure: `.modern-card` for the event's own info (title, date, "All day" or formatted time, rendered Markdown description via `@Html.Markdown(...)`), and — **only when `Model.CanManage` is true** (any DM on the board, per D-05/D-11, not an owner check) — a separate `.modern-card` "Actions" block with:
  - `btn btn-warning w-100 mb-2` — "Edit Event" (`<i class="fas fa-pen me-2"></i>`)
  - `btn btn-danger w-100` inside a `<form asp-action="Delete" method="post" onsubmit="return confirm('...');">` — "Delete Event" (`<i class="fas fa-trash me-2"></i>`), matching `Contacts/Details.cshtml`'s exact Delete-button structure (D-17).
- No dedicated `.Mobile` variant is required by any decision in CONTEXT.md; per Claude's Discretion, ship **one shared `Details.cshtml`** (no `.Mobile` split) since the content is a simple info card with no platform-specific interaction — reserve the desktop/mobile split for the calendar rendering itself, which already differs structurally.

### Create / Edit Event forms (EVENT-01, EVENT-02, D-06)

- Structural clone of `Contacts/Create.cshtml` / `Contacts/Edit.cshtml`, minus the image-upload column (events have no portrait):
  - `.modern-card` > `.modern-card-header` (icon + "Create Event" / "Edit {Title}") > `.modern-card-body` > `<form>`.
  - Fields, top to bottom: `Title` (required, text input, placeholder `"Enter event title"`), `Date` (required, `type="date"`), `StartTime` (optional, `type="time"`, label "Start Time (optional)"), then `_MarkdownEditor.cshtml` partial for `Description` (optional, `Required = false`, `Placeholder = "What's happening?"`) — reusing the exact partial call shape from `Contacts/Create.cshtml`.
  - `<hr />` immediately before the button row (CLAUDE.md rule).
  - Button row: `d-flex justify-content-between` — `btn btn-secondary` "Cancel" (`<i class="fas fa-times me-2"></i>`) on the left, linking back to the calendar at the event's month if editing, or the current calendar month if creating; `btn btn-warning` primary submit on the right — **"Create Event"** (`<i class="fas fa-plus me-2"></i>`) on Create, **"Save Changes"** (`<i class="fas fa-save me-2"></i>`) on Edit.
  - No `.Mobile` variant required by any locked decision; ship one shared view (same reasoning as Details above) unless the executor finds the date/time native inputs render badly under a real mobile User-Agent, in which case split — verify with the real-UA test harness per D-16, not devtools emulation.

### Mobile agenda (D-13, D-14, D-15, D-16)

- **Filter (line 9 of `Index.Mobile.cshtml`):** `.Where(d => !d.IsEmpty && (d.QuestsOnDay.Any() || d.EventsOnDay.Any()))`.
- **Empty state copy (month-neutral, replaces "No Quests This Month" / "No adventures are planned for {month}"):**
  - Heading: **"Nothing This Month"**
  - Body: **"No quests or events are planned for {month}. Check another month."**
- **Per-day order:** inside `.agenda-day-section`, render `day.EventsOnDay` first, then `day.QuestsOnDay` — matching desktop D-08/D-15.
- **New CSS classes:** `.agenda-event-entry` (mirrors `.agenda-quest-entry` — dark `#343a40` surface, `border-left: 3px solid #6f42c1`), `.agenda-event-title` (mirrors `.agenda-quest-title`, `1rem`/`#F4E4BC`).
- **Time slot:** every event and quest entry that has no start time (`StartTime == null` for events; this already can't happen for quests, which always have a `ProposedDate`) prints **"All day"** in the same right-hand `<small class="text-muted ms-2 flex-shrink-0">` slot that currently prints `HH:mm` — never a blank slot.
- Tap target is the entire `.agenda-event-entry` div (`onclick="window.location.href=...EventsController.Details..."`), matching `.agenda-quest-entry`'s existing `onclick` pattern exactly (not a Razor `<a>` — this codebase's established idiom for full-row-clickable agenda cards).

### Navbar entry (EVENT-06)

- Desktop (`_Layout.cshtml`) and mobile (`_Layout.Mobile.cshtml`) DM dropdown: insert **"Create Event"** as the item immediately after "Create Quest" (both currently the first item in the "Dungeon Master" dropdown), same list, same `<li>`/`<a class="dropdown-item">` shape:
  ```html
  <li>
      <a class="dropdown-item" asp-controller="Events" asp-action="Create">
          <i class="fas fa-calendar-plus me-2"></i>Create Event
      </a>
  </li>
  ```
- **Not gated on `activeBoardType == BoardType.OneShot`** — matches "Create Quest", which has no such gate (unlike "Manage Shop" / "Edit My Profile", which are OneShot-only). This directly encodes EVENT-06's "available to all DM roles."
