# Phase 94 Audit: Events, Series, Calendar and Agenda (area `events`)

Finding IDs are `A-events-nnn`. Screenshots are not committed; every path below is a scratch path under `~/qb-ui-review/phase-94/` (the BEFORE record is `~/qb-ui-review/phase-94/before/{desktop,mobile}/<row>.png`, probe results are in `~/qb-ui-review/phase-94/before/report.json`, extra probes and shots are under `~/qb-ui-review/phase-94/audit/events/`). The report names fixtures by id only and quotes no member name, email or user-entered text.

## Scope

- **Pages (manifest rows):** `Calendar/Index` (+ `Calendar-Index--crowded` state variant), `Agenda/Index`, `Events/Index`, `Events/Create`, `Events/Details`, `Events/Edit`, `Series/Details`.
- **Partials (audited through the pages that render them, findings tagged "shared partial"):** `Shared/_Calendar` (rendered by `Calendar/Index` desktop and by `Quest/Details`), `Shared/_Calendar.Mobile` (rendered only by `Quest/Details.Mobile`, not by the Calendar page, so it was read but not exercised), `Shared/_LinkedDayEntries` (inside `_Calendar`), `Shared/_LinkedAlsoThatDay` (inside `_Calendar.Mobile`), `Events/_AvailabilityCell`, `Events/_AvailabilityCounts`, `Events/_SeriesFormScripts`.
- **Stylesheets:** `calendar.css`, `calendar.mobile.css`, `events-overview.css`, `events-overview.mobile.css`, `agenda.css`, `agenda.mobile.css`.
- **Method:** BEFORE captures from the frozen baseline (port 8001, baseline source `b6770322`), desktop 1440 and mobile Pixel 7 (real mobile User-Agent, `mobileLayout` true on every mobile record), review against the senior-frontend critique checklist (Critic mode), code read of every view and stylesheet above, contrast measured with `tools/contrast.mjs` over B-med, B-99 and B-max, plus live probes against 8001 written under `audit/events/` (`probe1.mjs` chip fonts, keyboard focus, 320 reflow, mobile target sizes; `probe2.mjs` text-spacing, 390 overflow, Create form facts, DM views of Details; `probe3.mjs` overflow culprit; `probe4.mjs` Agenda filter rows and row-link focus ring; `contrast-events.mjs` computed pairs, output `contrast-events.txt`). The twin-less views were reviewed under both User-Agents.
- **Extra captures (not in BEFORE, scratch only):** DM views of `Events/Details` for the single event (id 2) and a series occurrence (id 3) at `audit/events/shots/details-dm-{desktop,mobile}-{2,3}.png`; Create with recurrence on at `audit/events/shots/create-recurring-{desktop,mobile}.png`. Full-page shots taken by these probes show a white band below the first viewport; that is a screenshot artefact of the fixed backdrop, not a finding.
- **Fixtures (ids only):** event 2 (single), series 1 with occurrences 3 and onward, calendar month 2026-11 with entries on 25 days, linked-board entries present on the calendar legend only (the second board of the link set is empty, so `_LinkedDayEntries` and `_LinkedAlsoThatDay` rows were never rendered; their contrast is computed from the stylesheet, not measured on a render).
- **Corrections to the brief's known items:** (1) none of the Events-area views or partials uses `Html.WallClock` or `Html.LocalTime`; every date and time is a plain `ToString` of a date-only or wall-clock value with no zone conversion (`Calendar/Index.Mobile.cshtml:98`, `Events/Index.cshtml:66`, `Events/Details.cshtml:44`, `Series/Details.cshtml:36`), so there is no helper markup to preserve here and the area phase must simply not introduce a conversion. (2) The linked-entry dashed border and inert rule were confirmed in `calendar.css:516-606` (dashed left border, `--static` has no link, tab stop or data attributes) and in `agenda.css:119-177`; they are not findings. (3) The seeded brand-text and footer-text questions belong to the layout audit, not to this area.
