# Phase 94 — UI Design Contract

> Visual and interaction contract for the foundation of the whole-app UI sweep. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **This phase is unusual.** It is the first phase of a multi-phase sweep. Its deliverables are an audit, a signed-off visual direction, the foundation
> (tokens, cascade, shared component classes, five layouts, footers, toasts, self-hosted vendor assets, dead dependencies removed), a rewritten
> `.claude/ui-guidelines.md`, and appended area phases. It does **not** convert individual area views (D-05).
> The final colour shades, the primary-action fill and the Shop theme are chosen by the operator from mockups **during execution** (D-01, D-02, D-03), so this
> contract cannot pre-lock them. It locks everything that can be locked now and states, for every value the sign-off sets, the constraint that value must satisfy.

Sources: `94-CONTEXT.md` (D-01 to D-19, all locked); `ROADMAP.md` Phase 94 section; `.claude/ui-guidelines.md`; `senior-frontend` SKILL (Designer, Builder, Critic modes);
`93-UI-SPEC.md` (format precedent); and measurements taken from the code on 2026-10-30 (`wwwroot/css/*.css`, `wwwroot/images/Notice Board-blank2.jpg`,
`Views/Shared/_Layout*.cshtml`, `_Footer*.cshtml`, `_Toasts.cshtml`, `Areas/Platform/Views/Shared/_Layout.Platform*.cshtml`, every `.cshtml` under `Views/` and `Areas/`).

**Legend used throughout.**
**FIXED**: decided here; the planner and executor implement it as written, and a change needs the operator.
**SIGN-OFF**: the value is set by the operator at direction sign-off; the constraint stated beside it is FIXED and the mockups must already satisfy it.
**DISCRETION**: Claude's Discretion in CONTEXT.md; the choice and its reason are stated.
Rows marked **(measured)** come from the code or the artwork, not from memory.

**Visual cue list (senior-frontend Designer mode).** Reference: a wooden village notice board with notices pinned to it. Cues the identity already carries and every direction
must keep: dark oak planks with visible grain and nails (the backdrop); paper-like, warm, parchment-toned surfaces; heavy brown wood trim (the navbar); gold as the colour of
value and selection (gold pieces, the focus of attention); a serif inscription face for titles (Cinzel); soft contact shadows under raised surfaces. Cues the assets
offer but the app uses lightly today: wax seals, pinned posters (`wwwroot/images/Blanks`, `Ruined Posters`, `Wax Seals`). Gaps against the reference, which the
directions may close: surfaces read as frosted glass rather than paper; no pinned or edge-lit feel; titles and labels over bare wood rely on a light halo instead of a legible tone.

## Cascade Architecture (DISCRETION: the choice, and why it differs from the lean in CONTEXT)

**Decision.** Layered cascade with **tokens as custom properties**, Bootstrap **re-themed through its own CSS variables**, and the legacy page stylesheets left **unlayered** until
their area phase converts them. The foundation is written without `!important` and without colour literals outside `tokens.css`.

```
Layer order (declared once, first stylesheet in every layout):
  @layer vendor, tokens, base, components, pages, utilities;
```

| Layer | Holds | Files |
|-------|-------|-------|
| `vendor` | Bootstrap CSS and Font Awesome CSS, pulled in with `@import url(...) layer(vendor)` | `app.css` (order statement plus the two imports) |
| `tokens` | custom-property declarations only: palette roles, surfaces, type, space, radius, shadow, motion, layout, theme blocks | `tokens.css` |
| `base` | page chrome rules with element and `:root` selectors: backdrop, body, headings, links, focus ring, reduced motion, the `--bs-*` mapping | `base.css` |
| `components` | the shared classes: card, button, form, alert, toast, table, badge, modal, nav, shell | `components.css`, `shell.css`, `shell.mobile.css` (mobile layouts only) |
| `pages` | converted pages' own rules (empty after Phase 94; each area phase fills it) | per-area files |
| `utilities` | the few project helper classes (`.visually-hidden-focusable`, text-halo, `.text-purple`) | `components.css` tail |

**Why this and not only "lean" in CONTEXT.** Three pieces of evidence from the code:

1. **`!important` inverts across layers.** In a layered cascade, for `!important` declarations the *earlier* layer wins, and layered `!important` beats unlayered `!important`.
   Bootstrap loaded into `vendor` (the earliest layer) would therefore beat the 41 legacy `!important` rules that re-colour a Bootstrap `!important` utility, 28 of them
   `.text-muted`, and would make muted text unreadable on every unconverted page. A plain "put Bootstrap in a layer" plan breaks D-08 silently.
   **Rule that resolves it: re-theme Bootstrap by setting its variables, never by out-specifying its selectors.** `.text-muted` reads `--bs-secondary-color`; `.text-danger`
   reads `--bs-danger-rgb`; `.btn-*` read `--bs-btn-*`; `.card` reads `--bs-card-*`; `.form-control` reads `--bs-border-color` and friends. `base` and `components` set
   those variables per surface. No `!important` is needed, and the 41 fights disappear as the variable overrides land (the audit lists each one; the foundation converts them).
2. **Unlayered CSS beats all layered CSS.** Leaving the legacy page sheets unlayered is the safe default for D-08: they keep winning on their own selectors exactly as today, so
   an unconverted page does not change. It also means the foundation can never be beaten by a legacy rule it cannot see, so the foundation retires the *global* legacy rules
   (below) instead of fighting them.
3. **Bootstrap must be layered**, because an unlayered Bootstrap would beat every new layered rule. Font Awesome is layered too for the same reason.

**What the foundation retires from the global legacy files (so no new rule needs `!important`):**

| Legacy rule family | Today | Replacement |
|--------------------|-------|-------------|
| Element-enumerated cream colour (`.modern-card p, li, span, small { color: #F4E4BC !important }`, same for `h1`-`h6`, `.form-label`, `.form-text`, `.table`) | caused real bugs in Phases 67, 80, 91; repaints badges (parchment on `bg-secondary` 3.7:1) | **Surfaces set `color` and descendants inherit.** `.modern-card { color: var(--qb-fg) }`. Anything that must differ (muted, links, danger) is a token-driven class. **This resolves the open "retire the cream rule" item: it goes in Phase 94** |
| Global element colour rules in `site.css` (`p, li, span, small`, `h1`-`h6`, `.card-body`, `div { background: transparent }`, `.container { background: none !important }`) | dark brown plus white halo on bare board (C1) | replaced by `--qb-fg-on-board` inherited from `body`; `div` and `.container` background resets deleted |
| Bootstrap button, form, alert, badge, table, card re-themes in `site.css`, `modern-card.css`, `mobile.css` (the 213) | three buttons palettes (brown, blue in-card, mobile brown), failing labels (C8 to C12) | one set in `components.css` through `--bs-btn-*` and friends |
| Duplicated backdrop (`body::before` in `site.css` and `mobile.css`), duplicated `--card-width` | two copies | one each, in `base.css` and `tokens.css` |

**D-08 guard for the retirement.** Before the cream rule goes, a before/after screenshot of every page in both layouts (mobile under a mobile User-Agent, D-15) is reviewed; a page is
acceptable if text is readable, no control is hidden or unreachable, and the suite is green. Pixel parity is not required. No compatibility class aliases are built (D-08).

**What stays legacy until its area phase (FIXED):** every page-specific class (quest board, calendar grid, shop, characters, contacts, DM profile, markdown editor and content,
image crop, move entry, agenda, events overview) and every `*.mobile.css` page sheet. They stay unlayered, in their files, still linked from the same places. The remainder of
`site.css` after extraction is renamed `legacy-pages.css` in the commit that extracts the globals, so a reader sees what is left; it shrinks to nothing across the sweep.

**Per-page stylesheet loading (DISCRETION).** Add `@await RenderSectionAsync("Styles", required: false)` to the desktop `_Layout.cshtml` and to `_Layout.Platform.cshtml` (the
mobile layouts already render it). The 14 global links stay in the desktop layout during the sweep; when an area phase converts the last view that needs a sheet, that phase
moves the sheet out of the global list into `@section Styles` of the views that use it (or into the area's `pages` file). At the end of the sweep the global list is empty.
Reason: removing the global links in Phase 94 would touch every desktop view, which D-05 excludes.

**Specificity rules for new CSS (FIXED).**
- One class per selector where possible (specificity 0,1,0); at most one descendant combinator; no ID selectors; no element-qualified class selectors (`div.foo`).
- Use `:where()` for zero-specificity resets and for the mobile touch-target rule so pages can override without a fight.
- No `!important` in any layered file. The only permitted exceptions are inside `@media (prefers-reduced-motion: reduce)` and the `.visually-hidden*` helpers. A guard test pins this.
- No colour literals (hex, `rgb()`, `rgba()`, `hsl()`) in layered files other than `tokens.css`; derive tints with `color-mix(in srgb, var(--qb-x) 40%, transparent)`.
- Two of the existing device-targeting conventions stay: mobile twins carry **no `@media`** (the layout, chosen by User-Agent, decides); shared and twin-less pages
  (`Events/Create`, `Events/Details`, `Events/Edit`, `Series/Details`, `Admin/EmailStats`, `Shared/AccessDenied`) may use `@media (max-width: 767.98px)` in the `pages` layer.

**Risk named.** Moving Bootstrap into a layer changes outcomes wherever a legacy rule *lost* to Bootstrap on specificity and now wins by being unlayered. The full-page screenshot
sweep above is the control. The audit lists any page where this appears.

## Spacing Scale

Declared values (multiples of 4), exposed as tokens `--qb-space-xs` to `--qb-space-3xl`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | icon gap in badges, inline padding |
| sm | 8px | compact element spacing, gap between switch or list rows, control inner padding (block axis) |
| md | 16px | default element spacing, card padding on mobile, gap between form groups |
| lg | 24px | card body padding on desktop, section padding |
| xl | 32px | gaps between cards in a grid, layout gaps |
| 2xl | 48px | major section breaks |
| 3xl | 64px | page-level spacing (top of an empty state, hero) |

Mapping to Bootstrap utilities (FIXED): `0`=0, `1`=4, `2`=8, `3`=16, `4`=24, `5`=48 (Bootstrap's own scale). 32 and 64 have no Bootstrap utility; they are used from the tokens in
CSS only. New markup does not use arbitrary inline spacing.

Exceptions (FIXED):
- **Navbar height** `--qb-nav-h: 56px` (existing, a multiple of 4). Not on the 4 to 64 scale because it is chrome, not content spacing.
- **Touch targets**: every interactive element is at least `--qb-hit-min: 44px` tall and wide **on the mobile layout** (D-16); at least 24px by 24px on desktop (WCAG 2.5.8). Targets
  smaller than that get their hit area enlarged with padding or a `::after`, not their visible size. Known accepted deviation: the EasyMDE toolbar buttons on mobile (Phase 67).
- Legacy off-scale values (12px paddings, `0.75rem`, `1.5rem` mixes, 6px) are not carried into the foundation; they round to the nearest scale step.

### Width and geometry exceptions (FIXED; not part of the spacing scale)

These are fixed widths and ring geometry, not spacing. They are declared separately so the 4-to-64 spacing scale stays a pure multiple-of-4 scale. Every value is an explicit px
number, and every width is a multiple of 4.

| Token | Value | Reason |
|-------|-------|--------|
| `--card-width` | 352px | the quest-card width. Today's 350px rounded to the 4px grid |
| `--card-width-tablet` | 312px | today 311.5px (350 x 0.89), rounded to the grid |
| `--card-width-mobile` | 276px | today 276.5px (350 x 0.79), rounded to the grid |
| `--card-width-small` | 248px | today 248.5px (350 x 0.71), rounded to the grid |
| `--qb-focus-width` | 2px | the stroke of each of the two focus-ring bands (A-2). Ring geometry |
| `--qb-focus-offset` | 2px | the gap between the element and the inner band (A-2). Ring geometry, not the `xs` spacing step |

Why the card widths move: a fixed card width is a component dimension chosen for how many cards fit a row, not a gap between things, so it does not belong in a spacing scale.
The multipliers (0.89, 0.79, 0.71) are retired; the four values are written out as numbers. No measurement of the rendered pages argues for keeping the fractional pixel widths:
they are the unrounded result of a calc, not a designed value. The rounding changes a rendered card by 2px or less (352 against 350, 312 against 311.5, 276 against 276.5,
248 against 248.5, at most 0.6%), which stays inside D-08 (pages stay usable, pixel parity not required). The four tokens are defined once in `tokens.css`; the duplicate definitions
in `site.css` (removed in the global extraction) go away. `quests.css` still re-declares the old values and, being unlayered, wins on its own pages until the Quests area phase removes
that duplicate, so quest cards keep their exact current width until they are converted; elsewhere the 2px-or-less change is visible.

## Typography

Four sizes and two weights, both layouts. Sizes are tokens in `rem` so the browser's text-size setting is honoured. **No text anywhere is smaller than 14px**
(today's Bootstrap `.badge` is 12px, `.item-rarity` 12.8px, `.item-stock` 13.6px; all move up to the 14px step).

| Role | Size | Weight | Line height | Where |
|------|------|--------|-------------|-------|
| Body | 16px (`1rem`) | 400 | 1.5 | paragraphs, form controls (16px also prevents iOS focus zoom), table cells, nav links |
| Label | 14px (`.875rem`) | 400, or 600 for labels, badges and table headers | 1.5 | field labels, hints, helper text, badges, meta lines, dates in dense lists, footer |
| Heading | 20px (`1.25rem`) | 600 | 1.2 | card titles, section headings, modal titles, mobile page titles |
| Display | 28px (`1.75rem`) | 600, Cinzel | 1.2 | desktop page title in the card header |

Rules (FIXED):
- **Mobile uses three sizes** (14 / 16 / 20): page title 20px Cinzel 600, section heading 16px 600 in the body face, body 16, label 14. The 28px step is desktop only.
- **Weights are exactly 400 and 600.** `b` and `strong` map to 600; `fw-bold` (700) and `bold` are not used in new code; today's 500 and 700 collapse into these two. Cinzel is
  loaded across its variable weight axis (400 to 700) but only 600 is used for display text.
- **Cinzel is for display only**: page titles, the brand, the Shop hero. Never for body, labels, dates, numbers in tables, buttons or form controls. Signed off at G1 (S11): the 20px notice titles on the desktop Quest board are also Cinzel (Direction A's departure, accepted); shown again in the Quests-phase poster redraw.
- **The navbar brand sits on the 20px Heading step** (`--qb-text-lg`, Cinzel 600, line height 1.2), on both the desktop and the mobile layout. There is no fifth size. Why 20px and not 28px:
  the bar is 56px tall (`--qb-nav-h`); a 28px line is about 34px, which leaves under 12px above and below and crowds the toggler and the user menu, while a 20px line is 24px and leaves
  16px each side, on the 4px grid. Why 20px and not today's 24px: 24px is not a step in the scale, and the shorter brand text also gives the desktop bar more room at 992 to 1200px, where
  the audit measures item wrapping. This lowers the brand from 24px to 20px on every page; it is a shell change made after direction sign-off, and S11 can veto it. The brand keeps
  its gold hover (reserved use 3).
- Prose blocks (quest descriptions, markdown content) cap at `72ch` on desktop.
- **Bootstrap's heading defaults are mapped onto the scale** (FIXED), in the `base` layer through Bootstrap's own variables: `--bs-headings-font-weight: 600`; `h1`/`.h1` takes the Display step (28px desktop, 20px mobile), `h2`/`.h2` and `h3`/`.h3` the Heading step (20px), `h4` to `h6` and `.h4` to `.h6` the Body step (16px, weight 600). Bootstrap's own sizes (40px down to 16px, weight 500) would otherwise add sizes and a third weight to every unconverted heading. Its responsive `h1` to `h4` `calc()` sizes are overridden by the same rules.
- **SIGN-OFF:** whether a direction lengthens the display step or adds letter-spacing to Cinzel titles. Constraint: still at most four sizes and two weights; the brand stays on the 20px Heading step.

Self-hosted font files (FIXED): `wwwroot/lib/cinzel/` holds a latin and a latin-ext variable `woff2` plus `OFL.txt`; `@font-face` declares `font-display: swap` and `unicode-range`;
the latin file is preloaded from each layout; the fallback stack is `'Cinzel', 'Trajan Pro', Georgia, 'Times New Roman', serif`. Latin-ext is included because user-entered quest titles
and names with diacritics appear in display headings.

## Assumptions

None of A1 and A3 to A11 changes a locked decision. **A2 is different: it is an explicit departure from today's behaviour**, and the operator approved it on 2026-10-30 (recorded as S13).
No operator was available during the research itself; A1 and A2 were put to the operator afterwards and both approved on 2026-10-30. Each other assumption is conservative and the operator may veto it.

1. **A1, pre-sign-off changes (approved by the operator, 2026-10-30).** D-01 says no production view or stylesheet changes before sign-off. Vendor self-hosting, dead-dependency removal and empty layer scaffolding do not alter appearance, so they may proceed before sign-off, but only on a zero-visible-difference screenshot check. Any visible difference blocks the change until sign-off.
2. **A2, DEPARTURE approved by the operator (2026-10-30): error and warning toasts persist.** Today they carry no `data-bs-autohide`, so Bootstrap's default hides them after 5 seconds, which is too short for a message the user must act on (WCAG 2.2.1 and 3.3.1 intent). They now persist until dismissed: `data-bs-autohide="false"` is added to those two toast types, and A-9 pins it. Success, info and gold toasts keep their auto-hide delays.
3. **A3, the cream rule goes in Phase 94.** CONTEXT left this open. The surface-inheritance model needs it gone, because an element-enumerated `!important` rule defeats inheritance; keeping it would force every new component to fight it. D-08 is protected by the full before/after sweep.
4. **A4, no `data-theme` until the Shop decision.** The `data-theme` hook on `<body>` is added only if S9 picks variant (a).
5. **A5, the minimum text size is 14px.** Badges, rarity tags and stock lines move up from 12 to 13.6px. This is denser to lay out; the crowded mockup states exist to show it.
6. **A6, hover lift is opt-in.** The static `.modern-card:hover` lift is removed; only a card that is itself clickable (`.modern-card--interactive`) lifts. A moving non-interactive card is a false affordance and moves content under the pointer.
7. **A7, `@media` is allowed only in twin-less and shared views.** This keeps the project rule that mobile twins use no `@media`, while letting `AccessDenied`, `EmailStats`, the GroupPicker and the four no-twin views be responsive.
8. **A8, GroupPicker keeps no footer.** Whether it is deliberate is an audit question.
9. **A9, versions.** Bootstrap 5.3.8 and Font Awesome 6.7.2 are the best-known latest; the executor confirms with the package registry at execution.
10. **A10, `rgba()` literals.** Because `color-mix()` needs a base colour in a token, tints are derived from tokens; if a needed tint cannot be derived cleanly, it becomes its own token, still inside `tokens.css`.
11. **A11, Bootstrap utilities keep working.** `d-flex`, `mb-3`, `text-center` and the rest stay in markup; the layered cascade does not remove them, and they stay the way new markup spaces and aligns things.
