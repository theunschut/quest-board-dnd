<objective>
Close the structural reason the phase's blocking gap shipped unnoticed, and repair the two
test groups the code review showed cannot fail.

No test in this phase renders the mobile availability overview. Every request in the two
overview test classes uses the default client user agent, which selects the desktop view, so a
ninety-six line view with its own stylesheet, legend, card list and collapse markup has zero
rendering coverage — which is exactly why a missing paging control passed a green suite of 953
tests. The navigation test class already owns the mechanism for issuing a request under a
mobile user agent; this plan brings it to the page.

Separately, the two tests named for the page-size clamp seed five events and assert an upper
bound of one hundred, so deleting the clamp outright keeps both green, and the three-figure
count test asserts substrings the always-rendered legend also produces, so none of the three
numbers the page exists to compute is verified end to end.

Purpose: make the mobile surface and the page-size ceiling defended by tests that can fail.
Output: mobile-user-agent facts, clamp and count facts with real assertions, and a requirements
ledger that matches reality.
</objective>
