# Phase 77 — UI Design Contract

> Visual and interaction contract for the Availability Overview page. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Stack note:** This is an existing ASP.NET Core 10 MVC + Razor + Bootstrap 5.3.0 codebase. There is no component registry, no shadcn, no React. Every class named below is either a stock Bootstrap 5.3 utility already loaded in this app, or a small custom class added to `wwwroot/css/calendar.css` (desktop) and a new `wwwroot/css/events-overview.css` / `events-overview.mobile.css` pair, following the file-splitting precedent `calendar.css` / `calendar.mobile.css` already uses.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — Bootstrap 5.3.0 + Popper (already loaded on both layouts) |
| Icon library | FontAwesome (`fas` solid set), used throughout the existing app |
| Font | Body text: Bootstrap's default system sans-serif stack (no site-wide override exists). `'Cinzel', serif` is reserved for decorative headings/brand only (navbar brand, shop header, quest-log header) — do not apply it to this page's dense grid or counts; a serif display face on small tabular numbers hurts legibility exactly where D-08 needs a fast scan. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between stacked badge + icon in a cell; gap in the count-summary two-line block |
| sm | 8px | Table cell horizontal padding on member columns; gap between legend swatch and its label |
| md | 16px | `modern-card-body` padding (inherited); gap between mobile card sections |
| lg | 24px | Space between the page header row and the grid/card list |
| xl | 32px | Not used on this page |
| 2xl | 48px | Not used on this page |
| 3xl | 64px | Not used on this page |

**Exception:** the mobile card's "Show players" expand toggle is a `<button>` and must keep a minimum **44×44px** tap target (iOS/Android touch guideline), even though its visual content (chevron + text) is smaller — pad the button to reach 44px height rather than relying on the 8-point scale alone.

## Typography

Exactly 4 sizes, exactly 2 weights, as required.

| Role | Size | Weight | Line Height | Usage on this page |
|------|------|--------|-------------|---------------------|
| Body | 16px | 400 (regular) | 1.5 | Empty-state body copy, legend explanatory copy, mobile card description-adjacent text, roster names |
| Label | 14px | 600 (semibold) | 1.3 | Table `<th>` member-name headers, badge text inside chips, the secondary count line ("3 confirmed · 2 Maybe"), mobile card meta line (date/time) |
| Heading | 20px | 600 (semibold) | 1.2 | `modern-card-header` title text (inherited h4/h2 sizing), the "Attendance" column header, mobile card event title |
| Display | 28px | 600 (semibold) | 1.2 | The page's own `<h2>` title, and the **headline Yes-count number** in each row/card — the one figure D-05 says must read at a glance |

Two weights only: **400** for body prose, **600** for everything that needs to be found quickly (headings, labels, the headline number). Do not introduce a third weight for emphasis — use size (Display vs Label) or color (muted vs solid), not weight, to differentiate.

## Color

This app has no flat 60/30/10 palette — it is a translucent "glass card over a dark background image" theme (`modern-card.css`). The closest honest mapping:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Fixed dark background image (`body::before`) showing through everywhere the glass cards don't cover | Page backdrop — unchanged by this phase |
| Secondary (30%) | `.modern-card` glass surfaces: `rgba(255,255,255,0.15)` card body, `rgba(255,255,255,0.05)` header, cream text `#F4E4BC` on card chrome, `rgba(244,228,188,0.85)` opaque table-cell background | The grid card, the mobile card list, the legend card |
| Accent (10%) | `#6f42c1` ("Event" identity purple — already reserved by `calendar.css`'s `.text-purple` and the event chip's `border-left-color`) | **Reserved for exactly:** the page header icon, the nav entry icons (desktop dropdown item + mobile flat entry), and the legend's introductory icon. Never used as a vote color — vote colors are the existing green/yellow/red semantic set below, which must not be reassigned. |
| Destructive | `#dc3545` (Bootstrap `bg-danger`, already used for `VoteType.No`) | The "No" vote chip only. This page has no destructive actions (see Copywriting) — `bg-danger` here is a semantic vote color, not a delete/cancel affordance. |

**Vote semantics (inherited, unchanged from `Events/Details.cshtml`, do not re-theme):**

| Vote | Background | Text | Icon |
|------|-----------|------|------|
| Yes (confirmed) | `bg-success` (`#198754`) | white | `fa-check` |
| Maybe (confirmed) | `bg-warning` | `text-dark` | `fa-question` |
| No (confirmed) | `bg-danger` (`#dc3545`) | white | `fa-times` |

Accent reserved for: **page header icon, "Calendar" desktop-dropdown's "Availability Overview" item icon, mobile nav's "Availability Overview" item icon, legend header icon.** Nowhere else — specifically never for a vote chip, a button, or a focus ring, matching the existing rule documented next to `.text-purple` in `calendar.css`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Show More Events"** — the only actionable control the page itself owns (see Paging below); the page is read-only otherwise (D-23), so there is no create/submit CTA |
| Empty state heading | **"No Upcoming Events"** |
| Empty state body | **"This board has no upcoming events yet. Once a DM schedules one, it will appear here."** — mirrors the existing calendar mobile empty-state tone ("Nothing This Month") |
| Error state | **"Something went wrong loading the availability overview. Try refreshing the page."** — generic fallback; this page has no user-input error path since it takes no input |
| Destructive confirmation | **Not applicable.** The page is read-only (D-23) — it exposes no delete, cancel, or write action of any kind. Every destructive control for an event (Delete, Cancel Occurrence) lives on `Events/Details.cshtml` and is untouched by this phase. |

**Muted-Yes cell accessible label** (not a visible CTA, but load-bearing copy — screen readers and hover both need it): `title="Yes — counted, but not yet confirmed by this member"` / `aria-label="Yes, unconfirmed default"`.

**Empty-cell accessible label:** `aria-label="No signup for this event"`.

**Cross-link copy (D-21), placed on `Calendar/Index.cshtml` and `Index.Mobile.cshtml`:** a small button/link reading **"Availability Overview"** with the `fa-calendar-check` icon, placed beside the month-navigation control on desktop and just below the month nav row on mobile.

## Component Specifications

### 1. The cell vocabulary — five mutually distinguishable states

All four vote-bearing states render as a Bootstrap `badge`; the fifth (Empty) deliberately does **not**, so a glance separates "no signup exists" from "a signup exists" by shape alone before color is even read.

| # | State | Shape | Fill | Border | Icon | Label text | Font style |
|---|-------|-------|------|--------|------|-------------|------------|
| 1 | Confirmed Yes | pill badge | solid `bg-success` | none | `fa-check` | "Yes" | normal |
| 2 | Confirmed Maybe | pill badge | solid `bg-warning` | none | `fa-question` | "Maybe" | normal |
| 3 | Confirmed No | pill badge | solid `bg-danger` | none | `fa-times` | "No" | normal |
| 4 | Muted Yes (Campaign default, `HasAnswered == false`) | pill badge | `bg-success-subtle` (hollow/pale) | **1px dashed**, `border-success-emphasis` | `fa-clock` (never `fa-check`) | "Yes" | **italic** |
| 5 | Empty (no signup row) | bare text, no pill | none | none | none | "—" (em dash) | normal, `text-muted` / reduced opacity |

Markup:

```html
<!-- Confirmed Yes -->
<span class="badge bg-success"><i class="fas fa-check me-1"></i>Yes</span>

<!-- Confirmed Maybe -->
<span class="badge bg-warning text-dark"><i class="fas fa-question me-1"></i>Maybe</span>

<!-- Confirmed No -->
<span class="badge bg-danger"><i class="fas fa-times me-1"></i>No</span>

<!-- Muted Yes — the D-01/D-02 cell -->
<span class="badge avail-cell-yes-muted"
      title="Yes — counted, but not yet confirmed by this member">
    <i class="fas fa-clock me-1"></i><em>Yes</em>
</span>

<!-- Empty — D-03/D-15 cell -->
<span class="text-muted avail-cell-empty" aria-label="No signup for this event">&mdash;</span>
```

New CSS (`events-overview.css`, and its rules duplicated verbatim into `events-overview.mobile.css` since mobile loads its own stylesheet — the same reason `modern-card.css` had to be split out for `.modern-card` itself):

```css
/* Availability Overview — the D-01/D-02 muted-Yes chip. Bootstrap 5.3's
   "-subtle"/"-emphasis" pair is the accessible-on-purpose variant of the
   success palette (bg-success-subtle #d1e7dd + text/border-success-emphasis
   #0a3622 measure ~10.4:1 contrast, well past the 4.5:1 AA floor for normal
   text) so the hollow fill alone is already legible. The dashed border and
   the fa-clock icon (never fa-check) are the load-bearing non-colour cues:
   both survive greyscale and a colour-blind viewer, which fill alone would not. */
.avail-cell-yes-muted {
    background-color: var(--bs-success-bg-subtle);
    color: var(--bs-success-emphasis-color, var(--bs-success-text-emphasis));
    border: 1px dashed var(--bs-success-emphasis-color, var(--bs-success-text-emphasis)) !important;
}

.avail-cell-yes-muted em {
    font-style: italic;
}

/* Empty cell — deliberately not a badge at all, so its shape alone already
   separates "no signup" from every vote-bearing state before color is read. */
.avail-cell-empty {
    opacity: 0.55;
    font-weight: 400;
}
```

**Contrast evidence (D-02):** `#0a3622` text on `#d1e7dd` background computes to a relative-luminance contrast ratio of **~10.4:1** — well above the WCAG AA 4.5:1 floor for normal text (and past the 7:1 AAA floor). Combined with the dashed border and the distinct `fa-clock` icon, the muted state carries three independent non-colour signals, not one — satisfying D-02's "something non-colour is mandatory" with margin.

**Rejected per D-01/D-02:** a `?` badge overlay (explicitly rejected in CONTEXT — "busiest option, in the densest region of the page"); opacity/fill-weight-only differentiation (explicitly rejected — invisible in greyscale).

### 2. The count format (D-05/D-06/D-07/D-08)

Two-line block, used identically on desktop (in the sticky "Attendance" column) and mobile (leading the card):

```html
<div class="avail-count-summary">
    <span class="avail-count-headline">
        <i class="fas fa-users me-1"></i><strong>5</strong> Yes
    </span>
    <span class="avail-count-detail text-muted">
        (3 confirmed) &middot; 2 Maybe
    </span>
</div>
```

- **Line 1 — Display role (28px/600):** total Yes including untouched Campaign defaults (D-05). This is the number a DM scans the whole page for.
- **Line 2 — Label role (14px/600, muted color):** the confirmed subset in parentheses, then the Maybe count after a middot separator (D-06/D-07). No count folds into another; No is never counted here (it's visible per-cell only, per D-07).
- If the compact two-line form cannot fit all figures without wrapping badly (e.g. very long numbers on an unusually large board), stack a third micro-line rather than truncate any figure — **the format bends, the three counted figures never do** (D-08).
- A per-board denominator ("4 of 6") is explicitly **not** included — deferred in CONTEXT as undecided and wrong on One-Shot boards where there is no fixed membership size (D-13).

```css
.avail-count-summary {
    display: flex;
    flex-direction: column;
    gap: 2px;
}

.avail-count-headline {
    font-size: 1.75rem; /* 28px, Display role */
    font-weight: 600;
    line-height: 1.2;
}

.avail-count-detail {
    font-size: 0.875rem; /* 14px, Label role */
    font-weight: 600;
}
```

### 3. Desktop grid

Standard `.modern-card` + `.table` (existing theming from `modern-card.css` applies automatically — do not re-theme td/th colors).

```html
<div class="card modern-card">
    <div class="card-header modern-card-header">
        <h2 class="mb-0"><i class="fas fa-calendar-check text-purple me-2"></i>Availability Overview</h2>
    </div>
    <div class="card-body modern-card-body p-0">
        <div class="table-responsive">
            <table class="table table-hover mb-0 avail-grid">
                <thead>
                    <tr>
                        <th class="avail-sticky-col avail-col-event">Event</th>
                        <th class="avail-sticky-col avail-col-attendance">Attendance</th>
                        @* member columns, alphabetical order, stable across every row *@
                        <th>Alice</th>
                        <th class="avail-col-self">Bob (you)</th>
                        <th>Carol</th>
                    </tr>
                </thead>
                <tbody>
                    <tr class="avail-row-clickable" onclick="window.location.href='/Events/Details/42'">
                        <td class="avail-sticky-col avail-col-event">
                            <strong>Session 14</strong><br />
                            <small class="text-muted">Sat, Sep 5 &middot; 19:00</small>
                        </td>
                        <td class="avail-sticky-col avail-col-attendance">
                            <!-- count-summary block from section 2 -->
                        </td>
                        <td><!-- cell vocabulary badge --></td>
                        <td class="avail-col-self"><!-- cell vocabulary badge --></td>
                        <td><!-- cell vocabulary badge --></td>
                    </tr>
                </tbody>
            </table>
        </div>
    </div>
</div>
```

- **Events are rows, members are columns (D-25).** Column order is alphabetical by name, matching `GetRosterForEventAsync`'s existing SQL `ORDER BY` — this must be the **same order on every row**, or the grid is meaningless.
- **Two sticky leading columns** ("Event", "Attendance") stay pinned via `position: sticky; left: 0/…` as the member columns scroll horizontally — this is what keeps D-05/D-06's headline number readable even on a wide board, without needing to scroll back to column 1. Sticky background must match the opaque table-cell tint already used by `.modern-card .table td` (`rgba(244,228,188,0.85)`) so scrolled content doesn't show through.
- **Member column minimum width: 90px.** Below the board's member count where columns would compress past a badge's minimum readable width, the `.table-responsive` wrapper scrolls horizontally instead of shrinking columns further.
- **The whole row is the click target (D-24).** `cursor: pointer` on hover (reuses `.table-hover`'s existing highlight) plus an `onclick` navigating to that event's `Events/Details` page — same idiom already used for the calendar's mobile agenda entries (`onclick="window.location.href=...">`), not a new interaction pattern.
- **The viewer's own column gets a subtle highlight** — `rgba(255,255,255,0.08)` background tint on the whole column (header + every cell) — so a player can find themselves in a wide grid without breaking the stable alphabetical order.

```css
.avail-sticky-col {
    position: sticky;
    z-index: 2;
    background-color: rgba(244, 228, 188, 0.85);
}
.avail-col-event { left: 0; min-width: 200px; }
.avail-col-attendance { left: 200px; min-width: 170px; }
.avail-grid th, .avail-grid td { min-width: 90px; text-align: center; }
.avail-grid .avail-col-event, .avail-grid .avail-col-attendance { text-align: left; }
.avail-row-clickable { cursor: pointer; }
.avail-col-self { background-color: rgba(255, 255, 255, 0.08); }
```

- **Counts lead every card (D-18).** The per-member breakdown is collapsed by default behind Bootstrap 5's native `.collapse` + `data-bs-toggle="collapse"` — the exact mechanism already loaded (Bootstrap 5.3 + Popper), no new JS.

- **The toggle button is 44px tall minimum** (padding, not just font-size) per the spacing-scale exception above.
- Card container reuses `.modern-card`-style translucency for visual consistency with the rest of the mobile app (see `.agenda-event-entry` in `calendar.mobile.css` for the closest existing precedent — same rounded, tappable, translucent block idiom).

### 5. Page legend

**Include one** (D-02 explicitly permits, and five cell states plus a two-line count format is enough to warrant a quick reference — but it is a supplement, never the only place the muted-yes distinction is legible).

- **Desktop:** a small `.legend-card` in a right-hand column, same idiom as `Calendar/Index.cshtml`'s existing legend card — one row per state, swatch + label.
- **Mobile:** no room for a side column; render as a collapsed `<details>`/Bootstrap `.collapse` triggered by a small "What do these mean?" link directly under the page header, using the same native collapse mechanism as the per-card roster toggle.

Legend content (5 rows, matching the cell vocabulary table above 1:1):

```

[Yes badge]        Confirmed available
[Maybe badge]      Confirmed maybe
[No badge]         Confirmed not available
[dashed Yes badge] Counted by default — not yet confirmed
[—]                No signup for this event
```

### 7. Paging (D-10)

A **"Show More Events"** button below the grid/card list, styled `btn btn-primary` (filled, per the CLAUDE.md button convention), visible only when more events exist beyond the current window:

```html
<div class="text-center mt-3">
    <a href="@Url.Action("Index", new { take = Model.Take + 20 })" class="btn btn-primary">
        <i class="fas fa-chevron-down me-2"></i>Show More Events
    </a>
</div>
```

- Query-string driven (`?take=N`), not session state — stateless, back-button-safe, and consistent with how the rest of this app avoids session for anything that isn't cross-request UI state (the "show hidden" toggle is the one deliberate exception elsewhere, and it is explicitly not the pattern to copy per Phase 81's own scope notes).
- Grows the existing set rather than replacing it with a numbered page — matches the "reach anything in the runway" intent behind D-10 without introducing pagination-index UI for a page whose event count is bounded by design (D-09).
- **Cancelled occurrences get no on-page acknowledgment** — they are excluded per D-12 and simply do not appear; no "N cancelled hidden" counter is added, keeping the page's only two paging-adjacent numbers (headline attendance figures and the Show More button) uncluttered.
