<objective>
Navigation on this app's clickable rows and cards lives entirely in a click handler on a
non-interactive element — a table row or a plain container with no link target, no tab stop, no
role and no key handler. A keyboard user or an assistive-technology user cannot reach those
destinations at all. The code review noted this on the availability overview and observed that
the design contract knowingly reused the existing agenda-entry idiom, which means the idiom
itself is the defect and it is present in eleven view files.

Nine of the eleven files were never touched by this phase, so this work is deliberately isolated
in its own plan and its own wave: it can be reviewed or reverted on its own without disturbing
the phase's other fixes.

The approach is additive. Each row or card gets one real anchor around its primary text,
pointing at exactly the destination the existing handler already navigates to. The handler stays
as a mouse convenience, so nothing about the current pointer behaviour changes.

Purpose: make every destination that is currently mouse-only reachable by keyboard.
Output: a shared link style, thirteen anchors across eleven views, and a test proving a
focusable link exists on a representative desktop surface and a representative mobile surface.
</objective>
