  <action>
Create both stylesheets. The mobile layout loads its own stylesheet set, so the cell-state and
count rules are duplicated verbatim into the mobile file rather than shared — the same reason
`calendar.css` and `calendar.mobile.css` already exist as a pair.

Shared rules, present in BOTH files and byte-identical between them:

`.avail-cell-yes-muted` — `background-color: var(--bs-success-bg-subtle);`,
`color: var(--bs-success-text-emphasis);`,
`border: 1px dashed var(--bs-success-text-emphasis) !important;`.
Bootstrap 5.3's subtle/emphasis success pair measures about 10.4:1 contrast, well past the
4.5:1 AA floor, so the hollow fill is legible on its own — but fill weight is a difference of
degree and is exactly what a colour-blind or low-contrast reader loses. The dashed border is
one of three non-colour signals (the italic label and the clock icon in the markup are the
other two) and is load-bearing, not decorative.

`.avail-cell-yes-muted em` — `font-style: italic;`.

`.avail-cell-empty` — `opacity: 0.55;`, `font-weight: 400;`. The empty cell is deliberately not
a badge, so its shape already separates "no signup row exists" from every vote-bearing state
before colour is read.

`.avail-count-summary` — `display: flex; flex-direction: column; gap: 2px;`.
`.avail-count-headline` — `font-size: 1.75rem; font-weight: 600; line-height: 1.2;`.
`.avail-count-detail` — `font-size: 0.875rem; font-weight: 600;`.

Desktop-only rules in `events-overview.css`:

`.avail-grid th, .avail-grid td` — `min-width: 90px; text-align: center;`.
`.avail-grid .avail-col-event, .avail-grid .avail-col-attendance` — `text-align: left;`.
`.avail-sticky-col` — `position: sticky; z-index: 2;`.
`.avail-col-event` — `left: 0; min-width: 200px;`.
`.avail-col-attendance` — `left: 200px; min-width: 170px;`.
`.avail-row-clickable` — `cursor: pointer;`.
`.avail-col-self` — a subtle lightening (around `rgba(255, 255, 255, 0.08)`) of the viewer's own
column so a player can find themselves in a wide grid without disturbing alphabetical column
order; apply it to both the header cell and the body cells of that column.

Sticky-column backgrounds: `.modern-card .table th` and `.modern-card .table td` both declare
`background-color` with `!important`, so a sticky column at lower specificity will show scrolled
content through it. Write two separate rules — `.modern-card .table th.avail-sticky-col` using
the header brown `rgba(139, 69, 19, 0.95)` and `.modern-card .table td.avail-sticky-col` using
the body cream `rgba(244, 228, 188, 0.95)` — each with `!important` and each one step more
opaque than the base tint so nothing bleeds through. This makes the UI-SPEC's "sticky background
must match the opaque table-cell tint" specific, because the header and body tints differ.

Mobile-only rules in `events-overview.mobile.css`, in addition to the shared block:

`.avail-card` — a rounded, translucent, tappable block matching the `.agenda-event-entry` idiom
already in `calendar.mobile.css`.
`.avail-card-title` — the event title line at 20px / weight 600.
`.avail-expand-toggle` — `min-height: 44px;` reached through padding rather than font size,
because the roster toggle is a real tap target and 44px is the iOS/Android floor. Do not shrink
it to fit the 4px spacing scale.

Do not restyle any `.badge`, `.bg-success`, `.bg-warning` or `.bg-danger` rule — the vote colours
are inherited unchanged from the event details page and must not be re-themed. Do not hard-code the
events accent purple as a hex value anywhere in these files: the accent is applied through the
existing `.text-purple` class on icons only.

Header comment on each file: one short paragraph in plain language explaining that the
unconfirmed-default chip carries non-colour signals on purpose, and that the two files are a
duplicated pair because the mobile layout loads its own stylesheets. Do not write phase numbers,
requirement ids, or decision ids in these comments.
  </action>
