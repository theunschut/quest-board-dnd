<objective>
Repair the two desktop grid stylesheet defects the code review found, both of which make a
shipped affordance silently absent rather than visibly wrong.

The viewer's own-column highlight never paints: the rule is written at a specificity of one
class with no importance flag, while `modern-card.css` declares header and body cell
backgrounds with importance flags, so the shared rules win unconditionally and only the text
suffix survives. This same stylesheet already documents and solves that exact collision about
twenty lines earlier for the frozen columns, so the fix is to apply the established workaround
consistently.

The second frozen column's left offset is pinned to a value that the first column is only
guaranteed to be *at least*, not exactly. A long event title widens column one past that
floor, and the two frozen columns then overlap as soon as the grid is scrolled sideways —
which on a board with many members is the normal viewing mode.

Purpose: make the "find yourself in a wide grid" and "keep the event and its counts pinned"
affordances actually work on the desktop surface.
Output: one stylesheet, two corrected rule groups.
</objective>

deliberately more specific than these two, so hovering a row still tints the whole row

  <action>
Read the frozen-column rules in `events-overview.css` and the two header cells at the top of
the grid in `Index.cshtml` so it is clear which class lands on which column.

Declare a single custom property `--avail-event-col-width` with the value `200px` on the grid
table class `.avail-grid`, so every cell inside the table inherits it, and then:

- Rewrite the first frozen column's rule to set `left: 0` and all three of `width`,
  `min-width` and `max-width` to `var(--avail-event-col-width)`. A minimum width alone is a
  floor, not a size — table auto-layout is free to widen the column past it, which is exactly
  what happens on a long event title and what pushes the column under its neighbour.
- Add `overflow-wrap: anywhere` to that same rule so a long unbroken title wraps inside the
  declared width instead of forcing the column wider. The event title field allows up to 200
  characters, so this is a reachable case, not a hypothetical.
- Rewrite the second frozen column's rule so its `left` offset is `var(--avail-event-col-width)`
  rather than a repeated literal. Keep its existing minimum width of `170px` — that column
  holds the three-figure count block and is not itself an offset source for anything.

Add a short plain-language comment above the custom property stating that the first frozen
column's width and the second column's offset must stay equal, which is why both read from one
declaration. Do not name a requirement, decision, plan or review-finding identifier.
  </action>
