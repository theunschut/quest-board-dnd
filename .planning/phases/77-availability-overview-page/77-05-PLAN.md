<objective>
Close the phase's one blocking verification gap and the three review warnings that live in the two availability overview views.

The mobile availability overview never reads the paging state the controller already computes, so on a board with more upcoming events than `EventsOverviewOptions.DefaultTake` (10) a mobile member sees exactly ten events with no control to load more and no signal the list is truncated. Mobile views in this app are user-agent-selected, so there is no browser-resize workaround. This plan wires that control, and while both views are open it also fixes the self-referencing paging link at the ceiling, the roster taps that navigate away, the unguarded positional cell dereference, and two cosmetic inconsistencies between the two files.

Purpose: restore EVTVIEW-01 on the mobile surface, which is the surface most board members use.
Output: a paging control on both surfaces gated on real growth, an inert expanded roster, bounded cell indexing on both surfaces, and a mobile legend that is actually styled.
</objective>

In `EventOverviewViewModel`:

- Add a computed, expression-bodied, get-only property `public bool CanShowMore => HasMore && NextTake > Take;`.
  It must have no setter, so the controller's existing object initializer keeps compiling unchanged.
  This is the fix for the paging control that currently renders as a link to the page the
  reader is already on: once `Take` has been clamped up to `EventsOverviewOptions.MaxTake`
  (100 by default), `NextTake` equals `Take` while `HasMore` is still true.
- Rewrite the class-level comment. The current text claims `Take` feeds a Show More control
  and an alignment check, and neither consumer existed. Replace it with a plain-language
  sentence stating that the type carries the shared member axis, one row per event, and the
  three paging values the growth flag is computed from. Add a short comment above
  `CanShowMore` explaining that existence of further events is not by itself enough to offer
  growth, because the window can already sit on its ceiling.

In `QuestBoard.Service/Views/Events/Index.cshtml`:

- Add `@using QuestBoard.Domain.Enums` as the first line of the file, above the existing
  `@using QuestBoard.Service.ViewModels.EventViewModels`, then shorten the five
  fully-qualified enum arguments passed to the `_AvailabilityCell` partial in the legend block
  so they use the short type name, matching how `Index.Mobile.cshtml` already writes them.
- Change the condition on the paging block from the raw has-more flag to `Model.CanShowMore`.
  Leave the block's markup, copy (`Show More Events`), icon (`fas fa-chevron-down me-2`),
  Bootstrap classes and `@Url.Action("Index", new { take = Model.NextTake })` href exactly
  as they are.
- In the per-member loop, stop dereferencing the row's cell collection at the member index
