<objective>
Two defects in the non-presentation half of the availability overview, both of which turn a
configuration or environment difference into wrong or unavailable behaviour.

The domain service decides which events are upcoming from the server's local date, while
cancellation and signup timestamps in the same feature are UTC. Near midnight, or on a
container whose time zone differs from the group's, an event enters or leaves the list hours
early or late. The comment sitting above that read justifies its location by claiming it keeps
the repository pinnable to a known date, and that justification does not hold for the service
itself: the unit test has to recompute the same local date expression to match, which asserts
the implementation rather than the behaviour.

Separately, the page-size clamp uses the configured ceiling as its upper bound with no
validation, and the clamp throws when the ceiling is below the lower bound. Deployment
configuration for this app lives in a server environment file, so a typo there is a realistic
path to every request for this page becoming a server error.

Purpose: make the upcoming-window boundary deterministic and testable, and make a bad ceiling
fail loudly at boot instead of quietly per request.
Output: an injected clock, a named options predicate validated at start, a defensive clamp, a
rewritten boundary test and a new validation test.
</objective>
