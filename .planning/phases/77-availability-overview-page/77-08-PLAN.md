<objective>
The navigation test class carries two defects the code review flagged, both of which are about
the file being trustworthy rather than about behaviour.

Its class documentation comment names requirement identifiers, a decision identifier and a plan
number, and asserts the tests start failing because a feature does not exist yet. The project's
own contributor guidance forbids planning and tracking references in source comments precisely
because they go stale the moment a phase closes — and this one is already stale twice over,
since the gating shipped long ago and the tests are green.

Four theories added by this phase assign the shared board type and never restore it, while a
neighbouring pre-existing test wraps the same mutation in a restore block. Two further tests in
the class do not set the board type at all and inherit whatever ran last. Nothing fails today
because assembly parallelism is off and those two assertions happen to be board-type agnostic,
but the class holds a latent ordering dependency that will surface the first time an assertion
in it becomes board-type sensitive.

Purpose: remove the stale planning references and make every test in the class state its own
premise.
Output: one test file whose documentation is durable and whose shared state is restored.
</objective>
