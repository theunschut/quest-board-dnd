Create `QuestBoard.IntegrationTests/Tests/EventsOverviewTenantIsolationTests.cs` in namespace
`QuestBoard.IntegrationTests.Tests`, copying the class shape of
`EventAvailabilityTenantIsolationTests` exactly:
`public class EventsOverviewTenantIsolationTests(WebApplicationFactoryBase factory) : IClassFixture<WebApplicationFactoryBase>, IAsyncLifetime`,
with `InitializeAsync` returning `ValueTask.CompletedTask` and `DisposeAsync` resetting
`factory.TestGroupContext.ActiveGroupId = 1;` and
`factory.TestGroupContext.BoardType = BoardType.OneShot;`. The reset is not optional: the group
context is a shared singleton and a class that leaves it pointing elsewhere corrupts whichever test
class runs next.

Copy the three private seeding helpers from the sibling file, renaming their seeded users to fresh
prefixes (`evtoviso_*`) so they never collide: one that creates board 2 if absent and adds an event
to it, one that adds an event to board 1, and one that creates a user, their membership row on a
given board, and a signup row for a given event. Extend the signup helper with parameters for the
availability value and for whether the answered marker is stamped, so a test can seed an
unconfirmed default. All seeding goes through `factory.Database.CreateContext()` — never through the
request pipeline, which is pinned to board 1 and could not write board 2's rows even if asked.

Write a class-level doc comment explaining, in plain language, why this file exists separately from
the page's ordinary integration tests: the harness defaults every test to board 1, so an ordinary
test is structurally blind to a cross-board leak on an aggregating read, and this page joins across
events, signups and members — the exact place where a filter bypass gets reached for.

Cases, each starting with `await TestDataHelper.ClearDatabaseAsync(factory.Services);` and setting
`factory.TestGroupContext.ActiveGroupId = 1;` before issuing the request, and each using
`TestContext.Current.CancellationToken` on every awaited call:

1. `Overview_ContainsOnlyActiveBoardEventsAndMembers` — seed a board-1 event titled
   "Group One Overview Session" with a signup for the authenticated board-1 member, and a board-2
   event titled "Group Two Overview Session" with a signup for a board-2 member named
   "Group Two Overview Member". GET `/Events` as the board-1 member. Assert 200; assert the body
   contains "Group One Overview Session"; assert the body does NOT contain
   "Group Two Overview Session" and does NOT contain "Group Two Overview Member". Both halves
   matter — events and members are two separate leak surfaces on this page.

2. `Overview_SameNamedMemberOnAnotherBoard_AppearsOnlyOnce` — seed the board-1 member and a board-2
   member with the identical display name "Shared Overview Name", each holding a signup on their own
   board's upcoming event. GET `/Events` as the board-1 member (default desktop client, so the grid
   renders one header cell per member). Assert the body contains "Shared Overview Name" exactly once
   — count the occurrences rather than using a Contain/NotContain assertion, because with identical
   names a leaked column is invisible to a plain containment check. This is the case that makes the
   test able to detect a leak instead of merely observing an unfamiliar name.

3. `Overview_OtherBoardEventOnSameDate_DoesNotContributeToCounts` — seed a board-1 upcoming event
   with exactly one Yes signup, and a board-2 event on the same date with three Yes signups. GET
   `/Events` as the board-1 member. Assert the body does not contain the board-2 event's title, and
   assert the rendered headline figure for the board-1 row is 1 and that no headline figure of 3
   appears anywhere in the body. The count block renders the headline number inside a `<strong>`
   element inside `avail-count-headline`, so assert against that rendered shape rather than against
   a bare digit, which would match unrelated markup.

4. `Overview_LargeTakeParameter_DoesNotWidenBeyondActiveBoard` — with both boards seeded as in case
   1, GET `/Events?take=100000`. Assert 200 and assert the body still does not contain the board-2
   event title or member name. Widening the page size must not widen the tenant boundary.

5. `Overview_WithNoActiveBoardSelected_ShowsNothingFromEitherBoard` — seed both boards, then set
   `factory.TestGroupContext.ActiveGroupId = null;` inside a `try` and GET `/Events`, restoring
   `ActiveGroupId = 1` in the `finally` the way `EventsControllerIntegrationTests` does. Assert the
   status is not `InternalServerError`, is one of NotFound/Redirect/Found/OK, and that the body
   contains neither board's event title. In practice the session middleware redirects a GET with no
   active group before the action runs; the filters are fail-closed behind it either way, and this
   case pins that a null active board never resolves to "show everything".

Do not add a `[Collection]` attribute or otherwise change the assembly's serial-execution
configuration — `xunit.runner.json` already disables assembly parallelisation. Do not write phase
numbers, requirement ids or decision ids into the source comments.
