repository; persists across sessions, unlike the per-session scratchpad). In node scripts resolve it with

Facts the executor needs (verified in research, adapted to Windows):
- This machine is Windows 11 with Git Bash and PowerShell. `python` and `python3` both resolve to Python 3.14.4
  (Pillow 12.2, numpy, scipy installed); Node 22.16; Microsoft Edge 156/157 installed; Playwright is not installed.
- The committed connection string uses `Trusted_Connection=true`, which works as-is on Windows against a local SQL
  Server. Never edit `appsettings.json`; never run `dotnet user-secrets` for this.
- There is no self-registration route. An admin creates accounts at `/Admin/CreateUser` (Email, Name, GroupRole
  Player/DungeonMaster/Admin; Development suppresses the set-password email) and sets a password at
  `/Admin/ResetPassword/{userId}` (NewPassword). SuperAdmin is an Identity role with no UI; only the operator grants it.
  The Move page and Platform > Group (needed for the Campaign board fixture) are SuperAdmin-only.
- `MobileDetectionMiddleware` matches `Mobi|Android|iPhone|iPad|Windows Phone|BlackBerry`; Playwright's default
  User-Agent matches none, so the phone pass uses `devices['Pixel 7']` (UA, `isMobile`, `hasTouch`). Resizing alone
  renders the desktop views.
- Authenticated pages also need an active board: log in at `/Account/Login`, pick the board at `/groups/pick` through
  its form, then save `storageState`. A state issued by one source tree is rejected by another (the data protection
  key ring is scoped to the content root), so states are per port.
- Never run `npx playwright install msedge`: it replaces the system Edge. If enterprise policy blocks driving the
  installed Edge, the fallback is `PLAYWRIGHT_BROWSERS_PATH=~/qb-ui-review/phase-95/browsers npx playwright-core
  install chromium` (scratch path only), recorded as a deviation.
- The default profile in `launchSettings.json` binds both `https://localhost:8001` and `http://localhost:8000`, which
  would collide with the frozen baseline the next plan starts on 8001. Every launch in this phase therefore uses
  `dotnet run --project QuestBoard.Service --no-launch-profile --urls http://localhost:<port>` with
  `ASPNETCORE_ENVIRONMENT=Development` set explicitly: 8000 is the working tree, 8001 the frozen baseline.
