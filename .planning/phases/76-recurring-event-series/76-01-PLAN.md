Create `QuestBoard.Domain/Services/EventSeriesDateGenerator.cs` in namespace `QuestBoard.Domain.Services`
as a `public static class EventSeriesDateGenerator`. It takes no constructor, no interface, no DI, and
never reads `DateTime.Today`, `DateTime.Now` or `DateTimeOffset` — "today" is always supplied by the
caller downstream. This is deliberate per D-05 and per 76-PATTERNS.md.

Public surface:

- `public const int MaxCycleLength = 100;` — the practical ceiling implied by the `nvarchar(200)` CycleMask
  column when every position is one character plus a comma. Independent of, and stricter than nothing,
  the 24-cell cap the Create form applies in the browser (per 76-UI-SPEC.md) — the browser cap is
  convenience, this constant is the enforcement.
- `public const int MaxSlotScan = 10_000;` — the hard iteration ceiling. `GenerateSlots` never yields
  more than this many slots even when `maxSlots` is larger and no end date bounds it. This exists so a
  user-authored cadence can never drive an unbounded loop in a background job.
- `public static DateOnly DateForSlot(DateOnly anchorDate, int intervalWeeks, int slotIndex)` — the one
  place the slot-to-date arithmetic is written: `anchorDate.AddDays(slotIndex * intervalWeeks * 7)`.
  `GenerateSlots` calls it rather than repeating the expression, and so does the later "has this
  occurrence been moved?" check, so there is exactly one implementation of slot-to-date anywhere.
- `public static IEnumerable<(int SlotIndex, DateOnly Date, bool Fires)> GenerateSlots(DateOnly anchorDate, int intervalWeeks, IReadOnlyList<bool> cycleMask, DateOnly? endDate, int maxSlots)` —
  implements exactly D-01: for slot in `0 .. min(maxSlots, MaxSlotScan) - 1`, the date is
  `anchorDate.AddDays(slot * intervalWeeks * 7)`; if `endDate` has a value and the date is past it, stop
  yielding (`yield break`); otherwise yield the slot index, the date, and `cycleMask[slot % cycleMask.Count]`.
  Every slot is yielded whether or not it fires — the mask decides which dates become events, and the
  slot index counts non-firing steps too, which is what keeps a slot number stable for the life of the
  series. Guard clauses before the loop: throw `ArgumentOutOfRangeException` when `intervalWeeks` is less
  than 1, and `ArgumentException` when `cycleMask` is null or empty. Because the method is an iterator,
  put the guards in a non-iterator wrapper method so they throw at call time rather than at first
  enumeration.
- `public static bool TryParseMask(string? mask, out IReadOnlyList<bool> parsed, out string? error)` —
  splits on `,`, trims each token, and accepts a token only when it is exactly `"0"` or `"1"`. Rejects,
  with a specific `error` message suitable for display in a form validation span: a null/empty/whitespace
  input ("A cycle must have at least one position."), any token that is not `"0"` or `"1"`
  ("A cycle position must be on or off."), a position count above `MaxCycleLength`
  ("A cycle can hold at most 100 positions."), and a mask with no `"1"` at all
  ("A cycle must have at least one session position turned on."). On failure set `parsed` to an empty
  list and return false; never return a partially-parsed mask. The all-zero rejection is load-bearing —
  a mask that never fires would make the top-up loop scan to `MaxSlotScan` on every run forever.
- `public static IReadOnlyList<bool> ParseMask(string? mask)` — calls `TryParseMask` and throws
  `ArgumentException` carrying the returned error when it fails. This is the internal-caller form used
  once a mask has already been validated and persisted.
- `public static string FormatMask(IReadOnlyList<bool> mask)` — renders `"1,1,0,0"` style, no spaces,
  the exact storage form of the `CycleMask` column.

Write XML doc comments explaining *why* the slot index counts non-firing steps and why the generator
takes no clock. Do not write any requirement ID, phase number, decision ID or plan number into any
comment or string literal in this file — that is a hard project rule from CLAUDE.md.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DM browser -> Create Event POST -> mask string | A user-authored cycle mask is persisted as a comma-delimited string and later parsed by a background job |
| Persisted cadence -> background generator loop | A stored anchor/interval/mask drives a loop that runs unattended under Hangfire retry |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-76-01 | Denial of Service | `EventSeriesDateGenerator.GenerateSlots` | high | mitigate | `MaxSlotScan = 10_000` hard iteration ceiling regardless of caller-supplied `maxSlots`, plus rejection of an all-zero mask in `TryParseMask` so no persisted cadence can make a firing-slot search scan forever |
| T-76-02 | Tampering | `EventSeriesDateGenerator.TryParseMask` | medium | mitigate | Strict token allowlist — a position is accepted only when it is exactly `"0"` or `"1"` after trimming; length bounded at `MaxCycleLength = 100`; a failed parse returns an empty list, never a partially-parsed mask |
| T-76-03 | Tampering | `GenerateSlots` interval argument | medium | mitigate | `ArgumentOutOfRangeException` for `intervalWeeks < 1`, thrown eagerly from a non-iterator wrapper so a zero interval cannot produce an infinite same-date sequence |
| T-76-SC | Tampering | npm/pip/cargo installs | high | accept | 76-RESEARCH.md § Package Legitimacy Audit records zero packages installed this phase; no plan in Phase 76 contains a package-install task, so there is nothing for the legitimacy gate to check |
