existing single-event update call succeeds, branch on `viewModel.EditScope`:

- `OnlyThisEvent` (the default, and the only possible value for a one-off event): behave exactly as today,
  including the existing `TempData["Success"] = "Event updated successfully."` wording.
- `ThisAndFutureEvents`: if the event has no `SeriesId`, return `BadRequest()` — a future-scope save is
  meaningless for a one-off event and a posted value that cannot be honoured is a malformed request, not
  something to silently downgrade. Otherwise call
  `eventSeriesService.ApplyTemplateToFutureAsync(existingEvent.SeriesId.Value, id, viewModel.Title, viewModel.Description, viewModel.StartTime, token)`

Note deliberately, in a plain-language comment, that only the title, description and start time propagate:
the edited occurrence's own date is *not* pushed onto its siblings, because moving one session must never
drag the rest of the series with it.

Keep the existing behaviour that the board id is re-derived on every write rather than round-tripped
through the form.

**Add `CheckOccurrenceCollision`**: `[HttpPost] [Authorize(Policy = "DungeonMasterOnly")] [ValidateAntiForgeryToken] public async Task<IActionResult> CheckOccurrenceCollision(int id, DateOnly date, CancellationToken token = default)`.
Load the event and return `NotFound()` when it is null. When it has no `SeriesId`, return `Json` reporting
no collision — a one-off event has no siblings to collide with. Otherwise require
`SeriesIsOnActiveBoardAsync` and return `BadRequest()` on failure, then call
`eventSeriesService.CountLiveSiblingsOnDateAsync(seriesId, date, id, token)` and return `Json` with a
boolean collision flag and the date formatted `d MMMM` for the notice copy. The count deliberately ignores
cancelled siblings — a session that is off is not a double booking — and the result is a notice only: the
move is always allowed, because a double session is legitimate and blocking it would be wrong.

Do not write any requirement ID, phase number, decision ID or plan number into any comment or string
literal.

rule is fixed once a series is created — changing the rhythm means ending the series and starting a new
one — so there is deliberately nowhere on this page to edit it, and the series page shows it read-only.

For a series occurrence:

- Add a hidden input bound to `EditScope` and a hidden input carrying the occurrence's original date, so
  the script can tell whether the date field actually changed.

  every future session in the series?", an `alert-warning` strip that stays hidden unless a collision is

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-76-32 | Tampering | Future scope posted for a one-off event | high | mitigate | The action re-resolves the event's series reference and returns a bad request rather than downgrading silently, so a crafted post cannot reach the sweep path at all |
| T-76-33 | Tampering | Sweep crossing a series or board boundary | high | mitigate | The sweep takes the series id from the server-loaded event, not from the form, and its eligibility set is computed from occurrences read through the fail-closed query filter for that one series |
| T-76-34 | Tampering | Sweep overwriting deliberate per-occurrence decisions | high | mitigate | Eligibility excludes past, cancelled, separately-moved and separately-edited occurrences, and only title, description and start time propagate — never the edited occurrence's date |
| T-76-35 | Elevation of Privilege | Collision endpoint reachable by a non-DM or cross-site | medium | mitigate | DM-only authorization policy plus antiforgery validation, and the series is re-checked against the active board before any count is returned |
| T-76-36 | Information Disclosure | Collision response leaking another board's schedule | high | mitigate | The count is scoped to one series that has already been proven to belong to the active board; a cross-board series id returns a bad request before any count runs |
