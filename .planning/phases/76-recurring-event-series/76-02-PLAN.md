Write a comment above it, in plain language with no tracking references, explaining that this is the
database-level guarantee that two rows can never claim the same slot of the same series; that the
filter keeps one-off events — which carry null in both columns — entirely out of it; and that the

columns in a unique index. Mention that the application-level existence check is not sufficient on its

the top and reproduces exactly the check-then-insert race this index closes.

phase does not need. Do **not** change `FK_Events_EventSeries_SeriesId` to cascade: the delete and

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Background job / concurrent request -> Events table | Two writers can attempt the same series slot simultaneously, or a retried job can re-run a partially-completed pass |
| Any board's request context -> EventSeries table | A series row must never be readable or writable from another board's context |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-76-04 | Tampering | `Events` table, `(SeriesId, SeriesSlotIndex)` | high | mitigate | Filtered unique index `IX_Events_SeriesId_SeriesSlotIndex` declared in `OnModelCreating` and created by the `AddSeriesRecurrence` migration, so a check-then-insert race under the app's global 5-attempt retry policy fails loudly at the database instead of silently duplicating an occurrence |
| T-76-05 | Information Disclosure | `EventSeriesEntity` new template columns | medium | accept | `EventSeriesEntity` already carries a fail-closed group query filter in `QuestBoardContext` (a null active group returns zero rows); the new columns inherit it with no additional surface |
| T-76-06 | Tampering | `EventEntity.CancelledAt` | medium | mitigate | The column is never bound from a form — the domain model exposes `IsCancelled` as get-only and the ViewModel-to-domain map ignores the timestamp (enforced in plan 06); the only writer is a dedicated narrow repository method (plan 03) |
| T-76-07 | Tampering | `FK_Events_EventSeries_SeriesId` | medium | mitigate | Deliberately left at its shipped no-action behaviour so removing a series can never silently take occurrences with it; both removal outcomes are explicit code paths, and the migration is asserted to contain no cascade change |
| T-76-SC | Tampering | npm/pip/cargo installs | high | accept | 76-RESEARCH.md § Package Legitimacy Audit records zero packages installed this phase; no plan in Phase 76 contains a package-install task |
