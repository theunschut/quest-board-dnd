<objective>
Turn the shipped Create Event form into the single entry point for a recurring series: a repeats toggle
that reveals cadence, a clickable cycle-mask strip, an optional end date, and a live server-computed
preview of the next ten dates; plus the controller work that validates the cadence server-side and
creates the series with its whole first generation pass in one transaction.

Purpose: this is EVTRECUR-01 and EVTRECUR-02, and it is the only place a cadence is ever authored — the
rule is immutable after creation, so this form is also the only place it can be got right.
Output: the extended event view model and mapping, the preview endpoint, the series branch on Create,
and the form markup, scripts and styles.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DM browser -> POST /Events/Create | Cadence, mask, interval, end date and every template field arrive from a form |
| DM browser -> POST /Events/PreviewSeries | An unauthenticated-shaped read endpoint that runs a loop over user-supplied parameters |
| Browser-rendered cap -> persisted cycle mask | The 24-cell strip limit is convenience and must not be the only limit |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-76-22 | Tampering | `EventsController.Create` server-side stamps | high | mitigate | `GroupId` is taken from the active group context and never from the form; the view-model-to-domain map ignores `GroupId`, `SeriesId`, `SeriesSlotIndex`, `CreatedAt` and `CancelledAt`, so a crafted post cannot attach an event to another board or forge a cancellation |
| T-76-23 | Input Validation / Denial of Service | Cycle mask and interval posted to Create and PreviewSeries | high | mitigate | Both actions call the Domain mask parser, which allows only `0` and `1` tokens, caps the position count at the schema ceiling, and rejects an all-zero mask; the interval is range-validated on both bound models; the browser's 24-cell cap is explicitly not relied upon |
| T-76-24 | Elevation of Privilege | `PreviewSeries` reachable by a non-DM or cross-site | high | mitigate | The action carries the same DM-only authorization policy as the other write actions plus antiforgery validation, matching the controller's existing convention |
| T-76-25 | Denial of Service | Preview loop driven by a hostile cadence | medium | mitigate | The preview asks for a fixed ten dates and the generator's scan ceiling bounds the walk; the endpoint performs no database work at all, so a flood costs no query load |
| T-76-26 | Repudiation | A half-built series after a mid-save failure | medium | mitigate | Series row and first generation pass share one transaction, so a failure leaves nothing behind and the DM is shown an explicit "nothing was saved" message rather than a success toast |
| T-76-SC | Tampering | npm/pip/cargo installs | high | accept | 76-RESEARCH.md § Package Legitimacy Audit records zero packages installed this phase; no plan in Phase 76 contains a package-install task |
</threat_model>
