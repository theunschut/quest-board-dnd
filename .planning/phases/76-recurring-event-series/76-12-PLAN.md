<objective>
Human verification of the four behaviours this phase's automated suite structurally cannot cover: the
live preview's client-side re-render timing, the cancelled state across three independently-written read
surfaces, the mobile agenda on a real device user agent, and the horizon banner actually surfacing.

Purpose: three of these are the phase's most easily-forgotten failure modes. The cancelled state is
rendered by three separate view files with no shared event-row component, so missing one shows a
cancelled session as live on exactly one surface. The horizon banner's whole reason for existing is that
the failure it reports is silent — a banner that never renders reproduces the very problem it was added
to solve.
Output: developer confirmation, or a list of defects to fix before the phase closes.

  <how-to-verify>
Run the app locally (`dotnet run --project QuestBoard.Service`) on a Campaign board where you hold a
Dungeon Master or Admin role, then work through these five checks in order.

**1. Live preview (EVTRECUR-02)**
1. Go to Create Event. Fill in a title and pick a Saturday as the date.
2. Tick "Make this a recurring series". The cadence section should appear.
3. Confirm the derived line reads "Every 1 week(s) on Saturday" and updates immediately if you change the
   date to another weekday.
4. Set the cycle to four positions with the pattern on-on-off-off using the toggle cells and the plus
   button. Confirm the "Cycle length" label tracks the cell count and that the plus button becomes
   disabled at 24 cells with the tooltip "Maximum cycle length reached."
5. Confirm the preview list re-renders shortly after each change (roughly half a second), showing ten
   dates, and that the pattern matches the strip: two consecutive weeks on, two skipped.
6. Change the date to one several months in the past and confirm the preview explains that the dates shown
   start from today rather than from the anchor.
7. Save. Confirm the toast reads "Series created successfully." and that the dates now on the calendar are
   exactly the ten the preview showed.

**2. Cancelled state on all three surfaces (EVTRECUR-04)**
1. Open one of the generated occurrences from the calendar and choose "Cancel Occurrence". Accept the
   confirm.
2. On that details page: a grey banner reads "This session has been cancelled.", the Yes/Maybe/No buttons
   are gone entirely, and the "Who's Coming" roster is still visible.
3. Go back to the calendar. The chip for that date is still there, faded and struck through — not missing.
4. Check the Legend card now lists "Cancelled" alongside Proposed, Finalized and Event.
5. Open the same occurrence again and choose "Restore Occurrence". Confirm it returns to normal on both
   the details page and the calendar, and that everyone's availability answers survived.

**3. Mobile agenda on a real mobile user agent (EVTRECUR-06)**
1. Cancel an occurrence again.
2. Load the calendar from an actual phone on the same network, or from a browser with a genuine mobile
   user-agent string — not a desktop browser's device-emulation mode, which does not change the user agent
   the server sees and therefore does not select the mobile view at all.
3. Confirm the agenda entry for that date is present, faded and struck through, and still taps through to
   the details page.

**4. Edit scope and collision notice (EVTRECUR-06)**
1. Open a future occurrence and click Edit. Confirm the form shows no cadence, interval or mask fields.
2. Change the title and click Save Changes. A dialog appears titled "Save this change" with two buttons.
3. Choose "Only this event". Confirm only that occurrence's title changed.
4. Repeat on another occurrence and choose "This and all future events". Confirm the toast reads "This
   event and all future sessions in the series were updated.", that future occurrences took the new title,
   that the occurrence you cancelled earlier did NOT, and that no past occurrence changed.
5. Edit a third occurrence and change its date to a date another live occurrence of the same series
   already holds. Confirm the dialog now carries an amber strip naming that date, and that choosing a
   scope still saves — the notice must not block the move.

**5. Horizon banner (EVTRECUR-03)**
1. On the series page for your new series, use "End Series" — or delete enough future occurrences — to
   drop the series below its runway of 20 upcoming sessions.
2. Load the calendar as the DM. Confirm an amber banner appears above the month grid naming the series and
   its remaining count, with a link to the series page.
3. Log in as a player on the same board (or use a non-DM account) and confirm the banner is absent
   entirely — not merely hidden.
4. On the series page, confirm the recurrence rule and template render read-only with no editable field,
   and that "Delete Series" opens a dialog offering both "Delete everything" and "Detach sessions" with
   real session and answer counts in its body.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DM-only information -> a player's rendered page | The horizon banner names series and counts that a player has no action to take on |
| Cancelled state -> three independently written read surfaces | Each surface renders event data separately; a miss on one shows a cancelled session as live |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-76-50 | Information Disclosure | Horizon banner visible to a non-manager | medium | mitigate | Check 5 step 3 loads the calendar as a non-DM account and confirms the banner markup is absent rather than merely styled away |
| T-76-51 | Spoofing | Mobile view verified by device emulation rather than a real user agent | medium | mitigate | Check 3 requires a genuine mobile user agent, because emulation does not change the header the server selects the view from and would prove nothing |
| T-76-52 | Tampering | Scope sweep silently overwriting a deliberately cancelled or moved occurrence | high | mitigate | Check 4 step 4 explicitly verifies the previously cancelled occurrence did not take the swept title and that no past occurrence changed |
| T-76-SC | Tampering | npm/pip/cargo installs | high | accept | 76-RESEARCH.md § Package Legitimacy Audit records zero packages installed this phase; no plan in Phase 76 contains a package-install task |
</threat_model>
