<objective>
Give the repository and service layers the tag read and write path: load tags alongside
contacts without a cartesian blow-up, reconcile a contact's tag list from a submitted set of
names, and prune tag rows the moment their last contact drops them — on contact save and on
contact delete.

The write path is the actual cross-tenant risk in this feature. The board query filter
protects reads; it does not protect a write that attaches an entity obtained without a real
query. Every submitted tag must be resolved through a genuine, board-filtered query so a
foreign-board tag simply comes back missing rather than being silently attached.

Purpose: make tag persistence correct and tenant-safe before any controller or view touches it.
Output: the repository and service methods, plus the unit tests that prove pruning and
case-insensitive reuse against the database rather than against a page.
Decisions implemented: D-04, D-06, D-07, D-16, D-28.
</objective>

   `FirstOrDefaultAsync(c => c.Id == contactId, token)`. A null result means the contact is on

   This is a real query, so the board query filter applies and a foreign-board tag is simply
   absent from the result. Do not resolve tags by primary-key lookup against the change tracker,

   case-insensitivity through the column collation, but the in-memory provider the test suite

5. Replace the contact's `Tags` collection with the resolved set (clear, then add each), and

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| submitted tag name or id -> persisted association | Untrusted form input crosses into an entity association here; this is the write path the board query filter alone does not protect |
| board A contact -> board B tag row | A reconciliation call must never attach a tag from another board, and must never disclose that such a tag exists |
| test provider -> production provider | The in-memory provider does not honour the column collation or the unique index, so correctness must not rest on either during tests |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-81-01 | Elevation of Privilege | `ReplaceContactTagsAsync` write path | high | mitigate | Every tag is resolved from a real board-filtered query over `ContactTags`; no change-tracker primary-key lookup and no manually constructed stub entity is ever attached. | T-81-07 | Denial of Service | Unbounded tag reconciliation | low | accept | A board's tag vocabulary is loaded whole on each save.
