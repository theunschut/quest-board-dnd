<objective>
Add the tag entry field to all four contact create and edit views, wrapping a pinned CDN chips
library with a thin local init module in exactly the shape this codebase already uses for its
image cropper.

The field is a real text input holding a comma-separated list. The library enhances it in
place and writes the same comma format back on every change, so the server keeps parsing one
value shape whether or not the script ran. A DM on a network that blocks the CDN gets a plain
text field that still tags correctly.

Purpose: give a DM a usable way to type tags, without making the feature depend on a script
loading.
Output: the init module, the four view wirings, the scoped theme overrides, and markup tests
covering both platforms and both audiences.
Decisions implemented: D-01, D-14, D-15, D-16, D-22.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party CDN -> browser execution context | An external script executes with full page privileges; a compromised or swapped file would run in a DM's session |
| server-rendered suggestion list -> inline script block | Tag names authored by a DM are emitted into a script context |
| DM-authored tag name -> rendered page | Free-typed text reaches the browser and must not be able to introduce markup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-81-04 | Tampering | CDN-delivered library | high | mitigate | Version-pinned url plus a subresource integrity attribute and a cross-origin attribute on both the script and the stylesheet, matching the existing cropper precedent. Task 1 re-verifies the version and both hashes against the served bytes rather than trusting a recorded value or a third-party listing |
| T-81-04b | Tampering | Silent version drift | medium | mitigate | The version appears in the url in all four views and the acceptance criteria assert the exact string, so a partial upgrade that leaves one view on an old pin fails the gate |
| T-81-02 | Cross-Site Scripting | Suggestion list injection | high | mitigate | The suggestion list is emitted through the framework's own JSON serializer, which escapes for a script context, rather than string-concatenated. The list itself is server-derived from the caller's visible contacts, so it cannot carry another board's names |
| T-81-02b | Cross-Site Scripting | Tag name in the input value | high | mitigate | The input value is written through the standard tag helper binding, which html-encodes it; no raw output helper is used for any tag name in these views |
| T-81-14 | Denial of Service | Unavailable CDN | low | accept | A blocked or failed CDN leaves a plain text input that still submits the correct value shape. This is the designed degradation, verified manually per the phase validation contract |
| T-81-11 | Spoofing | Player reaching the tag field | high | mitigate | Both forms already sit behind the dungeon-master authorization policy; the plan explicitly forbids adding a second parallel audience check, and the tests assert refusal on both user agents |
| T-81-SC | Tampering | npm/pip/cargo installs | high | accept | No package manager runs and no lockfile entry is created — the library is consumed by url. 81-RESEARCH.md's Package Legitimacy Audit records verdict OK for it, and the only remaining trust decision, whether the pinned hash matches the served bytes, is exactly what task 1 re-verifies |
</threat_model>
