<objective>
Render the mobile half of the tag surface: a full-width filter trigger above the contact list, a
bottom drawer of tag checkboxes behind it, chips on each contact row, and a muted tag line on
the mobile details page.

Mobile markup in this app is selected from the request's user agent, not from viewport size.
Markup that was written but never actually served is already on this project's record of
shipped bugs, so every assertion in this plan is made by sending a real mobile user-agent
header — device-toolbar emulation never exercises the middleware that picks the file.

Purpose: ship both platforms in the same phase, with the mobile half genuinely proven.
Output: the mobile styles, both mobile view changes, and a user-agent-driven test class.
Decisions implemented: D-01, D-11, D-17, D-18, D-19, D-20, D-21, D-22, D-24, D-26, D-27.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DM-authored tag name -> rendered mobile html | Free-typed text reaches every mobile viewer and must never become markup |
| DM-tier surface -> player-tier mobile response | A player must receive no tag markup at all on either mobile page |
| user-agent header -> layout selection | The layout under test is chosen by a header the test controls; asserting without it silently tests the wrong file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-81-02 | Information Disclosure | Player-tier mobile responses | high | mitigate | Every mobile tag surface sits inside the single existing audience conditional, and the controller already leaves the tag collections empty for a player. Proved by mobile player tests asserting absence of the class names, the drawer id, and the tag names themselves |
| T-81-02b | Information Disclosure | Drawer vocabulary | high | mitigate | The drawer binds the same viewer-scoped collection the desktop filter row binds; the view adds no second source. Proved by the unrevealed-contact drawer test |
| T-81-15 | Cross-Site Scripting | Tag name rendering on mobile | high | mitigate | Tag names render through ordinary escaped output; the acceptance criteria assert zero raw-output and markdown helpers in the mobile index, and the mobile details markdown count is pinned unchanged |
| T-81-18 | Repudiation | Untested mobile markup | high | mitigate | Every assertion is made under an explicit mobile user-agent header, and the acceptance criteria forbid a bare convenience request in the file. A paired two-user-agent test proves the layouts genuinely differ, which is the failure mode this project has already shipped once |
| T-81-16 | Tampering | Lost filter on the mobile toggle round trip | medium | mitigate | The mobile toggle form carries one hidden input per selected id, asserted by both a markup criterion and a test |
| T-81-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package and adds no external asset; the phase's single CDN dependency was pinned and re-verified in plan 06 |
