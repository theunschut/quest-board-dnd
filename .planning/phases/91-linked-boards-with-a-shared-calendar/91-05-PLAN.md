<assumption_delta_decision>
Primary noun: **board**. The assumption-delta detector's pluralization signal ("a calendar shows one board" → "a calendar shows a set of boards") is resolved as **add-alongside**. The active board stays the primary unit: it keeps the ambient tenant filter, its own entries, its own vote markup and its own rules. The linked set is a separately typed read-only overlay (`LinkedCalendarData`, `LinkedDayEntries`) that is never merged into the own `Quest`/`Event` collections. A **promote** (making the set the unit that owns entries) would be forced by Phase 92 moving entries between linked boards, or by any future write path keyed on the set. The invariant that holds this boundary: with no set, or a set of one, the cross-board reads are never called and no `linked-*` markup renders. `LinkedCalendarServiceTests` and `LinkedBoardCalendarTenantIsolationTests` pin it.
</assumption_delta_decision>
