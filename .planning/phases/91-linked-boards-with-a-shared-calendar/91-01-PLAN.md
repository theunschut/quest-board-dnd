<objective>
Store a named set of same-type boards and give the rest of the phase one repository to read and change it. The schema is one new table plus one nullable column on `Groups` (D-02). The repository creates, renames and deletes sets and assigns boards, over unfiltered tables with tracked writes only. Deleting a board leaves its set alone (D-03), deleting a set un-links its boards, a set with fewer than two boards stays (D-04), and renaming a board keeps its link.

Purpose: every later plan in this phase reads "which boards are linked to the active board" from what this plan stores. The Platform page (Plan 03) enforces the same-type and at-most-one rules on top of this repository (D-01, D-02), and the linked calendar reads (Plan 04) extend it with the per-viewer lookup.
Output: entity + migration, `LinkedBoardSetRepository` with its domain models and interface, and the repository unit tests.
</objective>

1. Schema shape (D-02, locked; reversibility costly): table `LinkedBoardSets` (`Id`, `Name` nvarchar(100) unique, `BoardType` int, `CreatedAt` datetime2) plus nullable `Groups.LinkedBoardSetId` with `ON DELETE SET NULL`. "A board is in at most one set" holds by construction, and D-03 (deleting a board leaves its set) needs no code. CONTEXT.md already locks this, so no decision checkpoint is inserted.
2. The set stores its `BoardType` at creation (Claude's discretion per CONTEXT). An empty set therefore refuses a wrong-type board, and the picker can filter by the set's type. The comparison itself is the service's job in Plan 03 (D-01).
3. `Groups`, `UserGroups` and `LinkedBoardSets` carry no query filter. `LinkedBoardSetRepository` uses no filter bypass and the five-file allowlist does not change. Writes load tracked rows, assign properties, then call `DbSet.Add`/`Remove` and `SaveChangesAsync`. Nothing else is used, because `FeedRevisionWriteSeamTests` bans the other write shapes in all production code.
4. Name uniqueness is checked twice: a case-insensitive service pre-check (`ToUpper()` equality, which translates on SQL Server and works in InMemory), and the unique index for the race. The repository translates `DbUpdateException` into a null or false result, so the Domain layer never references EF types. The service in Plan 03 turns either into a `DuplicateName` outcome.
5. The repository grows across the two tasks: Task 1 declares and implements only what the create-and-assign tracer needs, and Task 2 adds the remaining members test-first. No member is ever declared without an implementation.
6. ⚠ Spec-less probe fallback was skipped because this phase has no requirement IDs to probe. This is a visible, recorded choice. Coverage is the D-01..D-20 decision contract.
