## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> error endpoint | any client may request /Error/{code} directly with any verb and headers |
| failing request -> error page | the original request's path, id and route values are attacker-chosen |
| script callers -> bare statuses | existing JS reads response text into alerts and checks response.ok |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-103-SC | Tampering | npm and NuGet packages | high | mitigate | no package added; framework features only |
| T-103-13 | Information disclosure | a 404 body that differs by id or echoes the path (existence oracle, reflected input) | high | mitigate | the view reads only the model; the model never holds the path, query or route values; facts compare bodies for two ids and search for the id and path |
| T-103-14 | Tampering | a fetch caller receiving HTML into an alert or a JSON parse | medium | mitigate | the gate disables status pages for any request that is not a document navigation; facts for Accept */*, XMLHttpRequest, Sec-Fetch-Dest empty; a live script fetch |
| T-103-15 | Denial of service | the error page erroring on the error path | medium | mitigate | the minimal layout injects nothing and reads no database; the re-execute runs in a fresh scope |
| T-103-16 | Spoofing | /Error/{code} used to show arbitrary status pages | low | accept | the copy is fixed per status, the code is constrained to an int and clamped; the page carries no user input |
</threat_model>
