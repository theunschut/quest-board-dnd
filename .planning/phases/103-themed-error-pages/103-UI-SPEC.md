# Phase 103 - UI Design Contract (delta on Phases 94 and 100)

> Visual and interaction contract for the one shared error page (`Views/Shared/ErrorPage.cshtml` and its `.Mobile.cshtml` twin) and the minimal layout pair it renders in (`_Layout.Error`, `_Layout.Error.Mobile`). It covers the variants 400, 403 (authenticated and anonymous), 404 (with and without Switch board, and anonymous), 409, 429, 500 (with "Reference: <id>") and the generic fallback, on desktop and on the phone layout.
> Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **This file is a delta.** `94-UI-SPEC.md` ("the foundation spec") fixes the tokens, the type scale, the spacing scale, the colour roles, the closed gold list, the accessibility bar (A-1 to A-11), the component classes and the cascade rules. `100-UI-SPEC.md` is the most recent model for how a delta is written and which classes exist. This file **references them by section name and never restates a value they fix.** A number that appears here is a component dimension (declared in "Spacing Scale"), a measurement taken from the Phase 100 computed tables for the same tokens, or a pointer to a token name. If this file and the foundation spec disagree on a shared value, the foundation spec wins and this file has a defect.
>
> **Scope is locked by `103-CONTEXT.md` D-01 to D-19.** The visual and interaction decisions this file leans on are D-02 (one fixed 404 sentence, same body for every viewer and every 404), D-03 (Switch board only for 2+ memberships, 404 only), D-07 (every bodiless 4xx/5xx), D-08 (403 is a variant of this page), D-10 (429 keeps its sentence), D-12 (500 shows "Reference: <TraceIdentifier>" and nothing else from the exception), D-15 (Go back is `history.back()` from a file in `wwwroot/js`, Referer fallback, hidden when there is neither), D-16 (Home is `/`), D-17 (Log out ends on the login page; anonymous viewers get Log in with a local `returnUrl` only), D-18 (phone twin with its own `*.mobile.css`) and D-19 (Gate 1 before any visual build). Where CONTEXT leaves a choice (the exact copy per status, the layout, the Log out mechanism) this file records a **DISCRETION** choice with its reason or a **GATE 1** item with a recommendation and a stated default. **No question was put to the operator while writing this file** (it ran unattended).
>
> **Corrections taken from `103-RESEARCH.md`** and carried here: the view is name-based (`ErrorPage`) so the phone expander finds the twin; the page renders in its own minimal layout pair, not the main `_Layout`; the page's rules live in new `error.css` and `error.mobile.css`, **not** in `components.css` (Phase 100 is editing it); Log out is the existing `Account/Logout` POST form with an optional `toLogin` flag; Go back falls back to a same-site, local-path Referer link; 403 is served with status 403.
>
> **Source-code rule (applies to every row below).** The IDs in this file (D-xx, Gate 1 item numbers, phase and plan numbers) are for this document only. They are never written into a view, stylesheet, script, test string or comment. Comments say why, in plain language that stays true after the phase closes (`CLAUDE.md` section "Code Comments").
>
> **Look rule (D-19).** Nothing visual is built before the operator approves Gate 1: no `error.css`, no `error.mobile.css`, no layout chrome, no `error-actions.js`, no final view markup beyond a structural view that uses only shared classes (research slice order). The server behaviour (pipeline, gate, controller, `Logout(toLogin)`, `OnRejected`) may land first.
>
> **Real-member data rule.** An error page shows no member data. The Gate 1 mockups are drawn from the p103 fixtures (`@example.invalid`, fantasy names) and a made-up reference id; nothing from the real database is captured or published.
>
> **Delivery rule.** The phase ships as a minor release (provisionally v6.6.0, research Open Question 9) through a pull request the operator opens once both gates have passed. Nothing in this contract requires an executor to create a PR, a tag or a release, to push, or to touch `main`.

Sources: `103-CONTEXT.md`; `103-RESEARCH.md` (pipeline, navigation rule, per-status copy table, minimal layout, Log out, Back button, Gate 1 and tooling notes); `.claude/ui-guidelines.md`; `tokens.css`, `components.css`, `shell.css`, `shell.mobile.css`, `group-picker.css`, `account.css` read 2026-11-18; the current `AccessDenied.cshtml`, `_Layout.GroupPicker.cshtml`, `_Layout.Mobile.cshtml`, `GroupPicker/Index.cshtml`; `100-UI-SPEC.md` and `99-UI-SPEC.md` (structure and computed contrast pairs for the same tokens).

Every figure is re-proved on the rendered page by the sweep before Gate 2.

**Visual cue list (senior-frontend, Designer mode).** Reference: a dispatch pinned to the guild-hall notice board, stamped with a seal and a docket number. Cues the foundation already carries and this page must show: a glass card on the oak board (the pinned sheet), a darker title band, a gold Cinzel title on desktop, filled buttons with icons. Cues this page adds, each with one reason: **a round seal** (an opaque dark disc with a fine parchment edge, holding one status glyph) so the page has a focal object instead of a floating icon; **a docket line** ("Error 404", muted, under the title) so the number is present without a display-size numeral; **a stamped reference chip** (an opaque dark chip with the id, selectable in one click) so the 500 gives the member something to quote.
