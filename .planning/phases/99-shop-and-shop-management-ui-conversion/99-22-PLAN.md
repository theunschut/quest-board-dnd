<objective>
Close the authorization gap the operator deferred at Gate 2 (`df:defer`, "worth its own small plan next") and has now
released with "go, fix the draft access first". `ShopController.Details` loads any item of the active board by id and
renders it, as the full page and as the `isModal` dialog fragment, whatever its status. So any signed-in board member
can read an unpublished Draft, or a Denied item, by guessing its id. Shop item ids are sequential integers.

The rule this plan implements (investigated at planning, facts below):

| Status | Who may open Details (page and dialog) | Everyone else |
|---|---|---|
| Published | any signed-in member of the active board (unchanged) | n/a |
| Archived | any signed-in member of the active board (unchanged) | n/a |
| Draft | the `DungeonMasterOnly` policy: a Dungeon Master or Admin of the active board, or a SuperAdmin | 404, identical to a missing id |
| Denied | the same policy as Draft | 404, identical to a missing id |
| any status, another board | nobody through this board (the board query filter already answers 404; a deep link into a board the viewer belongs to switches first, then the rule above applies on that board) | 404 |

Purpose: unreleased and refused shop content stays with the people who review it, and nothing a Dungeon Master, an
Admin or a member could open before is lost (D-04: the editing DM's View Details link never dead-ends).
Output: the check in `ShopController.Details`, the integration facts, three re-pointed existing facts, the guard
list entries, `deferred-items.md` moving the item to resolved and recording what planning found, and the docs commit.
The operator's go-ahead and this plan's ids live only here and in commit messages, never in source.
</objective>
