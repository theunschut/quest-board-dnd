# Phase 99 — UI Design Contract (delta on Phase 94)

> Visual and interaction contract for converting Shop/Index, Shop/Details, ShopManagement/Index, Create and Edit (each with its `.Mobile` twin) and the shared partial `_ShopItemDetailsContent` onto the Phase 94 foundation (Direction A, refined glass) in the navy Shop theme, variant (a), on `<html data-theme="shop">`.
> Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.
>
> **This file is a delta.** `94-UI-SPEC.md` ("the foundation spec") fixes the tokens, type scale, spacing scale, colour roles, the closed gold list, the accessibility bar (A-1 to A-11), the component classes and the cascade rules. `97-UI-SPEC.md` and `98-UI-SPEC.md` fixed the card-role rules, the stretched row link, the empty-state structure, the form contract and the date helper rules. This file **references them by section name and never restates a value they fix.** A number that appears here is a measurement, a computation taken for this phase, a component dimension (declared in "Spacing Scale") or a pointer to a token name. If this file and the foundation spec disagree on a shared value, the foundation spec wins and this file has a defect.
>
> **Scope is locked by `99-CONTEXT.md` D-01 to D-16 and the inherited G1 answers.** Nothing here re-opens them. Where CONTEXT leaves a choice (its Discretion list, and the research's open questions) this file records a **DISCRETION** choice with its reason or a **GATE 1** item with a stated recommendation and default. **No question was put to the operator while writing this file** (it ran unattended); every open point is a numbered Gate 1 item, and silence at Gate 1 leaves the default in force. The one item with **no default** is the merchant placement (D-01), because CONTEXT says nothing is built until Gate 1 picks one.
>
> **Source-code rule (applies to every row below).** The IDs in this file (D-xx, Q-xx, A-shop-xxx, R-x, DoC-x, WINDOWS numbers, phase and plan numbers) are for this document only. They are never written into a view, stylesheet, script, test string or comment. Comments say why, in plain language that stays true after the phase closes (`CLAUDE.md` § "Code Comments").
>
> **Delivery rule.** The phase ships as v6.4.0 through a pull request the operator opens. Nothing in this contract requires an executor to create a PR, a tag or a release, to push, or to touch `main`. See "Delivery" at the end of "Gate artefacts".

## The whole image rule (FIXED; the v6.3.1 and v6.3.2 lesson)

Phase 98 shipped `aspect-ratio` together with `object-fit: cover` on details portraits and needed two patch releases. This phase must not reproduce it. **Shop items have no picture field and no `<img>` exists in the shop family**, so there is nothing to crop today; the rule exists so nothing ever gets cropped, and because three surfaces are meant to show their whole content.

| Surface | Meant to show whole | Safe approach (FIXED) |
|---------|---------------------|-----------------------|
| Emblem tile (D-07) and its icon | yes: a decorative icon in a tile | a block with `min-block-size` from the declared dimension (144px desktop, 120px phone), flex centring, glyph size smaller than the tile; **no `overflow: hidden`, no `aspect-ratio`, no `object-fit`, no literal `height`, no `style=`** (the `style="height: 250px;"` goes). The tile grows if the glyph or a large text-spacing setting needs it |
| Merchant figure (`fa-user-tie` in the button) and hero icon (`fa-store`) | yes: decorative glyphs | sized by the button's `min-inline-size` and `min-block-size` and the glyph's font size; centred; the bob moves with `transform` only, so it cannot crop the glyph |
| User Markdown images inside an item description (modal and Shop/Details; the sanitiser allows `img`, no sizing rule exists today) | yes: user content | in the shop sheet only: `.item-details-content .markdown-content img { max-inline-size: 100%; block-size: auto; }`. | Board backdrop | decorative; cover is correct by design | under `data-theme="shop"` the theme replaces `--qb-board-image` with the navy gradient, so there is no photo to crop |

**Forbidden in every shop stylesheet, view and script:** `aspect-ratio` anywhere, and `object-fit` anywhere (stricter than Phase 98's per-rule scan; the shop has no excuse for either), `overflow: hidden` on an element that holds an icon tile or an image, and an inline `style` carrying a `height`, `width`, `aspect-ratio` or `object-fit`. **Guard (required, in `ShopConversionGuardTests`, with a scanner self-test as Phase 98 did):** (1) no shop sheet contains `aspect-ratio` or `object-fit`; (2) no shop view or partial carries `style=` at all; (3) the `.markdown-content img` rule exists and holds `max-inline-size: 100%` and `block-size: auto`; (4) the scanner is proven on a seeded bad fixture string (a rule that mixes `aspect-ratio` and `object-fit: cover` is flagged) so it cannot go silent.
