Nyquist validation audit and by 99-22's planning:

1. **Limited-stock Return and Sell is broken.** On an item with limited stock, every Return or Sell slip in the

   recorded. The validation audit escalated it as a blocker and skipped its four reproduction cases.

   list, but it opens at `/Shop/Details/{id}` and can be bought, or sold to the shop, by id.

availability window means the same thing on every path, judged by the board's own clock.

**2. Archive and Reopen.**
- `ShopManagementController.cs:208-222` Archive: NotFound on a missing id, then `ArchiveItemAsync` for any status.
  `:259-279` Reopen: refuses anything not Archived ("Only archived items can be reopened."), then `PublishItemAsync`.
  `:180-206` Publish: Forbid for the creator (every role, Admin included), and "This item is already published or
  archived." for non-Draft. `:224-257` Deny: no self-deny, Draft only. `:281-306` Delete: Admin any status, others
  Draft or Denied only.
- Every management view since the first commit in git (a477ab98) offers Archive only on a Published row and Reopen
  only on an Archived row: desktop `Index.cshtml:154-171` (My Items) and `:253-270` (All Other Published Items), phone
  `Index.Mobile.cshtml:65-82`. The Edit views offer neither.
- Rule chosen: **Archive accepts only Published; Reopen is unchanged.** Why:
  - It makes the server match what every list has always offered. Archived has always meant "taken off sale after
    being published", and 99-22's Details rule keeps Archived open to members precisely because such items "were on
    sale once". This rule makes that true by construction. The only thing it removes is a hand-made post.
  - With Archive limited to Published, Reopen to Published is always a restoration of an item that was reviewed, or
    auto-published as Common or Uncommon. So Reopen needs no change and keeps working for every item the UI can archive.
  - The alternative (Reopen restores Published only if the item had been published, otherwise Draft) needs a record of
    earlier publication that the schema does not have, which means a new column and migration. Until then, an archived
    Draft would still show to members under the Archived rule.
  - Admin: same rule. Publish refuses an Admin's own item too, so an Admin who archives and reopens their own Draft
    would be the same bypass. Admin keeps Delete of any status.
  - Not widened: editing an Archived item and reopening it publishes the edit without review, which is no more than
    editing a Published item already does today (Edit keeps Published). That is existing semantics, unchanged.
  - Residual, accepted: an Archived row archived from Draft or Denied before this fix can only have come from a
    hand-made post. It cannot be told apart and would still reopen to Published.
- No view change: the lists already hide Archive on non-Published rows and Reopen on non-Archived rows. A render fact
  pins it. `ShopRenderTests.SeedManagementBoardAsync` (390-420) seeds the viewer's own Draft, Published, Archived and
  Denied items, another keeper's Draft and another keeper's Published item, as a DM or an Admin.
  `ManagementPostForms` (508-510) reads the posting forms.
