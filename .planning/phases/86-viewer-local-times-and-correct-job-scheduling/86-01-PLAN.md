<assumption_delta_decision>
**Primary noun:** the clock.

**Decision: promote.**

Before this phase the application had exactly one implicit clock — ambient UTC, read statically via `DateTime.Today` / `DateTime.Now` / `DateTime.UtcNow` at 18+ call sites. This phase introduces three distinct clocks: the stored UTC instant, the configured board zone, and the viewer's browser zone. The generalized noun is therefore *the clock*, and `IBoardClock` is **promoted to the primary clock** for every read compared against a board-local date — the ambient static read is **eliminated** from touched code rather than left available alongside it (CONTEXT.md D-07: "every ambient clock read … moves onto one board clock").

Rationale: leaving the static read available alongside the seam is precisely the failure mode the ROADMAP names as worse than the starting state — "fixing one clock and not the other" leaves the sweep computing on a different clock than the one that woke it. A companion invariant test (`AmbientClockSeamTests`, plan 86-06) encodes the generalized intent so a future phase cannot silently reintroduce the singular assumption.
</assumption_delta_decision>
