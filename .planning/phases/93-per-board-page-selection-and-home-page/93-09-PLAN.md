<objective>
Refuse a Phase 92 move onto a linked board where that kind of entry is switched off, on the preview, on the confirm and in the picker, and stop offering the move control when no linked board can take the entry.

Purpose: D-08 extends to anything that would put a new entry on a board whose page for it is off; a moved quest or event would otherwise appear on that board's feed and calendars pointing into a refused page.

Output: `MoveStatus.TargetPageOff`, the refusal in both move services, the control rule in `MoveControlService`, the controller arms, the picker, and tests.
</objective>

<recorded_choices>
1. **Refuse right after the target resolves,** before DM eligibility, roster or plan work, so no other refusal masks it and no write path is reached.
2. **The GET gets its own case** (toast and redirect to Details), because the default branch would render an unhandled state. The POST gets a message arm.
3. **Picker shows, but disables, an off board.** The super admin sees why that board cannot be chosen rather than wondering where it went.
4. **The control requires a taker.** `MoveControlService` offers the control only when some linked board can take the kind, so a board whose only partner has Events off shows no event move control.
</recorded_choices>
