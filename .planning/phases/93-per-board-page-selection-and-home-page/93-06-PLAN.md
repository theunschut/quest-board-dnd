<recorded_choices>
1. **Rows post only what is switchable.** Locked rows (type-disallowed, Quest Log while Quests is off, and any non-switchable page) render a disabled checkbox with no `name`, so they post nothing. The server ignores them anyway (D-15). Unlocked rows post `Pages[n].Page` and `Pages[n].Enabled` with a running index `n` that counts only posted rows, so list binding never hits a gap.
2. **Home dropdown lists every candidate the board type allows,** not only pages currently on, so a super admin can switch Calendar on and make it home in one save. The settings service refuses a home that is not available in the resulting state.
3. **Re-render shows what was posted.** On any refusal the rows reflect the outcome's resulting mask (what the super admin asked for, after sanitising), and lock reasons are recomputed from it.
4. **Success toast** becomes "Board settings saved." No test asserts the old text.
5. **Platform rows appear for switchable pages only.** Until plan 10 makes Quests switchable there is no Quests row. Plan 10's flip adds the row with no change here, because the row list reads `BoardPagePolicy.IsSwitchable`.
</recorded_choices>
