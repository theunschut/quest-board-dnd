<objective>
Remove every in-page way into a switched-off Events or Calendar page. With Events off, the Calendar stops loading the board's own events and runway series, and its Board Availability button disappears. With Calendar off, event saves and cancels land on the Events list instead of a refused calendar.

Purpose: D-07 says links into a switched-off page disappear. Research Pitfall 8 found that redirect-after-save would otherwise end every successful event save in a "calendar isn't used" toast. My Agenda's Board Availability button follows the same switch but sits in plan 03 with the layouts' Board Availability item.

Output: `CalendarController`, `EventsController` and `SeriesController` changes, the Board Availability button in the Calendar twins, the event form Cancel links, and `BoardPageEventsCalendarTests`.
</objective>

<recorded_choices>
1. **Not loaded rather than hidden.** With Events off the controller never reads the board's own events or runway series, mirroring how a Campaign calendar never reads quests. Nothing can leak through a view, and no view markup for those rows changes.
2. **`Serves` for buttons and loads.** None of these surfaces has a board-type check today, so the unresolved state keeps today's behaviour.
3. **Calendar on with Events off on a Campaign board renders an empty calendar** (research A9; the operator accepted the research recommendation). No extra rule ties Calendar to Events.
4. **Fallback target is the Events list** (`/Events`) for every redirect and Cancel link when Calendar is off. Events is necessarily on there, because these actions sit behind the Events gate.
</recorded_choices>
