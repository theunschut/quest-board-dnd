<objective>
Send every "home" entry point to the board's home page: the `/` address, landing after login or after picking a board with no return URL, and the Account page's back link. After this plan `/` and the picker land on the board's chosen home page, per board, while an explicit return URL still wins.

Purpose: D-11 lists the places the home page applies. Plan 01 covered the refusal redirect and plan 03 covers the brand link; this plan covers `/`, the picker (and so login) and the Account back link, all through the same `BoardPageRoutes.HomeRoute`.

Output: the async `HomeController.Index`, the picker fallback, the Account Profile back link on both twins, and `BoardPageHomeTests`.
</objective>

<recorded_choices>
1. **`/` is resolved in one place.** `HomeController.Index` asks the resolver and redirects to `BoardPageRoutes.HomeRoute`; the picker fallback and the Account back link point at `Home/Index`, so they inherit the same answer on the next request. The brand link (plan 03) and the refusal redirect (plan 01) call `HomeRoute` directly to save a hop. All of them share one function, so they cannot disagree.
2. **Account back link label kept.** "Back to Quest Board" keeps its wording. Only its target moves to `Home/Index`, so unconfigured boards render identically and the link follows a board's chosen home.
3. **MoveController redirects unchanged (D-11).** Its success and "no longer on this board" redirects go to the list of the same kind (quests or events). That list is on by construction, because the Move action is gated by the same kind (plan 02), and the gate would send the user home if it were not. This resolves research Open Question 3.
4. **The anonymous landing page and a super admin with no board stay unchanged** (CONTEXT discretion): a signed-out visitor still gets `View()`, and the group-session middleware still sends a board-less user to the picker before `HomeController` runs.
</recorded_choices>
