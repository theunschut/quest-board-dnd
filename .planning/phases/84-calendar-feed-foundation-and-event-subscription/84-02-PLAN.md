## Assumption delta — two singular-to-plural promotions, both already decided

The assumption-delta detector returned `detected: true`. The two literal signals it matched (`second`, `another`) are weak on their face — a *rejected* second URL shape, and a reader in another timezone. But two genuine singular-to-plural transitions are in this phase's scope, both already settled in `84-CONTEXT.md`. They are recorded here, not re-opened.

**Primary noun: the calendar subscription.**

| # | Transition | Outcome | Rationale |
|---|-----------|---------|-----------|
| 1 | one subscription per user → many named, independently revocable subscriptions per user (D-05) | **promote** | The subscription becomes its own entity with its own identity, its own name and its own tombstone. The rejected alternative was a single random column on `UserEntity`, which makes one URL per person, so rotating one device's address kills every device at once. The user row holds none of the subscription's state. |
| 2 | one feed source (events) → two sources (events now, quests in Phase 85) | **promote** | The VEVENT identifier names a `(source, occurrence)` pair from the start rather than an event id that Phase 85 has to retrofit. CONTEXT.md's `### Claude's Discretion` block already requires this: "namespaced by source — a quest and an event can share an integer id, and Phase 85 adds the second source." |

**Why promotion 2 is the one-way door.** Retrofitting namespacing later is irreversible in practice: every existing subscriber's calendar client keys its stored copy by identifier, so changing the identifier makes every phone accumulate a duplicate of every event it already holds, with no server-side way to withdraw the old copy. That is the reason the source segment is structural — a `CalendarFeedSource` enum member consumed by the identifier builder — rather than a string spliced in at the call site.

**What would force a later change:**
- Promotion 1 would have to be revisited only if a per-board feed URL is ever wanted (CONTEXT.md `## Deferred Ideas`), which needs a different token-to-scope model, not a wider table.
- Promotion 2 would have to be revisited only if a source ever needs a non-integer key (for example a composite occurrence key), which would widen `SourceId` and change every identifier. `84-03-T3`'s invariant test goes red the moment a new source produces a colliding identifier, which is what keeps that door shut.

**Companion invariant test:** judged worth the cost and planned as task `84-03-T3` in plan 84-03 — it asserts the identifier is stable across two successive renders of the same occurrence, that every declared source yields a distinct identifier for the same numeric id, and that no identifier contains the configured application host.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → `/feeds/calendar/{feedToken}.ics` | Fully anonymous, unauthenticated, machine-polled. No cookie, no session, no active board. The address in the path is the entire credential |
| board membership → feed contents | The subscription owner's membership set is the access-control decision; it is read fresh from the database on every fetch and never taken from session or claims |
| ambient tenant filter → `IgnoreQueryFilters()` bypass | The new query steps outside the filter that protects every other read in the application, and must re-pin scope in the same expression |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-84-01 | Information Disclosure | `EventSignupRepository.GetFeedRowsForUserAsync` + `CalendarSubscriptionService.GetFeedAsync` | critical | mitigate | `IgnoreQueryFilters()` paired in the same predicate with `memberGroupIds.Contains(es.Event.GroupId)`, where `memberGroupIds` comes from a `GetGroupsForUserAsync` read taken in the same request; then an independent in-memory re-check that drops any surviving foreign row and `LogError`s both counts. The query is called even for an empty membership set so a dropped predicate cannot hide behind a short-circuit |
| T-84-03 | Spoofing | the address as bearer credential | high | mitigate | `RandomNumberGenerator.GetBytes(32)` Base64Url-encoded to 43 URL-safe characters, unique-indexed; `Guid.NewGuid()` is explicitly forbidden by an acceptance criterion.
