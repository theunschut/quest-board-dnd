<objective>
Show a contact's category on both Details views, and prove that every mobile file this phase adds or
changes is the file the server actually selects — using a real mobile user agent, not viewport
emulation. Close the phase with a full-suite gate.

The mobile proof is not ceremony. Viewport emulation does not change the request's user agent, so the
mobile view is never selected and what renders is the desktop view squeezed narrow. This repository
has already shipped mobile markup that was never rendered because a check relied on emulation, and
that failure is on the project record.

The details line also carries the phase's one factual correction: the discussion recorded the category
field as already present on the mapped contact view model. It was not. By the time this plan runs the
field exists across the entity, the domain model and the view model, so this plan is genuinely
view-only — but only because earlier plans did that work.

Purpose: complete the visible surface and prove the mobile half of it.
Output: two view edits, two test classes, and a green suite.
</objective>
