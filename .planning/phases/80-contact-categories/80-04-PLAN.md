<objective>
Add the service-layer view models the two controller plans bind to, wire the view-model mapping
boundary, and add the category styles to the two contacts stylesheets.

This plan exists as its own unit for one structural reason: the management vertical and the index
vertical would otherwise both edit `ContactViewModel`, `ViewModelProfile` and the two stylesheets,
forcing them into the same wave. Landing every shared surface here lets the later plans stay
disjoint.

It also settles the grouping shape CONTEXT.md left to planning: nested groups on the index view
model, computed once in the controller. The alternative — each index view applying the
visibility-suppression rule itself — writes the sharpest rule in the phase twice, which is exactly
the drift class this project has already been bitten by.

Purpose: one shared surface, edited once.
Output: five view model files, the mapping entries, and the two stylesheets.
</objective>
