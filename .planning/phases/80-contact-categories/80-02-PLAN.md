Add `public DbSet<ContactCategoryEntity> ContactCategories { get; set; }` beside the existing
`Contacts`, `ContactImages` and `ContactNotes` sets, in the same declaration style.

In `OnModelCreating`, add four configuration blocks.

Block one, the board foreign key: on `ContactCategoryEntity`, configure
`HasOne(cc => cc.Group).WithMany().HasForeignKey(cc => cc.GroupId).OnDelete(DeleteBehavior.NoAction)`,
copying the five-line shape the `Contact → Group` block already uses, and place it next to the
other board foreign key blocks. `NoAction` is mandatory here, not stylistic: EF's convention
default for a required foreign key is `Cascade`, and a cascade from `Group` to `ContactCategories`
combined with the category-to-contact path converges two delete paths on `Contacts`, which SQL
Server rejects outright with a multiple-cascade-paths error at schema-creation time. Comment it in
the same plain style as the existing `Contact → Group` comment.

Block two, the contact-to-category foreign key: on `ContactEntity`, configure
`HasOne(c => c.Category).WithMany().HasForeignKey(c => c.CategoryId).OnDelete(DeleteBehavior.SetNull).IsRequired(false)`,
mirroring the `Event → Series` fluent shape with `SetNull` substituted for `NoAction`. The explicit
`IsRequired(false)` is load-bearing: it keeps the navigation optional by contract, so EF Core emits
a left join rather than an inner join when a related row is filtered out, instead of relying on
convention inference. This one configuration is what makes deleting a category orphan its contacts
rather than delete them (D-03).

Block three, the unique index: `HasIndex(cc => new { cc.GroupId, cc.Name }).IsUnique()` on
`ContactCategoryEntity`. No collation override and no computed lower-cased shadow column — this
database's ambient collation is already case-insensitive, which is what gives D-04 its
case-insensitive uniqueness for free.

Block four, the fail-closed board filter, placed directly after the existing `ContactEntity`
filter block: on `ContactCategoryEntity`, `HasQueryFilter(e => activeGroupContext.ActiveGroupId != null && e.GroupId == activeGroupContext.ActiveGroupId)`.
The lambda must dereference `activeGroupContext.ActiveGroupId` inline, both times, exactly as
written. Do not introduce a local variable holding the active group id anywhere near this block —
the file's own warning comment explains that a local captures the value once at model-build time,
when it is null, and permanently breaks the filter for every request thereafter. Comment the new
block in the neighbouring block's style: categories are a per-board roster with no cross-board
administrative view, and zero rows when no board is selected is the intended behaviour, not an
oversight (D-02).
