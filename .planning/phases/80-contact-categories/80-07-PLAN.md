<objective>
Add category assignment to the contact form on all four Create and Edit views, validate the
submitted category against the active board before persisting it, and prove cross-board isolation
end to end.

This is where the phase's tenancy risk actually lands. The board filter makes another board's
category unreadable, but a form post carries a raw integer, and persisting it without a filtered
lookup would write a foreign reference straight past the filter. This application has already
shipped two real cross-board leaks, so the refusal is implemented explicitly and proven by a
two-board test rather than assumed from the filter.

Purpose: make categories assignable, safely.
Output: the field on four forms, a validated write path, and the isolation suite.
</objective>

only when a board-filtered read by that id returns a category. Because the read goes through the
board-scoped service, a category owned by another board simply does not resolve, so a foreign id is
indistinguishable from a nonexistent one and both are rejected. Do not compare board ids by hand and
do not bypass the filter to look one up.

Change `Create` GET to an async action taking a cancellation token, construct the view model as it
does today, call the options helper, and return the view.

In `Create` POST, call the options helper before every `return View(viewModel)` path so a re-render
never comes back with an empty dropdown. After the existing model-state check and before the
contact is mapped and persisted, call the acceptance helper on the posted category id; when it
rejects, add a model error on the category id field reading exactly "Selected category is not
available on this board." then repopulate the options and return the view. Leave the mapping and the
board and creator stamping exactly as they are — the category id rides along through the existing
map.

In `Edit` GET, call the options helper on the mapped view model before returning the view, so the
contact's current category arrives preselected.

In `Edit` POST, call the options helper before every `return View(viewModel)` path. Apply the same
acceptance check on the posted category id with the same message and the same re-render. On the
success path, add the category assignment to the existing block that copies name, description, town
and sub-location onto the loaded contact, so a cleared selection writes a null reference and is not
silently dropped.
