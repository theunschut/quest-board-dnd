<objective>
Close the verification loop in CI. Add a real-network test that the installer's verification
refuses tampered and mismatched artifacts, a workstation script that verifies a published release
exactly as the server will (the bridge for the bootstrap's trust-on-first-use), and CI jobs that
run every script test, lint the release workflow and run the network proof on every PR.

Purpose: unit-level stubs cannot prove that gh actually rejects tampered bytes, and the packaging
and installer can only be proven together on a machine that builds. CI is where both meet. The
operator's first install also needs a trustworthy way to check the zip before `setup` runs.
Output: network test with copied public fixture, `build/verify-published-release.sh`, three new
dotnet.yml jobs, and a script-existence guard in `release-workflow-test.sh`.

Recorded choice: shellcheck, actionlint and zizmor run only in CI from digest-pinned images. They
are not installed or pulled on the workstation (no environment provisioning), so the executor
checks syntax with `bash -n` locally and fixes CI lint findings in the plan 10 loop. zizmor's
hash-pin policy runs on release.yml only; dotnet.yml's original build job keeps its tag-pinned
actions, which is a deferred observation and not in scope.
</objective>
