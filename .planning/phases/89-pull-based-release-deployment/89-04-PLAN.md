## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tag push -> release workflow | Anyone with push rights can create a tag; the tag name flows into shell |
| workflow -> GitHub token / OIDC | Job tokens can write releases and mint attestations |
| draft -> published release | Approval is the only human gate before the server will install |
| repository -> production box | Any workflow targeting self-hosted would run code on the App CT |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-89-12 | Elevation of privilege | release.yml expressions and permissions | high | mitigate | permissions: {} at workflow level, least job-level grants, every ${{ }} passed via env:, all actions pinned by full SHA, zizmor hash-pin config; release-workflow-test.sh enforces each |
| T-89-02 | Spoofing | tag off main / branch-modified workflow | high | mitigate | validate-release-tag.sh checks strict format, GITHUB_SHA match and main ancestry; installer re-checks the attested commit against main (plan 05); tag ruleset and environment tag policy checked by check-github-settings.sh |
| T-89-01 | Tampering | draft assets between build and publish | high | mitigate | publish job re-downloads, sha256sum -c, and gh attestation verify pinned to repo, signer workflow, source ref and --deny-self-hosted-runners before --draft=false |
