<objective>
Wire the tested libraries into the root installer `questboard-deploy`: poll, install, rollback,
verify and the setup entry point, implementing the install order (D-10), the full outcome matrix
(D-11), remember-and-skip (D-15) and mail-on-outcome-only (D-14). Prove every matrix row end to
end in a temp root with stubbed host commands, and prove that a real packaged zip installs through
its own shipped installer.

Purpose: this is the code that will run unattended on production every five minutes. Its
correctness is the difference between a deploy that heals itself and one that leaves the board
down or spends the Resend budget.
Output: `deploy/bin/questboard-deploy`, `deploy/tests/install-flow-test.sh`, a `.gitignore`
re-include for `deploy/bin/`.

Decisions recorded here (orchestrator defaults, Claude's discretion):
- manual rollback to the adopted release is refused;
- install of the active tag restarts and health-checks only;
- the default health timeout is 120 s;
- a manual rollback reports to the terminal and journal and sends no mail, because the operator
  is present and the relay budget is shared;
- a transport failure while downloading is "GitHub unreachable", which is journal-only and not
  remembered, while an HTTP 404 asset is a refusal.
</objective>

Write `deploy/bin/questboard-deploy` (bash, `set -euo pipefail`, `umask 022`, LF, `chmod +x`), porting the reference installer's dispatcher shape with this phase's behaviour.

1. Library location: use `SCRIPT_DIR/../lib` when `common.sh` exists there (running from an unpacked release), else `${DEPLOY_ROOT}/usr/local/lib/questboard-deploy`. Source common.sh, verify.sh, release.sh and deploy.sh. Define the globals exactly as named in the interfaces block. `require_root` is skipped only when `DEPLOY_ROOT` is non-empty. `acquire_lock` uses `mkdir -p` of the lock dir, then `exec 9>"$LOCK_PATH"` and `flock -n 9`, and dies "another questboard-deploy invocation is already running" when the lock is busy.

2. `load_configuration` assigns the defaults from the interfaces block unconditionally, ignoring any same-named environment variable, so every effective value is either a default or a line the loader validated. Only `QUESTBOARD_DEPLOY_ROOT` and `QUESTBOARD_DEPLOY_CONF` are read from the environment. It then calls `questboard_load_conf "$CONF_PATH"` and dies when `QUESTBOARD_GITHUB_REPO` is empty. `main` dispatches:
   - `setup` acquires the lock, then calls `cmd_setup` before any config load, because setup creates the config;
   - `verify` loads config without the lock;
   - `poll`, `install` and `rollback` load config and acquire the lock;
   - `-h`/`--help` prints usage;
   - anything else prints usage and dies.

3. `finish OUTCOME REASON [extra mail flags...]` is the single exit point for an install attempt. It:
   - records the attempt;
   - renders the mail with `--started "$STARTED" --finished "$(questboard_utc_now)"` plus the extras, writes it to a mktemp file and calls `questboard_send_mail`;
   - logs one line `outcome=OUTCOME tag=TAG reason=REASON`;
   - removes `DOWNLOAD_DIR/<version>`;
   - exits 0 for installed and 1 otherwise.
   This is the only place mail is sent (D-14).

4. `cmd_install TAG`:
   - validate the strict tag;
   - if it equals the active version, go to the redeploy path (Task 2); if it is not newer than the active version, die "refusing vX.Y.Z: not newer than the active release A; use rollback" with no mail and no record;
   - set `STARTED`;
   - download the zip, `.sha256` and `.sigstore.json` into a fresh `DOWNLOAD_DIR/<version>` (mode 700): download rc 2 means `finish refused asset_missing`; rc 1 means, when `INVOKED_BY_POLL` is 1, log "GitHub unreachable while downloading vX.Y.Z; the next poll retries" and exit 0 with no record or mail, and otherwise die;
   - `questboard_verify_checksum`, then `questboard_verify_attestation` against `refs/tags/TAG`, then `questboard_commit_on_branch ... main`, each failure going to `finish refused` with checksum_mismatch, attestation_failed or not_on_main (D-01, no flag or variable skips any of them);
   - `questboard_stage_release`: rc 3 is refused invalid_content and rc 4 is failed insufficient_disk;
   - run the new release's migrator `status`: rc 2 is refused database_ahead, rc 3 is refused non_transactional_migration, any other non-zero is failed database_unreachable, and each of these removes `releases/<version>`;
   - parse the pending count and `databaseExists`;
   - when pending > 0 and the database exists, run `backup --label TAG`; a non-zero rc is failed backup_failed with the release dir removed and the app never stopped; otherwise keep `backupName`;
   - `systemctl stop "$APP_SERVICE"`;
   - when pending > 0, run `apply`; a non-zero rc means `systemctl start "$APP_SERVICE"` (current still points at the previous release), a health check of the previous release with its manifest's header flag, removal of the new release dir, and `finish failed_rolled_back apply_failed --previous-healthy yes|no`; otherwise set migrated=1;
   - remember the pre-install previous version, `questboard_activate_release`, `systemctl start`, and `questboard_wait_for_health` with the new manifest's header flag;
   - on success: prune, compute `--update-from` via `questboard_deploy_files_differ "$RELEASES_DIR/<version>" "$DEPLOY_ROOT"`, and `finish installed`;
   - on failure: ask `questboard_decide_outcome health fail MIGRATED HAS_PREVIOUS`:
     - `rolled_back switch_back`: stop, reactivate the previous release, restore the remembered previous value in the state dir, start, health-check the previous release, `finish rolled_back unhealthy --previous-healthy ...`;
     - `halted leave`: leave the new release active and running (systemd keeps retrying it), `finish halted unhealthy --backup "$backupName"`;
     - `failed leave` (no previous release): `finish failed unhealthy`.
   Route every branch through `questboard_decide_outcome` rather than hard-coding outcome names, so the tested table is the only source of truth (D-10, D-11).

5. `cmd_poll`:
   - `questboard_fetch_latest_tag`: rc 1 logs "GitHub unreachable; the next poll retries" and exits 0; rc 3 logs "no published release yet" and exits 0;
   - a non-strict tag is logged and exits 0;
   - a tag not newer than the active version logs "nothing newer than A" and exits 0;
   - a remembered outcome logs "skipping vX.Y.Z: OUTCOME earlier; run questboard-deploy install vX.Y.Z to try it again" and exits 0;
   - otherwise set `INVOKED_BY_POLL=1` and call `cmd_install`.
   The poll never calls `questboard_send_mail` itself (D-13, D-14, D-15).

6. `cmd_verify --artifact F --bundle F --tag T`: attestation plus the main check, printing the digest; nothing is installed.

7. `cmd_setup "$@"`: die with "setup library not found in LIB_DIR" when `setup.sh` is absent, else source it and call `questboard_setup_main "$(cd "$SCRIPT_DIR/../.." && pwd)" "$@"`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| timer -> root installer | Unattended root code acting on internet input every five minutes |
| GitHub releases/latest -> install decision | Public metadata chooses which tag is attempted |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-89-03 | Tampering | replay or downgrade via releases/latest | medium | mitigate | Poll and install require a strictly newer strict-semver tag; older tags die with "use rollback"; rollback is local-only and database-checked |
