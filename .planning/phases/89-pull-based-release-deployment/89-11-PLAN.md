<objective>
Second half of the handover: cut production over from the flat, push-deployed install to the
versioned, pull-based one, and let the first attested release install itself.

Purpose: this is where the unverifiable assumptions get proven on the real hosts:
- systemd-run inside the sandbox;
- gh's cache under ProtectHome;
- the SQL login's backup rights;
- the backup directory;
- the real mail relay.
Each one fails safe (the install stops before the app is touched), but each must be seen working
once.
Output: production on `/opt/questboard/current -> releases/X.Y.Z`, the adopted release kept as the
rollback target, the timer enabled, one "installed" mail received, and a rehearsal backup proven
on the SQL CT.

The agent only reads: `gh` and `build/verify-published-release.sh` on this workstation, and
read-only SSH as `claude`
(`ssh -i ~/.ssh/questboard-lxc-claude -o IdentitiesOnly=yes claude@192.168.6.12`), using
`systemctl show -p ...` and never `systemctl cat`. Every privileged step is the operator's.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> CT (first zip) | Trust-on-first-use for the installer itself |
| operator root shell -> production | Layout change and new apt source |
| CT -> SQL CT | Backup of the full production database |
