## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub release download -> App CT disk | Untrusted bytes arrive from the internet |
| Sigstore TUF -> gh | Trust root fetched at verify time |
| root installer -> questboard migrator process | Privilege drop and secret hand-off via systemd |
| app -> installer health probe | The installer trusts what the loopback endpoint reports |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-89-01 | Tampering | questboard_verify_checksum / questboard_verify_attestation | high | mitigate | sha256 then gh attestation verify pinned to repo, signer workflow, refs/tags/<tag>, --deny-self-hosted-runners; any non-zero, missing or non-hex digest refuses; no bypass path exists (grep gate) |
| T-89-02 | Spoofing | branch-tagged build riding the signer workflow | high | mitigate | questboard_commit_on_branch requires the attested sourceRepositoryDigest to be identical to or behind main |

## Assumptions carried by this plan

- A2 / Pitfall 5: `systemd-run` and `systemctl` work from inside the sandboxed root oneshot (`ProtectSystem=strict`, `NoNewPrivileges`).
