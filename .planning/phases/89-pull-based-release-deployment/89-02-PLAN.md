<objective>
Give the migrator its two state-changing commands, `backup` and `apply`, with apply all-or-nothing
in one caller transaction. Prove the guarantee against a real SQL Server in gated integration
tests, and run them in CI against a service container.

Purpose: D-07 is the guarantee behind the whole install design. A failed migration must always
leave production where the previous release can safely come back up. EF Core 10 commits per
migration by default, so the migrator must supply the transaction itself, and InMemory cannot run
migrations, so only a real SQL Server can prove it.
Output: `backup`/`apply` in `QuestBoard.Migrator`, DB-less CLI tests, gated SQL Server tests, and
a `migrator-sql` CI job.

Local runs: `localhost:1433` is not reachable on the development machine and must not be
provisioned (CLAUDE.md). The gated tests therefore skip locally. The proof runs in CI, and the
hosted run is checked before merge in plan 10. If the operator says a SQL Server is available at
`localhost:1433`, the executor may run the gated tests against it with an operator-supplied
`QUESTBOARD_MIGRATOR_TEST_CONNECTION`, but must never start one.
</objective>

4. `public string Backup(string label)`:
   - throw `ArgumentException` on an invalid label before touching the connection;
   - open the connection explicitly (`context.Database.OpenConnection()`, any `DbException` becomes `MigratorConnectionException`);
   - when the database does not exist, throw `MigratorBackupException` (the installer skips backup when status says `databaseExists` false);
   - set the command timeout to 30 minutes;
   - read `databaseName` from `context.Database.GetDbConnection().Database`;
   - run `context.Database.ExecuteSql($"BACKUP DATABASE {databaseName} TO DISK = {fileName} WITH COPY_ONLY, CHECKSUM, INIT, NAME = {fileName}")`. Interpolation makes every value a parameter, and BACKUP accepts variables for the database, device and set name. The file name is bare so SQL Server resolves it against its default backup directory;
   - never inside a transaction, because BACKUP is not allowed in one;
   - return the file name. A `DbException` during the statement becomes `MigratorBackupException` carrying its number.

5. `public IReadOnlyList<string> ApplyAtomically()`:
   - (a) `status = GetStatus()`. Connection failure surfaces as `MigratorConnectionException`.
   - (b) If `status.Unknown` is non-empty, throw `MigratorDatabaseAheadException`.
   - (c) If `status.NonTransactional` is non-empty, throw `MigratorNonTransactionalException`. This refusal happens before anything is written.
   - (d) If nothing is pending, return an empty list.
   - (e) If `!status.DatabaseExists`, call `context.GetService<IRelationalDatabaseCreator>().Create()` outside any transaction (CREATE DATABASE cannot run inside one; a fresh host ends with an empty database if the batch then fails, which still lets the previous release start).
   - (f) Set the command timeout to 10 minutes, `OpenConnection()`, `using var transaction = context.Database.BeginTransaction();`, `context.Database.Migrate();`, `transaction.Commit();`.
   - (g) Any exception from (f) is wrapped in `MigratorApplyException`. The `using` disposes the uncommitted transaction, which rolls everything back, history inserts included.
   - (h) Return `status.Pending`.

   Comment the why in plain language: EF Core 10 commits after each migration unless the caller owns the transaction, and owning it also skips EF's own migration lock, which is safe only because the app is stopped and the installer holds its own lock. Do not add a retrying execution strategy anywhere.

6. `MigratorCli.Run`:

   - Map exceptions to exit codes: database-ahead to 2 (stderr lists the unknown ids), non-transactional to 3 (stderr lists the flagged ids), connection failure to 4, backup to 5, apply to 6.
   - For statement-phase failures (backup, apply) stderr may carry the SQL error number and the SQL error message, because these come from statement execution, not from the connection. Connection-phase failures still print only the fixed text and number.
   - Nothing ever prints the connection string.
