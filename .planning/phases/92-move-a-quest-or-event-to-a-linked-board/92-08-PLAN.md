<objective>
Put the move where the roadmap puts it, on the entry's Details page, and close the loop with the post-move toast. A super admin on a linked board sees "Move to Linked Board" on Quest Details (both layouts) and Event Details, or the same control disabled with a one-line reason when the entry cannot move. Everyone else, and every unlinked board, sees nothing new. After a move, the toast offers "Open it on {Board}" when the super admin can open that board.

Purpose: D-13 (nothing outside a set), D-14 (entry points on both quest layouts and on Event Details) and D-16 (land on the source board, link through the board switch). The disabled-with-reason control is the CONTEXT default for "an entry that cannot move", so a missing button never looks like a bug.

Output: `MoveControlState`, `IMoveControlService`/`MoveControlService`, `ViewBag.MoveControl` on both Details actions, the control in three views, the Moved toast block, the mobile reason style, and the unit and HTTP proofs.
</objective>
