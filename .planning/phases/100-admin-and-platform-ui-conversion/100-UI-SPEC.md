## The whole image rule (FIXED; the v6.3.1 and v6.3.2 lesson)

Phase 98 shipped `aspect-ratio` together with `object-fit: cover` on details portraits and needed two patch releases. **No admin or Platform view or sheet shows a picture today** (grep over the 26 views and nine sheets finds no `<img>`, `background-image`, `url(`, `aspect-ratio` or `object-fit`), so nothing can be cropped. The rule is stated anyway so nothing ever is: a picture meant to show whole never gets `aspect-ratio` with `object-fit: cover` on a fixed ratio; if a future admin page shows one it uses `max-inline-size: 100%; block-size: auto`. The icon glyphs in slips, tiles and empty states are decorative and sized by font size, never by a fixed box with `overflow: hidden`. **Forbidden in every sheet and view of the area:** `aspect-ratio` anywhere, `object-fit` anywhere, `overflow: hidden` on an element that holds an icon or an image, and an inline `style` carrying a `height`, `width`, `aspect-ratio` or `object-fit`. **Guard (required, in `AdminPlatformConversionGuardTests`, with a scanner self-test as Phases 98 and 99 did):** no area sheet contains `aspect-ratio` or `object-fit`; no area view or partial carries `style=`; the scanner is proven on a seeded bad fixture string (a rule mixing `aspect-ratio` and `object-fit: cover` is flagged) so it cannot go silent.

## Refused controls: visible reason, Error toast (D-02, D-03; look is GATE 1 item 5)

**Pattern (FIXED; the same shape as the move control, `Quest/Manage.cshtml`):** a refused control renders as `<button type="button" class="btn btn-sm btn-… disabled" aria-disabled="true" aria-describedby="reason-{id}">` with its normal label and icon, **outside any POST form**, so it cannot submit, stays in the tab order, and a screen reader announces the reason; directly under the row's actions (or beside the control) one `<p class="control-reason" id="reason-{id}"><i class="fas fa-lock" aria-hidden="true"></i>reason</p>`. One reason line per refusal kind per row, referenced by every refused control of that row; a row with no refusal renders nothing extra (no hidden placeholder). A `title` is never the reason (A-admin-042). The server answers a crafted or stale request for the same action with a PRG redirect and an **Error toast** (persistent, `role="alert"`, foundation toast), so the reason is also visible to anyone who did not see the row.

| Where | Refused control(s) | Refusal kind | Reason line (new wording, GATE 1 item 5) | Error toast (new wording, GATE 1 item 5) |

## Destructive actions: POST forms and native confirm (D-12, D-13; FIXED)
