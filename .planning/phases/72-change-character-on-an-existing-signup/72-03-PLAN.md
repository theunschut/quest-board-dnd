<objective>
Wire the desktop quest Details page to the shared modal: a change control on the player's own row in both tables, one modal instance instead of the old add-only block, and every character picker on the page speaking the same language about status.

Purpose: this is the platform where the feature is discoverable today (the add-only plus button already lives here), so it is the one where a half-wired change control would be most visible. It also has three of the four character pickers on it, which is where the widened list either becomes coherent or becomes confusing.

Output: `Details.cshtml` rendering the shared partial with triggers in both character cells, plus automated markup coverage proving the triggers carry the right identity for each row.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rendered row data -> trigger `data-*` attributes | Character names and ids from the database rendered into HTML attributes |
| Trigger -> shared modal -> POST | Client-side only; the server re-validates every posted `characterId` (plan 01) |
| Other players' rows -> the acting player's browser | The page already renders every participant's character name; this task must not add a control on rows the viewer does not own |

## STRIDE Threat Register

ASVS level 1; blocking threshold: high.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-72-11 | Elevation of Privilege | Change trigger rendered on a row the viewer does not own | high | mitigate | Both filled-state triggers are guarded by `isCurrentUser`, computed from `ViewBag.CurrentUserId` against the row's player id. Proved by `Details_Get_ForAnotherPlayersRow_RendersNoTriggerForThatRow`. Even if the guard were bypassed, `UpdateSignupCharacter` resolves the signup from the authenticated user and never from a posted id (plan 01, T-72-05). |
| T-72-08 | Tampering (stored XSS) | Character name rendered into `data-current-character-label` and into option text | medium | mitigate | Both are emitted through Razor's `@`, which HTML-attribute-encodes; the label originates from `ToSelectLabel`, a plain string builder with no markup. `Html.Raw` is not used anywhere in the touched blocks. |
| T-72-07 | Tampering | Client-supplied `characterId` from a hand-edited trigger attribute | medium | mitigate | Trigger attributes carry no authority. Ownership and board scope are enforced server-side on every POST (plan 01, T-72-01/T-72-02). |
| T-72-12 | Information Disclosure | Widened pickers exposing other players' or other boards' characters | low | accept | The list is owner-filtered in the controller and board-filtered by the entity's global query filter; widening only added the viewer's own inactive characters. No new disclosure surface. |
| T-72-SC | Tampering | npm/pip/cargo installs | high | accept | This phase installs zero packages; no task runs a package-manager install. |
</threat_model>
