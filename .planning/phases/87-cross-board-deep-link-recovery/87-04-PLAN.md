1. **Honest limit on the parity evidence.** A paired HTTP test proves the two responses are indistinguishable in status, body and headers. It says nothing about timing. The structural argument — one code path, one query shape, no branch — is what covers timing, and no test in this plan claims otherwise. The prohibition is therefore recorded as flagged rather than dismissed.
2. **Planner discretion — parity is asserted per entity family, not per route.** Eighteen routes share eight kinds and a handful of query shapes; a pair per family covers every distinct code path, and a pair per route would add eighteen more tests that exercise the same three lines. The families covered are quest, event, character, contact, shop item, series, contact category and board member.
3. **The `Sec-Fetch-*` gate is not tested as an attacker-facing control, deliberately.** No test in this plan asserts that an attacker cannot forge those headers, because any HTTP client can. The property under test is that a *member's own browser background requests* do not move their board, which 87-01 pins. This is recorded here so its absence reads as a decision rather than a gap.

| Boundary | Description |
|----------|-------------|
| browser → application | Any authenticated viewer can request any id on any of the 18 registered routes, whether or not they belong to the owning board |
| resolved board → authorization | The board the request was switched to is the board every policy handler on the landed page is judged against |
| response → requester | The response itself is the only channel through which membership or existence could leak |
