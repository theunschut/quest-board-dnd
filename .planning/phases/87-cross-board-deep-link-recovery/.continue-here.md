# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Role-blind live verification — before judging any membership-gated behaviour from a browser, establish the test account's role AND its real membership set, because this codebase gives a SuperAdmin a board list drawn from every group on the platform while the cross-board resolver answers only from `UserGroups` rows — the two disagree, and a correct 404 looks exactly like a broken feature — mitigation: read the controller's role branch and confirm the account's actual memberships (log `GetGroupsForUserAsync`'s result, or compare the picker's list against `UserGroups`) before concluding anything is broken.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Role-blind live verification | The first live test of the tracer used a quest on a board the operator could *reach* via the picker but was not a *member* of. It 404'd. That is D-12 behaving exactly as designed, but it presented as a broken feature and cost a full instrumentation cycle to diagnose. | blocking | Before judging membership-gated behaviour, check the account's role branch in the controller and its real membership set. `GroupPickerController.Index` lists every board for a SuperAdmin; the resolver never does. |
| Fixing one contrast defect in isolation | The dispatched fix for the translucent toast background would have made the switch-back button *invisible* — `btn-outline-light` is white-on-white once the background goes opaque solid white. The translucency was accidentally providing the only contrast the button had. | advisory | When changing a background colour, re-check every foreground that sits on it. Caught only because the operator asked about the button independently. |
| Judging rendered state from a mid-animation screenshot | A desktop screenshot appeared to still show bleed-through after the fix. It was the `.toast.fade` transition caught in flight. Reporting it would have been a false defect. | advisory | Settle first, then assert via `document.elementFromPoint` / computed style. Do not judge opacity or layering from a screenshot alone. |
| Cross-plan assertions about shared closed sets | 87-03 asserted `/Quest/Manage/42` was unregistered; 87-02 then registered `Quest/Manage`. Both passed in isolation and the merge broke one. | advisory | When asserting a route is absent from the registry, pick one of the *deliberate* documented exclusions (the image subresources, Shop/Details' AJAX variant), never one that merely happens to be unregistered today. The post-merge gate catches this class; keep it. |
| Racing a form POST against a navigation in one browser batch | Submitting `SelectGroup` and navigating to the deep link in a single `browser_batch` raced — the POST had not landed, so the active board was still the old one and the test read as a false negative. | advisory | Submit, confirm the landing page, then navigate as a separate call. |
